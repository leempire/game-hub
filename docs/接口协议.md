# GameHub 接口协议（前后端契约）

> 前后端并行开发的唯一契约，双方必须严格遵守。修改需同步更新本文档。

## 部署约定

| 项 | 值 |
|---|---|
| 后端地址 | 部署时由 `public_base` 决定（环境变量 `PUBLIC_BASE` / `IP`，或 `server/config/config.json`）；本地开发 `http://localhost:50541` |
| WebSocket | `<后端地址>/ws/...`（`http`→`ws`） |
| 前端 Web 端口 | `50540`（Expo web） |
| 后端技术 | Python FastAPI + SQLite，uvicorn 监听 `0.0.0.0:50541` |
| 前端技术 | Expo (React Native + react-native-web)，同时支持 APP 与手机浏览器 |
| 鉴权 | JWT Bearer Token（HTTP 头 `Authorization: Bearer <token>`；WS 用查询参数 `?token=<token>`） |
| 种子管理员 | 账号取自 `config.json` 的 `admin` 段（可用 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 覆盖）；**没有内置默认口令**，两者缺一就不建号 |

## 通用约定

### 蜘蛛纸牌（单人）

`spider` 为私有单人游戏，每账号保留一个可续玩的牌局，不出现在公共房间列表。
`POST /api/rooms {"game":"spider"}` 创建或返回本人牌局，其他账号不可查询、加入或退出。
初次 WS 发 `start`，恢复使用 `sync.game`；`spider_action` 支持 `move/deal/undo/new`，
均须携带当前 `revision`，移动另带从零开始的 `source/index/target`。
成功回 `spider_state {game}`；失败回 `error` 和当前牌面。暗牌以 `null` 表示，
只提供余牌张数与合法移动，不提供暗牌点数、余牌顺序和撤销历史。
离线只保存，不判负；新局或通关记录历史。完整字段见 [蜘蛛纸牌设计与协议](游戏设计/蜘蛛纸牌/设计.md)。

- 所有请求/响应均为 JSON（`Content-Type: application/json`）。
- 错误统一返回 `{"detail": "错误信息"}`，HTTP 状态码：400 参数错、401 未登录/token无效、403 无权限（如非管理员、非房主）、404 不存在、409 冲突（如用户名已存在、房间已满）。
- 用户对象：`{"id": int, "username": str, "nickname": str|null, "role": "admin"|"user", "banned": bool, "created_at": "ISO8601"}`
- 房间号 `code`：6 位大写字母数字。

## 一、认证与账号 REST

### POST /api/auth/register
请求：`{"username": str(3-20位字母数字下划线), "password": str(6-32位)}`
响应 200：`{"token": str, "user": 用户对象}`
错误 409：用户名已存在。

### POST /api/auth/login
请求：`{"username": str, "password": str}`
响应 200：`{"token": str, "user": 用户对象}`
错误 401：用户名或密码错误；403：账号已被封禁（detail="账号已被封禁"）。

### GET /api/auth/me （需鉴权）
响应 200：用户对象。

### PUT /api/auth/me （需鉴权）
请求：`{"nickname": str|null}` 修改昵称。
响应 200：用户对象。

### POST /api/auth/password （需鉴权）
请求：`{"old_password": str, "new_password": str}`
响应 200：`{"ok": true}`；错误 400：原密码错误。

## 二、管理员 REST（均需鉴权且 role=admin，否则 403）

### GET /api/admin/users?page=1&size=20&keyword=
响应 200：`{"total": int, "items": [用户对象]}`

### POST /api/admin/users/{id}/ban
请求：`{"banned": true|false}` → 响应 200：用户对象。不能封禁自己。

### POST /api/admin/users/{id}/role
请求：`{"role": "admin"|"user"}` → 响应 200：用户对象。不能改自己的角色。

## 三、房间 REST

房间对象：
```json
{
  "code": "ABC123",
  "name": "房间名",
  "game": "gomoku",
  "host_id": 1,
  "status": "waiting" | "playing",   // 只有两种：对局结束即回到 waiting
  "has_password": true,
  "max_players": 2,
  "players": [{"id":1,"username":"a","nickname":null,"ready":true,"is_host":true,"connected":true}]
}
```

### POST /api/rooms （需鉴权）
请求：`{"game":"gomoku", "name": str|null(默认"{username}的房间"), "password": str|null}`
`game` ∈ `gomoku | minesweeper | reversi | battleship | dots | ludo | 2048 | xiangqi | connect4 | tetris | uno | stasis | luzhanqi`。
`max_players`：深空休眠 6；扫雷/飞行棋/2048/俄罗斯方块/UNO 为 4；其余（含军棋）为 2。飞行棋与 UNO 2 人即可开局（无需满员）；
2048 与俄罗斯方块 **1 人即可开局**（各玩各的盘，单人就是经典刷分）。
响应 200：房间对象。创建者自动成为房主并已加入（未准备）。
说明：**一个人可以同时在多个房间**（v1.7 起取消了「只能在一个等待房」的限制），
本接口不会再因为「你已在房间中」报 409。

### GET /api/rooms?game=gomoku （需鉴权）
响应 200：`{"items": [房间对象]}`，按创建时间倒序，只返回 waiting 与 playing 的房间。

### GET /api/rooms/{code} （需鉴权）
响应 200：房间对象，额外带一个 `in_game: bool`——请求者还算不算这局的在局玩家。
房间页拿它做**自愈**：漏收 `game_start` 广播时主动查一次，房间在游戏中且自己在局中
就自己进对局页。扫雷/飞行棋/2048 允许「本人已出局、其他人继续」，这类玩家
`in_game` 为 false，不能被弹回对局页。

### POST /api/rooms/{code}/join （需鉴权）
请求：`{"password": str|null}`
响应 200：房间对象。
错误：404 房间不存在；403 密码错误（detail="房间密码错误"）；409 房间已满 / 房间已开始且不是断线重连（detail 区分）。
说明：
- playing 状态：若该用户是断线玩家，join 视为重连。
- 已在房间内的玩家（游戏中断线重连 / 结束后重进 / 等待房重进）：直接放行返回房间。
- 房间状态只有 waiting/playing：对局结束回到 waiting，因此结束后同样可以重进、续开。
- 加入别的房间不再受「你已在某个等待房」限制（v1.7 起）。

### POST /api/rooms/{code}/leave （需鉴权）
响应 200：`{"ok": true}`。
房主离开**不再无条件删房**：房主身份按座位顺序转移给下一个真人玩家；仅当 waiting 状态房间内无真人（只剩人机或空）时才删除并广播 `room_closed`。playing 中房主离开 = 认输（对方胜，房间回到 waiting 保留）。

## 四、WebSocket（大厅 + 对局同一连接）

### 连接：`ws://{host}/ws/room/{code}?token={jwt}`

连接成功后服务端**总是**先推一条 `sync` 全量状态：
```json
{"type":"sync","room":房间对象,"game":null | {
  "board_size":15,
  "board":[[0,0,...],...],        // 15x15，0空 1黑 2白
  "moves":[{"x":0,"y":0,"color":"black"},...],
  "next":"black"|"white",
  "your_color":"black"|"white",
  "winner":null|"black"|"white"|"draw",
  "reason":null|"five"|"resign"|"surrender"
}}
```

### 客户端 → 服务端消息
| type | 字段 | 说明 |
|---|---|---|
| ready | - | 准备（仅 waiting 状态） |
| unready | - | 取消准备（仅 waiting 状态） |
| start | - | 房主开始游戏（仅 waiting；人数满且除房主外全员已准备；房主点开始即视为就绪） |
| move | x:int, y:int | 落子（0-based，轮到该玩家且位置为空才合法）；点格棋复用此 type，字段见「十三」 |
| roll | - | 飞行棋掷骰（仅当前回合玩家） |
| move_piece | piece_id:int | 飞行棋移动指定飞机（0-3） |
| move2048 | direction:str | 2048 竞速滑动（up/down/left/right） |
| tetris_actions | actions:str[] | 俄罗斯方块：本地攒下的动作序列，服务端**重放**（≤`TETRIS_MAX_ACTIONS=200`；动作 ∈ left/right/rotate_cw/rotate_ccw/down/soft_drop/hard_drop/hold）。方块锁定时发一次；`hold` 需要立刻换块，单独发一次并等 `last_action:"hold"` 的权威回包。未连接时不排队（过期序列重放会分叉盘面） |
| uno_play | card:str, color:str\|null | UNO 出牌。`card` 是牌码（`R5`/`RS`/`R+2`/`W`/`W+4`），出黑牌时必须带 `color` ∈ `R/G/B/Y`。合法性由服务端裁决（客户端只按 `playable` 高亮） |
| uno_draw | - | UNO 摸牌（有待罚牌时一次摸完累计张数并移交回合） |
| uno_pass | - | UNO 摸到可选牌之后选择不出，移交回合 |
| uno_call | `target`（可选，v1.17） | 喊 UNO（手牌恰好 1 张时；本版不抓罚，纯广播）。组队档里可以**替队友喊**：不传 `target` 时服务端按「自己有就喊自己、否则喊队友」决定 |
| swap_request | target_id:int | **等待大厅里请求与某人互换座位**（v1.16）。座位 = 玩家列表下标，开局时决定先手 / 出牌顺序。对方是人机 → 直接换好并广播 `lobby`；是真人 → 转一条 `swap_request` 给对方等他点头。**只有 waiting 状态**，开局后回「对局中不能换位置」 |
| swap_respond | from_id:int, accept:bool | 答复别人的换位请求（**只有被请求方本人能答**，`from`/`to` 都要对上；凭空答复回「这条换位请求已经失效了」） |
| surrender | - | 认输（飞行棋中为弃权：飞机全部回基地、排名垫底，多人局继续进行；UNO 中只让本人出局，牌局继续） |
| leave | - | 离开房间（随后客户端应断开 WS） |
| ping | - | 心跳，服务端回 pong |

### 服务端 → 客户端消息
| type | 内容 | 说明 |
|---|---|---|
| sync | 见上 | 连接/重连时全量同步 |
| lobby | `{"room":房间对象}` | 玩家进出/准备状态变化时广播 |
| game_start | `{"game": sync中game同构, "first":"black"}` | 开局；黑先 |
| move | `{"x":int,"y":int,"color":"black"\|"white","next":"black"\|"white"}` | 广播落子 |
| game_over | `{"winner":"black"\|"white"\|"draw","reason":"five"\|"surrender"\|"disconnect"\|"draw"}` | 对局结束，room.status 回到 waiting（`round` 自增） |
| player_disconnected | `{"user_id":int}` | 某玩家掉线；对局中则暂停计时并广播，其座位保留 120 秒 |
| player_reconnected | `{"user_id":int}` | 掉线玩家重连回来 |
| uno_state | 见「十七」 | UNO **逐人下发**的权威状态：本人拿到 `hand` 与 `playable`，其余人只有 `hand_counts` |
| uno_event | `{"kind":str,"seat":int,...}` | UNO 公开事件（谁出了什么/摸了/过牌/喊 UNO/自动过牌/认输），供提示条与动效；**不含任何手牌** |
| swap_request | `{"from_id":int,"from_name":str}` | **只发给被请求的那个人**（换位请求要对方点头，见下「等待大厅里互换座位」）。界面据此弹确认框 |
| swap_result | `{"ok":bool,"accepted":bool\|null,"auto":bool,"message":str}` | **只回给发起人**。`accepted=null` = 请求已转达、等对方答复；`true`/`false` = 同意/拒绝；`auto=true` = 对方是人机、已直接换好。`message` 是给玩家看的一句话 |
| room_closed | `{}` | 房间解散（仅 waiting 状态无真人时触发），客户端收到后应断开并回房间列表 |
| error | `{"message":str}` | 操作被拒绝（如未轮到你、位置已有子） |
| pong | - | 心跳响应 |

### 等待大厅里互换座位（v1.16）

**座位就是 `room.players` 里的下标**，各 `_start_*` 开局时直接读它决定先手 /
出牌顺序 / 颜色。所以要换位只有一条路：**在大厅里换**（`status != playing`）。

- **只能双方同意**。人机没有「不同意」这个语义 → 服务端直接换好；真人之间由服务端
  把 `swap_request` 转给对方（带发起人名字，界面据此弹窗），对方发 `swap_respond`
  才真的换。**任何一方都不能单方面挪走别人的座位。**
- 成功后**广播 `lobby` 给全房** —— 只回给发起人的话，别人看到的还是旧顺序。
- 发起人退房 / 被移出 → 那条待答请求自动作废（`respond` 时再校验一遍，回
  「这条换位请求已经失效了」）。开局时**清空所有待答请求**（否则上一局之前挂着的
  请求会在下一局回到大厅时突然生效）。
- 请求的四种结果都回一句话（`swap_result.message`）：已转达 / 对方同意 / 对方拒绝 /
  人机已同意。**一条都不静默** —— 被静默拒绝的动作在界面上就是「点了没反应」。

### 断线重连规则
1. 对局中（playing）玩家 WS 断开：座位保留 120 秒，广播 `player_disconnected`，对局暂停（不判负、不走时钟）。
2. 保留期内该用户重新 `POST /join` + 连 WS：收到 `sync` 恢复完整棋盘，广播 `player_reconnected`，对局继续。
3. 超过 120 秒未重连：判该玩家负，广播 `game_over reason="disconnect"`。
4. 大厅中（waiting）玩家断开：直接移出房间并广播 `lobby`。
5. 等待中（waiting）玩家断开：**只标记离线、不移出玩家**，记 `empty_since`，重连即取消；超过 `WAITING_EMPTY_TTL=60s` 无人在线才由 sweeper 回收。界面不显示「断线」（等待房没有掉线状态）。
   - 为什么不立即移出：客户端从对局页返回房间是「先关对局页 socket、再重连房间页」，立即移出会让房间瞬间没人而被销毁（返回房间 → 房间不存在）。
   - `GET /api/rooms` 只展示**有真人在线**的等待房，宽限期内不出现幽灵房。

### 房间生命周期（v1.5.1 起：只有两种状态）

**房间状态只有 `waiting` / `playing`**。对局结束调 `_back_to_lobby()` 把房间放回 `waiting`
（`round` 自增，客户端据此提示「上一局已结束，可继续开始新一局」），并把**真人非房主的
`ready` 复位**（v1.7 起）——续开一局要重新表态，否则房主一点「开始游戏」就把还没表态的
人直接拖进下一局。房主本来就不需要准备（前端 `allReady` 里房主恒真、服务端开局校验也
跳过房主），人机是自动准备的，两者都不参与复位。

| 状态 | 房主离开 | 非房主离开 | 全员断线 | 定时清理 |
|---|---|---|---|---|
| waiting | 转移房主给下一真人；无真人则删房 | 移出玩家；无真人则删房 | 移出玩家；无真人则删房 | 60s 无人在线 → 回收 |
| playing | 认输判负 → 回到 waiting | 认输判负 → 回到 waiting | 120s 判负 → 回到 waiting | 30 分钟无真人在线 → 删房 |

- **GC 只有一条规则**：没有真人在线的房间——`waiting` 由 `WAITING_EMPTY_TTL=60s` 回收，`playing` 由 `ROOM_IDLE_TTL=1800s` 回收。显式退出导致「连真人成员都没有了」时立即销毁。
- **TTL 常量**：`ROOM_IDLE_TTL = 1800`（秒），后台 sweeper 每 60s 扫描一次；playing 的宽限是热重启的兜底（恢复的对局无人回来时不能永久留着）。
- **重连/加入重置计时**：任一真人 join 或 WS 重连，`empty_since` 置 None。
- **房间列表**：`GET /api/rooms` 返回全部 waiting/playing 房间（等待房必然有真人，无人的已被销毁）。

## 六、APP 版本与下载（无需登录）

- APK 存放：`server/data/app-release/gamehub-latest.apk`，静态挂载于 `/media/app-release/`
- 版本号双写：`server/config/config.json` 的 `app.version_code/version_name` 与 `app/app.json` 的 `android.versionCode/versionName` 必须一致（发版脚本 `bin/release-apk.sh` 自动双写）

### GET /api/app/version
响应 200：`{"version_code": int, "version_name": str, "download_url": str|null, "has_update": bool}`
未发布 APK 时：`version_code=0, has_update=false, download_url=null`。

### GET /api/app/latest
302 跳转到 `download_url`，供浏览器直接下载。

## 八、扫雷协议（竞技淘汰制）

### 概述
- 1-4 人竞技：所有玩家操作同一份棋盘，共享翻开/插旗集合。**同时进行、没有回合**
- 每人按难度有 1/2/3 条命（初级 1 / 中级 2 / 高级 3）。踩雷扣一条命，
  **命扣完才淘汰**（本局不能再操作，观战到结束）；弃权与断线超时直接淘汰
- 个人统计：每个玩家分别累计「翻开格数」（flood-fill 展开的每个安全格都算给操作者）与「正确标雷数」（结算时按当前仍存在的旗归属计算）
- 结束条件：全员淘汰，或全部安全格翻开。结束后公开全部雷
- 首次翻开安全：全局限定第一次 reveal 时再生成雷布局，排除该格及其八邻域
- 预设难度：初级 9×9/10雷/1命、中级 16×16/40雷/2命、高级 16×30/99雷/3命

### 房间创建

POST /api/rooms 只传游戏类型（难度**不在这里定**，与军棋的玩法、深空休眠的地图一样
由房主进房之后选）：
```json
{
  "game": "minesweeper",
  "name": "可选",
  "password": "可选"
}
```
- 房间对象额外包含 `max_players=4`

### 客户端 → 服务端消息
| type | 字段 | 说明 |
|---|---|---|
| room_setting | key:str, value:str\|int\|bool | **房主在等待大厅里改一条房间级设置**（v1.15 统一入口，见「二·补」）。只有房主、只有等待态；`key` 不属于这个游戏、取值非法、非房主、已开局各回一条**能看懂的中文** `error`。成功则广播 `lobby` 给全房 |
| reveal | x:int, y:int | 翻开格子（0-based），已被淘汰的玩家操作被拒 |
| flag | x:int, y:int | 切换插旗，已被淘汰的玩家操作被拒 |
| chord | x:int, y:int | 快速展开：对已翻开的数字格，若其八邻域旗数 == 该数字，则一次揭开其余未翻开且未插旗的邻格。条件不满足（格未翻开 / 非数字格 / 旗数不符 / 无格可揭）**静默忽略**，不回 error |
| surrender | - | 主动弃权（自我淘汰） |

### 房间级设置（v1.15 统一）

**「房主进房之后再选」的游戏设置全部收在这一份结构里**，一条消息改、一处渲染。
在这之前是五套字段、四种选项形状（`{id,name,blurb,rooms}` / `{size,…}` / `{id,…}` /
`{key,label,kind,…}`），而扫雷与军棋的档位表**压根不下发**、客户端各抄了一份
（军棋直接写死在 JSX 里）。服务端那张表在 `server/app/room_settings.py`。

`room.settings` 是一个**扁平数组**（没有可调项的游戏不下发这个键）：

```jsonc
{
  "key": "difficulty",          // 线上唯一键（同一房间内不重复）
  "label": "难度",              // 中文名（服务端翻译好，客户端不抄表）
  "kind": "choice",             // "choice" | "toggle"
  "value": "intermediate",      // 当前值：string | number | bool
  "value_label": "中级",        // 当前值的**中文名**，房间页那行摘要直接用
  "blurb": "…",                 // 兜底说明：当前值能在 choices 里找到时用那条的 blurb
  "choices": [ { "value": "beginner", "label": "初级", "blurb": "9×9 / 10雷 · 每人 1 条命" } ],
  "toggle_labels": ["开", "关"], // 仅 kind="toggle"：两个状态的中文名（军棋那条是「公开/不公开」）
  "visible_when": { "key": "mode", "value": "hidden" },  // 可选，由**客户端**求值
  "in_summary": true            // 可选，是否进房间页那一行摘要
}
```

有设置的游戏各自的项：

| 游戏 | key | kind | 取值 |
|---|---|---|---|
| 扫雷 | `difficulty` | choice | beginner 初级 / intermediate 中级 / advanced 高级 |
| 扫雷 | `daily` | toggle | 每日固定盘（雷盘种子按 UTC 日期；第一下安全区仍随落点移动） |
| 军棋 | `mode` | choice | open 明棋 / hidden 暗棋 |
| 军棋 | `reveal` | toggle | 公开 / 不公开（`visible_when` = 暗棋） |
| 深空休眠 | `map` | choice | dorm / suite / atrium |
| 深空休眠 | `difficulty` | choice | easy 轻松 / normal 标准 / hard 挑战（只调静默体血量/门伤/进化速度） |
| 海战棋 | `board_size` | choice | 6 闪电战 / 10 标准 / 12 大战场 |
| 海战棋 | `adjacent_placement` | toggle | 舰船不可相邻（含斜角；人机随机布阵同样遵守） |
| 海战棋 | `hide_sunk_ship_type` | toggle | 击沉不报舰种（协议层不下发 `ship_id`） |
| 俄罗斯方块 | `start_level` | choice | 1 慢 / 5 标准 / 10 快（起始速度档，同时抬高分倍率） |
| UNO | `preset` | choice | classic / party / no_mercy（`custom` 不在 choices 里） |
| UNO | 另外 7 条 | 按 `uno_rules.RULE_META` | 见「十七」的房规表 |

**改设置**：`{"type":"room_setting","key":"difficulty","value":"beginner"}`。
服务端五步校验（房间在不在 / 是不是房主 / 是不是等待态 / **这个房间有没有这项设置** /
取值合不合法），每一步都回一句能看懂的中文 `error`；成功则广播 `lobby` 给**全房**。
「游戏对不对」由「按 (游戏, key) 查表」结构性保证 —— 在 UNO 房里发 `difficulty`
查不到，直接回「这个房间没有「difficulty」这项设置」。

⚠️ **v1.15 之前的五条消息（`mine_pick` / `stasis_pick_map` / `battleship_pick_size` /
`luzhanqi_pick` / `uno_pick`）已删除**，但留了一块「墓碑」：收到就回
「客户端版本过旧，请更新后再改玩法设置」。**不是静默丢弃** —— 应用内更新是用户手动
点的，老 APK 不会被自动拦下，静默丢弃在界面上就是「点了没反应」。

### 服务端 → 客户端消息
| type | 内容 | 说明 |
|---|---|---|
| revealed | `{"seat":int, "username":str, "cells":[[x,y,value],...], "hit_mine":bool, "eliminated":bool, "revealed_count":int, "chord"?:true}` | 翻开结果。seat 为操作者座位号，value: 0-8（邻雷数）或 -1（踩雷）。flood fill 一次广播全部翻开格；`chord` 消息也复用它，附 `chord: true` 区分 |
| flagged | `{"x":int, "y":int, "flagged":bool, "questioned":bool, "state":"flag"\|"question"\|"none", "seat":int}` | 三态标记轮换（空 → 旗 → 问号 → 空）；`flagged` 保留给旧客户端，问号不进 `flagged` 集合 |
| player_eliminated | `{"seat":int, "username":str, "message":str}` | 玩家被淘汰（踩雷或弃权），message 为中文广播文案如「XXX 踩雷淘汰」 |
| game_over | `{"reason":"cleared"\|"eliminated", "ranking":[...]}` | 终局。ranking 数组见下方排名格式 |

### 排名格式（ranking 数组元素）
```json
{
  "seat": 0,
  "username": "alice",
  "nickname": "A",
  "alive": true,
  "correct_flags": 3,
  "wrong_flags": 1,
  "revealed_count": 42,
  "elapsed_ms": 63200,
  "rank": 1
}
```
- 排名规则：幸存者在前（组内按 correct_flags desc → revealed_count desc → **elapsed_ms asc**，即同标雷数、同翻格数时更快者在前）；淘汰者垫底（组内按 revealed_count desc → 淘汰时间晚者在前）
- `elapsed_ms` 是本局第一次翻开到该玩家最后一次翻开的跨度（毫秒）；**全程没翻过格子的人为 `null`**（界面不显示 0.0 秒）
- 并列排名共享同一 rank 值（幸存者要三项全同才算并列）

### sync 的 game 字段扩展（扫雷）
```json
{
  "game": "minesweeper",
  "width": 9,
  "height": 9,
  "mines": 10,
  "difficulty": "beginner",
  "daily": false,
  "revealed": [[x, y, value], ...],
  "flagged": [[x, y], ...],
  "questioned": [[x, y], ...],
  "started": true,
  "finished": false,
  "reason": null,
  "started_at_ms": 1792559000000,
  "players": {
    "0": {"alive": true, "revealed_count": 12, "elapsed_ms": null},
    "1": {"alive": true, "revealed_count": 5, "elapsed_ms": 4200}
  }
}
```
- `players` 以座位号（字符串）为键，包含每位玩家的存活状态、翻开统计与用时（终局结算前为 `null`）
- 游戏结束后 sync 额外包含 `ranking` 数组

### 胜负判定与战绩
- 全部安全格翻开 → `reason="cleared"`，幸存者按统计排名
- 全员淘汰 → `reason="eliminated"`，按统计排名
- 战绩落库：排名第 1 名 result="win"，其余 "lose"；若第 1 名统计完全并列则并列者都 "win"

### 断线重连
- 对局中掉线保留座位 120 秒，广播 `player_disconnected`
- 重连后推全量 sync（含当前 revealed/flagged/players 状态）
- 超时未重连：玩家视为淘汰（alive=false），若全员淘汰则游戏结束

## 九、翻转棋协议（2人对战）

### 概述
- 8×8 棋盘，黑先，经典初始布局（中央 4 格对角摆放黑白各 2）
- 落子必须至少夹住翻转一枚对方棋子（八方向均可）
- 无合法着法自动 pass（服务端广播提示）；双方均无合法着法或棋盘满即终局
- 终局子多者胜，子数相同为平局
- 颜色分配：房主执黑（先手），加入者执白

### 房间创建

POST /api/rooms 请求：
```json
{
  "game": "reversi",
  "name": "可选",
  "password": "可选"
}
```
- max_players=2

### 客户端 → 服务端消息
| type | 字段 | 说明 |
|---|---|---|
| move | x:int, y:int | 落子（0-based，轮到该玩家且为合法翻转位置才有效） |
| surrender | - | 认输 |

### 服务端 → 客户端消息
| type | 内容 | 说明 |
|---|---|---|
| move | `{"x":int,"y":int,"color":"black"\|"white","next":"black"\|"white","flipped":[[x,y],...]}` | 广播落子及翻转位置列表 |
| pass | `{"color":"black"\|"white"}` | 某方无合法着法被自动 pass |
| game_over | `{"winner":"black"\|"white"\|"draw","reason":"score"\|"surrender"\|"disconnect","score":{"black":int,"white":int}}` | 终局，附带比分 |

### sync 的 game 字段（翻转棋）
```json
{
  "board_size": 8,
  "board": [[0,0,...],...],
  "moves": [{"x":0,"y":0,"color":"black","flipped":[[x,y],...]},...],
  "next": "black"|"white",
  "your_color": "black"|"white",
  "pass_count": 0,
  "winner": null|"black"|"white"|"draw",
  "reason": null|"score"|"surrender"|"disconnect",
  "score": {"black": 2, "white": 2}
}
```

### 棋盘编码
- `0` = 空，`1` = 黑，`2` = 白
- 初始布局：`(3,3)=2, (4,4)=2, (3,4)=1, (4,3)=1`

### 胜负判定
- 双方均无合法着法或棋盘满 → 按子数判定，`reason="score"`
- 认输 → `reason="surrender"`
- 断线超时 → `reason="disconnect"`

### 断线重连
- 同五子棋：对局中掉线保留座位 120 秒，重连后推全量 sync
- 超时未重连判负

## 十、历史战绩（需鉴权）

### 概述
- 每局产生明确结果（胜/负/平，含认输、断线判负）的游戏会自动落库
- 房间在游戏结束前关闭（无结果）则不记录
- 记录内容：游戏类型、房间号、玩家列表（含座位/执子颜色）、每个玩家的结果、最终局面快照、开始/结束时间
- 扫雷竞技：排名第 1 名 result="win"，其余 "lose"；并列第 1 则都 "win"

### GET /api/history/mine?page=1&size=20

响应 200：
```json
{
  "items": [
    {
      "id": 1,
      "game": "gomoku",
      "room_code": "ABC123",
      "players": [
        {"username": "alice", "nickname": "A", "seat": 0, "color": "black"},
        {"username": "bob", "nickname": null, "seat": 1, "color": "white"}
      ],
      "results": [
        {"username": "alice", "result": "win"},
        {"username": "bob", "result": "lose"}
      ],
      "snapshot": { ... },
      "started_at": "2026-10-09T08:00:00+00:00",
      "ended_at": "2026-10-09T08:10:00+00:00"
    }
  ],
  "total": 42,
  "page": 1,
  "size": 20
}
```

- `size` 上限 100；`page` 下限 1
- 按 `id DESC` 排序（最新在前）
- 仅返回当前用户参与的记录（players 中包含当前 username）
- `result` 取值：`"win"` | `"lose"` | `"draw"` | `"end"`
  - `"end"` 是 **2048 专用**：2048 是跑分竞速不是胜负对抗，**只有真的合出 2048
    才记 `"win"`**，其余（分数最高但没合出来 / 卡死 / 认输）一律 `"end"`，名次另见快照的 `ranking`
- `players[].color` 仅对战类游戏（gomoku/reversi）存在，扫雷无 color 字段
- `players[].seat`：从 0 开始的位置索引

### GET /api/history/stats

「我的」页战绩卡与主页「最近玩过」共用。服务端聚合，**不把全量记录发给客户端**。

响应 200：
```json
{
  "total": 42,
  "wins": 20,
  "losses": 15,
  "draws": 7,
  "win_rate": 0.5714,
  "current_streak": 3,
  "best_streak": 6,
  "recent_7d": 9,
  "top_games": [{"game": "gomoku", "count": 18, "wins": 11}],
  "recent_games": [{"game": "uno", "last_played_at": "2026-10-21T..."}],
  "best_scores": {"2048": 4096},
  "best_times": {"beginner": 18000, "advanced": 300000}
}
```
- **胜率只按 `wins + losses` 算**：`draw`（平局）与 2048 的 `end` 都不进分母；
  `current_streak` 遇到任何非 win 都中断
- `recent_games` 是「每个游戏最近一次」的前 4 个，供主页「最近玩过」直接渲染
- `best_scores` 是跑分竞速的个人最佳（v1.18.1 起 2048 战绩的 `results_json`
  带 `score`；**老记录没有该键，直接跳过**，最佳分从新记录开始累积）
- `best_times` 是扫雷各难度的最佳用时（毫秒，v1.18.1 起扫雷战绩带
  `elapsed_ms` + `difficulty`；老记录同样跳过）
- 新账号返回全零且 `win_rate = null`、`best_scores = {}`、`best_times = {}`

### 快照（snapshot）结构

> **逐步回放**：五子棋 / 翻转棋 / 点格棋 / 四子棋 / 象棋 / 军棋的快照带 `moves`
> （每一步的坐标与落子方），客户端用「空盘 + 前 N 手」重建任意一手。
> v1.18.1 起才写入；更早的战绩没有这个键，前端按可选处理、不显示回放条。

#### 五子棋
```json
{
  "game": "gomoku",
  "board_size": 15,
  "board": [[0,0,...], ...],
  "winner": "black" | "white" | "draw" | null,
  "reason": "five" | "surrender" | "disconnect" | "draw" | null
```

- `board[y][x]`：0 空、1 黑、2 白

#### 扫雷（新格式，竞技模式）
```json

  "game": "minesweeper",
  "width": 9,
  "height": 9,
  "mines": 10,
  "revealed": [[x, y, value], ...],
```

## 十一、海战棋协议（2人对战）

> **棋盘尺寸 / 舰队配置是房间级设置**（v13，v1.15 起走统一的 `room_setting`）：
> 房主在等待大厅里发 `{"type":"room_setting","key":"board_size","value":6|10|12}`，
> 服务端校验后**广播一条 `lobby` 给全房**。选项与当前值都在 `room.settings` 里
> （`board_size` 项，`choices` 是三档的 `{value,label,blurb}`）；
> 开局后 `gs["size"]` 就是这一局的尺寸。见「二·补」。

### 概述
- 10x10 棋盘，每人 5 艘船（航母5/战列舰4/巡洋舰3/潜艇3/驱逐舰2）
- 两阶段：布阵（placing）→ 战斗（battle）→ 结束（finished）
- 布阵阶段：双方各自放置 5 艘船（可手动或随机），双方就绪后进入战斗
- 战斗阶段：轮流开炮（蓝方先手），命中/落空/击沉实时广播
- **命中续射（v1.10）**：命中或击沉后回合保留，可接着再打一发，直到打空为止；
  **先手方的第一发不触发**（补偿后手，先手天然多一个回合）
- **特殊武器（v1.10）**：雷达 / 齐射 / 空袭 各每局一次，布阵时挂靠到三条不同的船上，
  携带舰被击沉则武器失效；使用武器即本回合全部行动、**不触发续射**
- 全部击沉对方 5 艘船即获胜；认输或断线超时判负
- 颜色分配：房主执蓝，加入者执红

### 房间创建

POST /api/rooms 请求：
```json
{
  "game": "battleship",
  "name": "可选",
  "password": "可选"
}
```
- max_players=2

### 客户端 → 服务端消息
| type | 字段 | 说明 |
|---|---|---|
| placement | ships: `[{id,x,y,horizontal}×5]`, weapons?: `{radar:5,salvo:4,strike:3}` | 提交布阵。`weapons` 是三件武器各自挂靠的**舰船 id**，三条必须互不相同；缺字段或不合法时服务端用默认分配兜底（旧客户端兼容） |
| fire | x:int, y:int | 开炮（0-based，轮到自己且未开过炮才合法） |
| use_weapon | radar: weapon,x,y ／ salvo: weapon,cells:`[[x,y]×3]` ／ strike: weapon,x,y | 使用特殊武器。雷达/空袭给中心格，齐射给 3 个格子 |
| surrender | - | 认输 |

### 服务端 → 客户端消息
| type | 内容 | 说明 |
|---|---|---|
| game_start | `{"game": {phase:"placing", ...}}` | 布阵阶段开始，game 包含各视角棋盘 |
| placement_ready | `{"user_id": int}` | 某方已完成布阵 |

## 十二、人机系统

### 概述
- 支持游戏：gomoku、reversi、battleship、dots、ludo（扫雷/2048 不支持）
- 人机可在等待大厅（waiting）由房主添加/移除
- **满员即止**：双人游戏加一个 bot 后房间自然满员；飞行棋（4 人）可连加 3 个凑满，
  昵称带序号（「人机·棋手」「人机·棋手2」…）
- 人机自动准备（ready=true），房主点开始即可开局
- 人机执后手：五子棋/翻转棋执白，海战棋执红

### 客户端 → 服务端消息
| type | 字段 | 说明 |
|---|---|---|
| add_bot | - | 房主添加人机（仅 waiting、房间未满、支持的游戏） |
| remove_bot | bot_id:int? | 房主移除人机；**多个人机时必须传 bot_id**（前端「移除」按钮传该行玩家的 id），不传则移除第一个 |

### 服务端 → 客户端消息
- lobby 广播中 players 数组人机玩家带 `"is_bot": true`、`nickname` 为「人机·棋手」
- 其余消息与正常对局一致（人机落子/开炮走正常广播路径）

### 人机行为
- **五子棋/翻转棋**：轮到人机时，服务端延迟 0.8~1.2 秒后调用 AI（gomoku_ai/reversi_ai.best_move）并走正常落子广播
- **翻转棋 pass**：AI 返回 None 时走现有自动 pass 逻辑
- **海战棋布阵**：开局时人机自动调用 random_placement() 布阵，前端只收到 placement_ready + battle_start
- **海战棋开炮**：轮到人机时延迟后调用 battleship_ai.best_move 并走正常 shot 广播
- **点格棋画边**：轮到人机时延迟后调用 dots_ai.best_move 并走正常 move 广播（人机为后手，标识 `white`，界面显示为红方）

### 人机标识
- `username`：`bot_<房间码>`（如 `bot_ABC123`）
- `nickname`：「人机·棋手」
- `is_bot`：true
- `ready`：true（始终准备就绪）
- `connected`：true（合成玩家无 WS 连接，但视为在线）
- 人机 ID 为负数（不与真实用户冲突）

### 断线与移除
- 人机不适用断线保座逻辑（无 WS 连接）
- 对局中不允许添加/移除人机
- 人机对局战绩正常落库（以 nickname 入 players_json）

### AI 驱动说明
- 五子棋：gomoku_ai.best_move(board, player) → (x, y)，启发式 + NegaMax alpha-beta
- 翻转棋：reversi_ai.best_move(board, player) → (x, y) | None，位置权重 + NegaMax
- 海战棋：battleship_ai.best_move(attack_board, opp_board, opp_ships) → (x, y)，hunt/target 策略
- 点格棋：dots_ai.best_move(game) → (orient, y, x)，三阶段启发式（贪心封格 → 安全边筛选 → 最小伤害开链）

## 十四、飞行棋协议（Ludo，2-4人）

### 概述
- 每人 4 架飞机、一色（按座位序 = 蓝/绿/红/黄，对应左上/右上/右下/左下基地）；赛道是围着十字边缘一圈的 52 格公共环形 + 每色 6 格终点航道
- 掷 6 起飞/额外回合；连掷 3 次 6 触发「乐极生悲」全部回基地并失去回合；落敌机格撞回基地；终点精确到达，超出折返
- **赛道 52 格按蓝→绿→红→黄四色循环着色**（每色 13 格）。落点与**自己**同色则再向前跳 4 格（同色跳格，只跳一次）
- **虚线捷径**：赛道上每 13 格一处虚线（绝对索引 3 / 16 / 29 / 42，一色一条：黄/蓝/绿/红），**只有落在自己颜色的那条上才能飞**（标准规则原文）。因为「自己颜色」⇔「相对进度是 4 的倍数」，而 3/16/29/42 里只有 16 是 4 的倍数——所以对任何座位，可用虚线都恰好是**相对进度 16** 那一条，飞 12 格到 28；其余三条不生效（`is_arrow()` 返回 False）。若是**跳**到虚线格上则飞完就停。跳、飞各最多一次
- 落点是自己颜色格且格上已有敌机 → 直接撞落，不跳不飞
- **迭子**（同色 ≥2 架同格）：敌方走子路径**经过**迭子格则该走法非法（不可飞越）；正好**落在**迭子上则同归于尽，双方全部回基地（`new_progress = -1`）
- 4 架全部到终点者完成；只剩一人未完成时终局按完成数排名。弃权（surrender）排名垫底
- 骰子服务端权威：客户端只发 roll，引擎生成点数
- 不支持叠机（迭子）变体

### 客户端 → 服务端消息
| type | 字段 | 说明 |
|---|---|---|
| roll | - | 掷骰（仅当前回合玩家；phase=roll 时） |
| move_piece | piece_id:int | 移动飞机（0-3，须在 movable 列表内） |

### 服务端 → 客户端消息
| type | 内容 | 说明 |
|---|---|---|
| game_start | `{"game": sync中game同构 + "your_seat":int}` | **逐人下发**（各附自己座位号，seat=room.players 索引） |
| dice_rolled | `{"seat","dice","movable":[piece_id,...],"extra_turn":bool,"penalty":bool,"current_seat":int,"pieces"?:[...]}` | 掷骰结果广播；penalty=三连6惩罚。**`current_seat` 必须有**——掷到无可动飞机时回合会自动移交，客户端靠它更新轮到谁。`penalty=true` 时附 `pieces`（该玩家 4 架飞机的最新 progress），否则客户端棋盘上飞机会留在原地、与服务端脱节 |
| piece_moved | `{"seat","piece_id","old_progress","new_progress","dice","path":[progress,...],"segments":[{kind:"walk"\|"jump"\|"fly"\|"bounce",from,to},...],"captures":[{seat,piece_id},...],"finished":bool,"extra_turn":bool,"current_seat"}` | 移动结果广播。`old_progress` 是走子前位置；**`path` 是逐格动画的完整路径**（不含起点、含终点，把掷骰前进 / 同色跳格 / 虚线飞行串在一起），`segments` 标出每段是哪一种。跳/飞的形状取决于落点，**客户端不能按 `old+dice` 自己推**。人机走的是同一条广播。`kind="bounce"` = **迭子同归于尽**：落到敌方同色 ≥2 架的格子上，双方全部回基地，此时 `new_progress = -1`、`path` 末尾为 `-1` |
| player_surrendered | `{"seat","username","message","pieces"?}` | 某玩家弃权（多人局继续）。`pieces` 是该座位清回基地后的最新 progress（`[-1,-1,-1,-1]`），客户端据此清掉棋盘上的残留飞机 |
| game_over | `{"reason":"all_finished"\|"last_remaining"\|"surrender"...,"ranking":[...]}` | 终局+排名 |

### sync 的 game 字段（飞行棋）
`{num_players, players:{seat:{pieces[4],color,finished_count,finished}}, current_seat, dice_value, movable_pieces, phase:"roll"|"move", finished, reason, consecutive_sixes, your_seat}`
pieces 值：-1=基地，0..48=赛道进度（**只走 49 格**，自己的航道入口就在 48），
49..54=终点航道（6 格），55=到达（见 `ludo.py` 的 `RING_END` / `FINISH_PROGRESS`）。

`{"game":"ludo","num_players","players":{seat:{pieces,color,finished_count,finished}},"ranking":[{seat,username,nickname,color,finished_count,rank}],"reason"}`

## 十五、2048 竞速协议（1-4 人各自独立盘 + 共享实时排行榜）

### 概述
- **1-4 人各玩各的 4×4 棋盘，不是回合制**：走子无任何回合校验，随时可以滑
- 每人独立随机源但**种子相同**，出块序列完全一致（服务端权威，90% 出 2 / 10% 出 4）
- `max_players=4`，**1 人即可开局**（单人刷分）
- 结束是**逐人**的：合成 2048（reach_2048）或棋盘卡死（stuck）即本人结束；
  认输/中途退出只结束本人（surrender，排名垫底），其他人继续
- **全员结束**才结算：`_compute_2048_ranking` 按 `(是否 reach_2048, 达成先后, -分数)` 排序
- 颜色按入座顺序取 blue/red/green/yellow；不支持人机

### 客户端 → 服务端消息
| type | 字段 | 说明 |
|---|---|---|
| move2048 | direction:"up"\|"down"\|"left"\|"right" | 滑动；无效移动（棋盘无变化）返回 error"无效移动"；本人已结束/整局已终局则拒绝 |
| undo2048 | 无 | **仅单人局**回退上一步（盘面/分数/步数；RNG 不回滚）；多人局回 error"多人对局不支持撤销"，无步可撤回 error"还没有可以撤销的步数" |

### 服务端 → 客户端消息
| type | 内容 | 说明 |
|---|---|---|
| game_start | `{"game": sync中game同构}` | **逐人下发**（各自视角棋盘） |
| move2048 | `{"user_id","color","direction","score","score_gained","leaderboard":[...], "board"?,"spawned"?,"trace"?,"player_finished"?}` | **按人裁剪的广播**：`board`/`spawned`/`trace` 只发给走子者本人（盘面私有），其余人只收 `leaderboard`；`trace` 是逐块走子轨迹 `[{from:[r,c],to:[r,c],value,merged}]`，供客户端播滑动动画；`player_finished` ∈ reach_2048\|stuck 表示该玩家本局结束 |
| undo2048 | `{"user_id","board":[[int]],"score","move_count","undo_available","leaderboard":[...]}` | 只回给操作者（单人局，盘面私有） |
| game_over | `{"winner":color,"reason":"ranking","ranking":[...]}` | 全员结束才广播 |

`leaderboard` 每项：`{"user_id","color","score","max_tile","finished","finish_reason"}`，
按 `(是否 reach_2048, -分数)` 排好序。

### sync 的 game 字段（2048）
`{board[][], score, max_tile, game_over(本人已结束), finish_reason, seed, move_count, undo_available, your_color, player_count, leaderboard, winner, reason, ranking}`

### 快照（snapshot）
```
{
  "game": "2048",
  "boards":    { "<uid>": [[int]] },   // 各人最终盘面
  "scores":    { "<uid>": int },
  "max_tiles": { "<uid>": int },
  "players":   { "<uid>": {"username","nickname","is_bot","color"} },  // 供战绩页显示用户名
  "winner": color, "reason": "ranking",
  "ranking":   [ {"seat","user_id","username","nickname","color","score","max_tile","finish_reason","rank"} ]
}
```

- **`players` 是给界面显示「谁是谁」用的**：2048 的颜色按入座顺序发，1-4 人都可能拿到任意
  一色，拿颜色当「红方/蓝方」既不对也无从分辨，所以必须用 username/nickname。
- **`ranking` 必须在 `_set_game_over` 之前写回 `gs`**：后者内部触发战绩落库，快照读的
  正是 `gs["ranking"]`，顺序反了会让存下来的快照排名永远是空数组。
- **`winner` 记的是「排名第一的颜色」，不是「胜利者」**。判断谁赢要看
  `max_tile >= 2048`（= 各人 `finish_reason == "reach_2048"`），不要拿 `winner` 当胜负。

## 十六、俄罗斯方块对战协议（1-4 人各自独立盘 + 攻击行）

**没有服务端 tick**：重力归客户端，客户端把动作攒成一串、**方块锁定时整段发上来**，
服务端用同一套引擎重放（服务端仍是盘面唯一权威）。每块方块一次往返。

### 房间
- `max_players = 4`，**1 人即可开局**（各玩各的盘）。不支持人机。
- 开局：所有人共用**同一个随机种子**（7-bag 方块序列完全一致 → 公平）。

| type | 字段 | 说明 |
|---|---|---|
| tetris_actions | actions:str[] | 动作序列（见上表，另含 `hold` 暂存/换块） |

### 服务端 → 客户端消息
| type | 内容 | 说明 |

| game_start | `{"game": sync中game同构}` | **逐人下发**（只给自己的盘面与方块） |

每人独立结束（顶到天花板 / 收攻击行被压死 / 认输 / 掉线超时）；**全员结束才结算**：
排名键 `(是否撑到最后, 出局先后倒序, 分数)`。认输与中途退出只结束本人，其他人继续。

## 十七、UNO 卡牌协议（2-4 人回合制）

### 房间
`max_players = 4`，**≥2 人即可开局**（与飞行棋同档）。支持人机（最多 3 个）。
座位号 = `room.players` 下标，回合顺序与 `player_colors` 都按它对齐。

### 客户端 → 服务端消息
| type | 字段 | 说明 |
|---|---|---|
| uno_play | card:str, color:str\|null, jump:bool, target:int | 出牌。牌码编码见下；**黑牌必须带 `color` ∈ `R/G/B/Y`** —— 「哪些牌算黑牌」读服务端下发的 `color_kinds`，不要按牌码自己判断（无怜悯档有 5 种，漏一种就是「点了没反应」）。`jump=true` 是**抢出**（`jump_in` 房规，非本回合、与牌堆顶完全相同的牌）；`target` 是 **7 换手**要换给的座位（`seven_zero` 房规）。三者都由服务端裁决 |
| uno_draw | - | 摸牌：有待罚牌时**一次摸完累计张数**并移交回合；否则摸 1 张，摸到能出的牌则**保留回合**（等本人出或过牌）。「摸到能出为止」档下会一直摸到能打的那张 |
| uno_pass | - | 摸到可选牌之后选择不出，移交回合（没摸过牌时会被拒；「有牌必出」档下也会被拒） |
| uno_call | - | 喊 UNO（手牌恰好 1 张时）。**不抓罚**，纯广播 |
| uno_roulette | color:str | **颜色轮盘点名**（`W+RO`）：只有被点名的那个座位能发。翻抽牌堆直到出现该色，翻出来的牌全归他并停一轮 |
| ~~uno_pick~~ | — | **v1.15 起改用统一的 `room_setting`**：`{"key":"preset","value":"party"}` 一键填好整份房规；`{"key":"jump_in","value":true}` 逐条改（每条房规各是一个独立 key，所以「只合并给出的键」是结构自带的）。老客户端发这条会收到「客户端版本过旧」 |

**牌码编码**：`<颜色><牌面>`，颜色 ∈ `R/G/B/Y`（黑牌是 `W`）。
数字牌 `R5`；功能牌 `RS`(跳过) / `RR`(反转) / `R+2`；黑牌 `W`(变色) / `W+4`。
`deck = "no_mercy"` 时另有六种：`RSE`(跳过所有人) / `RDA`(弃同色) /
`W+6` / `W+10` / `W+RD4`(变色反转+4) / `W+RO`(颜色轮盘)。
**其中 `W+RO` 是唯一出牌时不需要 `color` 的黑牌** —— 它的颜色由下家点名；
其余四种（连同 `W` / `W+4`）都要求 `color`，也就是 `color_kinds` 那一张表。

### 服务端 → 客户端消息
| type | 说明 |
|---|---|
| game_start | **逐人下发**（每人一份 `game`，见下） |
| uno_state | 一次动作后的权威状态，同样**逐人下发** |
| uno_event | 公开事件：`{"kind":"play"\|"draw"\|"pass"\|"uno"\|"autopass"\|"surrender"\|"leave", "seat":int, ...}`，另带 `card`/`color`/`effect`/`skipped`/`pending_draw`/`drawn`/`penalty`/`jump`/`target`。**不含任何手牌** |
| game_over | `{"game":"uno","reason":"emptied"\|"last_remaining"\|"team_emptied","winner":seat,"winner_team":0\|1\|null,"seat_teams":[...],"emptied":[...],"ranking":[...],"points":{seat:分值},"seat_uids":[...]}`。**组队档的胜负是队伍**（`winner_team`），`winner` 只是该队的一个代表座位 |

`effect` 取值：`play` / `skip` / `reverse` / `draw2` / `wild4` / `empty` /
**`swap`**（7 换手，另带 `target`）/ **`rotate`**（0 传手，全员手牌换位）/
**`skip_all`**（跳过所有人）/ **`discard_all`**（弃同色）/ **`roulette`**（颜色轮盘，
点名交给下家）/ `draw6` / `draw10` / `rev_draw4`。
另有一条独立事件 `uno_event{kind:"roulette", seat, color, drawn}` —— 点名结算完广播。
**客户端别列罚牌清单** —— 罚几张一律读 `pending_draw`（加了新罚牌就不必回来改）。

### sync / game_start / uno_state 的 `game` 字段
```

  "num_players": int,
  "seat_uids": [int],           // 座位号 → uid
  "seat_colors": [str],         // 座位号 → 玩家身份色（theme.playerColors 的键）
  "your_seat": int | null,
  "hand": [str],                // **只有本人的手牌**

  "jumpable": [str],            // **本人此刻能抢出的牌**（`jump_in` 房规）
  "swap_targets": [int],        // 7 换手可以换给的座位；空表 = 现在不用选人
  "roulette_seat": int | null,  // 颜色轮盘正等着哪个座位点名；非 null 时全场只有他能动

  // 待罚的**牌面本身**（"+2"/"+4"/"+6"/"+10"/"+RD4"），不是另设的一套标记 ——
  // `same` 档拿它比牌面、`upgrade` 档拿它比面值，少一张映射表就少一处漂移
  "pending_kind": str | null,
  "uno_called": [int],          // 已喊 UNO 的座位
  // 已出局的座位（认输 / 判负）。**组队档里也包含「已经出完手牌」的人** ——
  // 他们不再被轮到，但队伍还在打（读 `emptied` 分辨这两件事）
  "out": [int],
  // ── 组队档（`rules.teams == "2v2"`，v1.16）──
  "seat_teams": [0\|1\|null],     // 座位 → 队伍；没开组队时全是 null
  "your_team": 0 | 1 | null,    // 我属于哪一队

  "uno_targets": [int],
  "winner": int | null, "reason": str | null, "finished": bool
}
```
**手牌私有是这局的核心不变量**：`hand` 只含本人的牌，别人的只有 `hand_counts`；
客户端压根收不到对手的牌面，不是靠渲染时隐藏。
**`jumpable` 同样是私有信息** —— 只有拿着那张牌的人才知道自己能抢；发给别人等于
把「我手里有哪张牌」漏了出去。
`playable` / `jumpable` 与四个 `can_*` 旗标让客户端**一格规则都不用实现**
（同象棋的 `legal`）。两者**永远不同时非空**：轮到我时服务端不下发 `jumpable`。
`color_kinds` 是同一纪律的第三条：**「哪些牌要先选色」也在服务端**。客户端原来自己写了
一份（只认经典的两张黑牌），无怜悯的 `W+6`/`W+10`/`W+RD4` 因此永远打不出去 ——
服务端回一句「变色牌需要指定颜色」，而玩家没有任何办法补上那个颜色。

### 房规（v1.14，v1.15 起随统一的 `room.settings` 下发）

房规本身没变，**变的是它在协议里的位置**：不再是 `room.uno_rules` /
`room.uno_preset` / `room.uno_presets` / `room.uno_rule_meta` 四个专用字段，
而是 `room.settings` 里的一项档位 + 七项房规（见「二·补」）。
`custom`（逐条改过、不匹配任何预设）**不在 `choices` 里**，它只是一个当前值，
中文名走 `value_label`：

| 键 | 取值 | 默认 |
|---|---|---|
| `preset` | `classic` / `party` / `team` / `no_mercy`（写它 = 整份重置） | `classic` |
| `stack_mode` | `off` / `same` / `upgrade` | `same` |
| `draw_until_play` | bool | `false` |
| `must_play` | bool | `false` |
| `jump_in` | bool | `false` |
| `seven_zero` | `off` / `swap` / `rotate` / `both` | `off` |
| `deck` | `classic` / `no_mercy` | `classic` |
| `mercy` | bool（手牌 ≥ **25** 张出局，阈值固定） | `false` |
| `teams` | `off` / `2v2` | `off` |

房规在 `create_game` 时落进 `gs["rules"]`（跟着对局一起热重启），**打到一半改不了**
（`room_setting` 会被拒）。`snapshot` 也带 `rules` —— 战绩页要能说清这局打的是哪套规矩。

### 快照（snapshot）
```
{
  "game": "uno",
  "num_players": int,
  "seat_uids": [int],
  "hands":  { "<seat>": [str] },    // 终局每人剩余手牌
  "points": { "<seat>": int },      // 剩余点数（数字按面值、功能牌 20、黑牌 50）
  "discard_top": str | null,
  "winner": seat, "reason": "emptied" | "last_remaining" | "team_emptied",
  // 组队档（v1.16）：胜负是队伍，战绩页要说「AB 队」而不是「某某获胜」
  "winner_team": 0 | 1 | null,
  "seat_teams": [0 | 1 | null],
  "emptied": [int],
  "ranking": [ {"seat","username","nickname","cards","points","surrendered",
                "team","emptied","rank"} ]
}
```
排名键（经典/无怜悯）`(是否为胜者, 剩余点数升序, 是否认输, 座位号)`——出完手牌的人
第一，其余按剩余点数（点数少 = 更接近赢），认输者同分时靠后。
**组队档第一键换成队伍**（获胜那队全员在前）——拿单个 `winner` 座位去排的话，队友会
被排到输队后面去，战绩页看起来像「他一个人赢的」。

### 2v2 组队（`teams=2v2`，v1.16）

**恰好 4 人**（人数不对时 `start` 回「组队模式需要恰好 4 名玩家」，不是「无法开始游戏」）。
**对家是队友**：`seat % 2` —— 0/2 一队、1/3 一队。配对**只在服务端算**，随状态下发
（`seat_teams`），客户端不自己推。

- **出完手牌不是出局，是从队友手里接管一半**（v1.17，官方 GOING OUT 口径）：
  队友把手里一半（向下取整，**奇数张时他留多的那些**）交过来，本人接着打。
  **只有队友手里只剩 1 张**（半手传不出来）时本人才真的留在场外。
  一队**两人同时空手**才算赢（`reason="team_emptied"`，`winner_team` 指出是哪一队）。
- **TAGGING BACK IN**（v1.17）：人在场外时，队友**只要摸到牌**就立刻分他一半、
  把他拉回场上。**认输的队友不拉回来**（判据是 `emptied`，认输只进 `out`）。
- **队友可以替你喊 UNO**（v1.17）：`uno_call` 带不带 `target` 都行，不传时服务端
  按「自己有就喊自己，否则喊队友」决定；`uno_targets` 随状态下发，客户端据此把按钮
  文案换成「替队友喊」。
- 对手整队都没了（认输 / 25 张淘汰 / 出完）时，剩下那队获胜
  （`reason="last_remaining"`）。
- 出完手牌的人**不算认输** —— 排名里他和队友并列第一，不会被当成逃兵排到队尾。
- 队友之间**照常各看各的牌**（`hand` 依旧只含本人），互相看不到手牌。
- 人机**不拿队友当换手对象**（换手是双向的，那是坑队友）；对手全没了才退回队友。
- **两张专属黑牌**（v1.17，只在组队档进牌堆，各 2 张 → **112 张**）：
  - `WTP` **Wild Team Play**：选色 → 回合**直接跳到队友**；他出得了就接着打，
    **出不了就罚出牌者摸 2 张**（罚的是打牌的人，不是队友）。
  - `WTD4` **Wild Team Draw Four**：下家摸 2 并停一轮，**他的队友也摸 2**
    （官方原文：场外的队友也照样摸）。
  - ⚠️ 两张都会让手牌张数**当场跳变**，所以 `uno_event{kind:"play"}` 与
    `uno_play` 的结果里多带一个 `takeover: {seat, from, count, reason}`，
    `reason` 是 `going_out`（接管一半）或 `tag_in`（被摸回场上）；没有发生就是 `null`。
  - `uno_event{kind:"draw"}` / `{kind:"autopass"}` 也带同一个字段 —— **摸牌是
    TAGGING BACK IN 最常触发的时机**（「队友只要摸到牌就分他一半」），
    不带上它界面上就只会看到两边手牌张数莫名跳变。
  - ⚠️ 两张都是**变色牌**（`color_kinds` 里带上 `TP` / `TD4`），不选色发上来会被
    整手拒收 —— 同 v1.14 那三张无怜悯黑牌的教训。

### 胜负判定与断线
**单局定胜负**：第一个出完手牌的人获胜（`reason="emptied"`；组队档见上一节）；
认输/中途退出/掉线判负**只让本人出局，牌局继续**，只剩一个人时该人获胜
（`reason="last_remaining"`）。

**断线自动过牌**：轮到一个已断线的玩家时，服务端替他「摸一张并过牌」并广播
`uno_event{kind:"autopass"}`，避免整桌被 120s 保座卡住。**护栏**：若除他之外
没有任何在线的真人或人机，则**不做自动过牌**，退回等保座超时判负——否则回合会
在几个断线座位之间无限自转（忙循环，还会把牌堆摸空）。

## 十八、军棋协议（2人对战 · 明棋 / 暗棋）

### 概述
12 行 × 5 列，双方各占 6 行；两半之间还有一排 3 个「前线」（可穿过的铁路）+
2 个「山界」（没有边）。每方 25 枚棋子摆在 23 个兵站 + 2 个大本营上（行营不能放子）。
**房主在等待大厅里选明棋或暗棋**，以及暗棋下「阵亡是否公开身份」。

### 房间创建
`game` 传 `luzhanqi`，`max_players` 为 2。房间对象另带两个字段：

```jsonc
"luzhanqi_mode": "open" | "hidden",   // 默认 open（明棋）
"luzhanqi_reveal": true               // 仅暗棋有意义：阵亡是否公开棋子身份
```

### 对局分两个阶段
开局先进**布阵阶段**（==`game.phase === "setup"`==）：服务端给双方各发一套合法的
**随机默认阵型**，玩家点两子交换 / 点「随机」重掷 / 点「确认布阵」，
**双方都确认**才进 `playing`。布阵阶段**对手半场的棋子身份也不下发**（明棋同样扣着）。

⚠️ 进对局屏那一次走的是 `game_start`（**客户端靠它导航到对局屏**），
不是 `luzhanqi_setup` —— 发错了房主能进、加入方永远停在房间页。

### 客户端 → 服务端

| type | 字段 | 说明 |
|---|---|---|
| ~~`luzhanqi_pick`~~ | — | **v1.15 起改用统一的 `room_setting`**：`{"key":"mode","value":"hidden"}` / `{"key":"reveal","value":false}`（两项各自独立）。老客户端发这条会收到「客户端版本过旧」 |
| `luzhanqi_setup` | `action`: `swap` / `random` / `preset` / `confirm`；`a`/`b`: `[r,c]`（swap 用）；`name`: 阵型键（preset 用） | 布阵四个动作。**阵型名单随视图下发**（`game.presets: [{key,label}]`），客户端不抄一份 |
| `luzhanqi_move` | `from_x, from_y, to_x, to_y` | x = 列、y = 行（同象棋） |
| `surrender` | — | 通用认输 |

### 服务端 → 客户端

| type | 内容 | 说明 |
|---|---|---|
| `game_start` | `game`（逐人裁剪）、`first: "red"` | 进入对局屏，`phase` 为 `setup` |
| `luzhanqi_setup` | `game` | **只回给刚改阵型的那个人** |
| `luzhanqi_ready` | `ready: {red, black}`、`phase` | 广播「谁确认了」 |

### 信息裁剪（本游戏的核心不变量）
- **暗棋下对手棋子的身份压根不下发**（不是渲染时藏）——与 UNO「手牌私有」同一条纪律。
  回归在 WS 层：`test_ws_luzhanqi.py::test_opponent_never_sees_my_pieces_over_the_wire`。
- 唯一例外：**司令阵亡后亮出的那面军旗**（`flag_revealed` + `newly_revealed`）。
  `newly_revealed: [{"color","at"}]` 把军旗位置一起给出去 —— 只发布尔值等于没发。
- **战报按收件人裁剪**：`mode == "hidden" && !reveal` 时只保留结果与**自己那一枚**的
  身份（`mask_battle`）。明棋或 `reveal == true` 则全公开。
- **`legal` 只算收件人自己的**：发「轮走方全部着法」会泄露「某位置有子可动」=
  「它不是地雷也不是军旗」。

### 布阵约束（只在服务端判定）
军旗必须在大本营；地雷只能在最后两排；炸弹不能在第一排。`luzhanqi_setup{swap}`
非法时回 `error`，服务端**原样回滚**。

### 胜负判定
吃对方军旗即胜（`reason="flag"`）；**无棋可走判负**（`reason="nomove"`，即吃光对方
所有能移动的棋子）；连续 120 半回合无吃子判和（`reason="no_capture"`）；
认输 / 掉线超时同其它游戏。

### 断线重连
`sync` 里 `game.phase` 决定客户端渲染布阵界面还是对局界面 —— 布阵阶段重连回来
不能直接跳到对局界面（对面还没确认）。回归：
`test_ws_luzhanqi.py::test_sync_during_setup_stays_in_setup`。
