# 重力四子棋设计文档

- 屏：`app/src/screens/ConnectFourScreen.tsx`
- 引擎：`server/app/game/connect4.py`　AI：`server/app/game/connect4_ai.py`
- 人数 2（须满员开局）｜支持人机｜战绩落库（含终局盘面回放）

## 玩法

7 列 × 6 行，棋盘竖立。**黑先**（房主执黑）。选一列把棋子丢进去，棋子顺重力
落到该列**最下面的空位**——所以棋子一层层往上堆，列满 6 颗就不能再落。

先连成四子者胜：横 / 竖 / 两条斜线都算。42 格填满仍无四连为和棋。

## 交互设计

### 点列即落子：热区是整列，不需要两步式

象棋/五子棋要两步落子或放大镜，是因为棋盘格子受物理尺寸限制低于 44pt。重力四子棋
**没有这个问题**：一次落子的决策单位是「列」，热区就是整列——宽 ≈ 48~62px、
高 6 格 ≈ 290~370px，两个方向都远超 44pt 下限，误触概率极低。所以保留最直接的
「点一下就落」，不为小棋盘设计的补偿手段在这里是多余摩擦。

> 首次实现时给满列加了 `disabled`，结果点上去毫无反应（RNW 里 disabled 的
> `TouchableOpacity` 是 `pointer-events: none`，连应用内提示都不会弹）。现在
> **只在不是自己回合时禁用**，满列照样可点，点了弹「这一列已经放不下了」。

### 落点行由服务端算，客户端只发列号

点列时客户端发 `{type:'move', x: col}`，服务端按重力算出落点行，随 `move` 广播
回来（`y` 就是落点行）。客户端不自己数「这一列还剩几个空位」——一旦本地状态和
权威盘面差一格就会画错（飞行棋「客户端自己推路径画错」是同一类教训）。
回归靠 `e2e_connect4_smoke` 的第 6~8 步：同一列连落三手，落点行必须依次是 5/4/3。

### 提示标：「连四」与「堵」

轮到自己时，棋盘会在相关列的顶部压一枚小标：

- **连四**（浅绿底）：这一手落下去直接连成四子，赢了。
- **堵**（浅琥珀底）：对手下一手就能连成四子，不堵就输。

两个标**同时**用颜色 + 文字标签 + 形状（圆角矩形 / 菱形）三条通道，颜色单独承载
信息不符合 WCAG 1.4.1。棋盘下方另有一行图例解释含义。

实现是本地推演（`winningCols()`，与引擎的四连判据同构，只用于高亮，不参与裁决）。
同一列既在「连四」又在「堵」里时只显示「连四」——自己能赢就不用管对手。

### 动画与反馈

| 动作 | 效果 | 时长 |
|---|---|---|
| 落子 | 棋子从棋盘顶部滑到落点行（`translateY`） | 160ms |
| 最后落子 | 盘面中央一枚黄点 + 深墨描边 | 常驻 |
| 落子 / 终局 | 震动 10ms / 30ms（仅原生） | — |

**不做「从顶部落下」的物理模拟**：一帧内 6 格的下落配缓动看起来像滑入而不是掉落，
但与逐格动画相比少 5 次重绘，且不会被后续广播打断。落点行既然权威，动画只需要
交代「哪一列、落在第几行」。

### 棋盘美术

深蓝棋盘 + **浅色**空位圆槽 + 圆盘棋子。空位故意用浅色而不是经典四子棋的深洞：
深洞 `#0B1B3F` 与黑盘只有 1.03:1，黑棋会彻底消失；浅槽是 14.04:1。
棋子按 `(r,c)` 顺序渲染，DOM 文本顺序即盘面顺序（E2E 依赖，别改成 map by id）。

## 状态与协议

```
sync / game_start 的 game 载荷：
  { cols: 7, rows: 6, board: number[][], moves: [...],
    next: 'black'|'white', your_color, winner, reason }
  board 是 board[row][col]，row 0 在最上面
落子：客户端 → { type:'move', x: col }
     服务端 → { type:'move', x: col, y: 落点行, color, next }
终局 → { type:'game_over', winner, reason }   reason ∈ four | draw | surrender | disconnect
```

**不要复用五子棋那套 `board_size: 15` 的载荷**——`_build_sync` / `_handle_start` /
`player_disconnect` 三处都要走 connect4 分支，漏一处重连后棋盘尺寸就错乱。
游戏 key 是 `connect4`（不是 `connect_four`）。

## 结算

弹窗只有「返回房间」（无「再来一局」）。终局后房间回到 `waiting`、续开由房主点
「开始游戏」，真人非房主的 `ready` 被复位、要重新点准备。

## 上一手的连线（v1.17）

从最后一手出发，把它在四个方向上连成的**同色段**串成一条线（≥2 连才画）。
「对方在铺哪条线」是这一局最该看出来的东西，但盘面上一片圆盘很难一眼读出来 ——
把那一手所在的连子串起来，视线自然就跟过去了。

⚠️ **线画在圆槽之下**：圆盘直径 0.78 格、相邻两格之间有 0.22 格空隙，线只从空隙里
露出来，看起来是「穿过这几枚圆盘」而不是盖在它们上面 —— 盖上去会挡住盘面本身，
而**盘色是判断归属的唯一依据**。两端正好收在首尾两枚圆盘的边缘。

⚠️ **这个 `useMemo` 必须放在 `if (!game) return …` 之前**：第一版写在提前 return
之后，于是「无 game」那一帧不调用它、有 game 那一帧调用 —— 条件式 hook，整屏白
（`e2e_connect4_smoke` 第 3 步超时才发现）。同 `RoomScreen` 的 `ai_difficulty`。

颜色 `connect4LineHint`（vs 深蓝棋盘底 5.74 ✓）：刻意不用 `connect4WinHint` 那支绿，
绿色在这一屏已经等于「连四」，**一个颜色只能有一个含义**。

## 配色

单一来源 `app/src/theme.ts`（对局屏与战绩回放共用），括号内是实测对比度：

| 常量 | 值 | 用途 / 实测 |
|---|---|---|
| `connect4Frame` | `#1E3A8A` | 棋盘底 |
| `connect4Slot` | `#DCE7FF` | 空位圆槽：vs 棋盘底 **8.34 ✓** |
| `connect4Black` | `#151A24` | 黑方盘：vs 空位槽 **14.04 ✓** |
| `connect4White` | `#FFFFFF` | 白方盘：vs 空位槽 **1.24 ✗** |
| `connect4DiscEdge` | `#0B1B3F` | 盘沿：vs 空位槽 13.61 ｜ vs 白盘 **16.90 ✓** |
| `connect4WinHint` | `#BBF7D0` | 「连四」标底：vs 棋盘底 8.55 ✓，深墨字 14.64 ✓ |
| `connect4BlockHint` | `#FDE68A` | 「堵」标底：vs 棋盘底 8.32 ✓，深墨字 14.24 ✓ |
| `connect4Last` | `#FDE047` | 最后落子黄点：vs 黑盘 13.22 ✓ ｜ vs 白盘 1.32 ✗ 靠描边 |

**白盘的边界完全靠那圈深墨盘沿**（16.90:1）——盘面本身压在浅槽上只有 1.24:1。
改色时这两条必须一起保住（和五子棋白子描边、象棋奶油盘面同一条教训）。

## 已知坑（勿回退）

- **满列不能 `disabled`**：禁用后是 `pointer-events: none`，点上去既没反应也没提示，
  用户只会觉得「点了没反应」。只在非自己回合时禁用。
- **落点行必须服务端给**，客户端只发列号（见上）。
- **`board` 按 `(r,c)` 顺序渲染**，否则 E2E 的盘面文本断言会 flaky。
- **AI 搜索要丢线程池**：`asyncio.to_thread(connect4_ai.best_move, 副本, stone)`。
  0.5s 的同步搜索直接 `await` 会卡住整个进程的事件循环（象棋踩过同一条）。
- **`winning_cols` / `would_win_at` 是只读的**：内部临时落子后必须还原，
  否则 AI 与提示高亮都会污染权威盘面。

## 待优化项

- 棋盘格子在小屏（360×640，`cell` 下限 26px）上略低于 44pt。落子单位是整列，
  实际热区足够；但若要逐格做「落点预览」，需要另加放大镜或拖动。
- AI 目前是「迭代加深到时间预算」，没有开局库；对熟练玩家还是偏弱（自对局常和）。
  要更强可以加置换表或开局定式表。
