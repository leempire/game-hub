# 飞行棋 设计文档

- 屏：`app/src/screens/LudoScreen.tsx`　棋盘视图：`app/src/screens/LudoBoardView.tsx`　几何：`app/src/ludoBoard.ts`　引擎：`server/app/game/ludo.py`　AI：`server/app/game/ludo_ai.py`
- 人数 2-4（≥2 可开）｜支持人机（可加多个凑满 4 人）｜战绩落库

## 玩法

**赛道是「围着十字边缘一圈」的 52 格环形**（v1.6.1 按 tmp/飞行棋.png 重做）：
十字的四条边贴着棋盘外缘走，四个凹角向里切进去，所以环看起来是一个十字轮廓。
每玩家 6 格终点航道。掷 6 才能起飞，掷 6 有额外回合；连续 3 次掷 6 所有飞机
回基地（乐极生悲惩罚）。落在敌机所在格把敌机撞回基地。终点需精确到达，
超出则折返。排名按到达顺序。

**同色跳格与虚线捷径**：

- 赛道 52 格按 **蓝→绿→红→黄四色循环**着色，每色 13 格。落点若与**自己**同色，
  再向前跳到下一个同色格（多走 4 格）。只跳一次，不连锁。
- 棋盘上有**四条虚线捷径**（黄/蓝/绿/红各一条，**一条归一个玩家**），画在十字
  四个角的空白走廊里。只有踩到**自己颜色的那条**虚线起点格才生效 → 沿虚线飞
  **12 格**到另一个同色格。
- **跳、飞各最多一次**，顺序由落点决定：踩虚线格是先飞后跳；**跳到**虚线格上
  则飞完就停（标准规则原文如此）。
- 落点是自己颜色格、且格上已有敌机 → **直接撞落，不跳不飞**（否则等于眼睁睁
  放过对手）。

## 标准棋盘

### 方位与配色（对齐 tmp/飞行棋.png / tmp/飞行棋.md 的视觉规格）

| 座位 | 基地方位 | 终点航道 | 颜色 |
|---|---|---|---|
| 0 | 左上 | 左臂 | 蓝 `#2E7FD6` |
| 1 | 右上 | 上臂 | 绿 `#2E9E44` |
| 2 | 右下 | 右臂 | 红 `#D8332B` |
| 3 | 左下 | 下臂 | 黄 `#F2D024` |

即**每个座位的臂是它基地「逆时针那一侧」的臂**（左上基地 → 左臂），与标准棋盘
一致。引擎的 `COLORS` 顺序、客户端 `TRACK` 表的起点/绕行方向、`HOME` 表三者
必须同时对得上，任一处反了都会变成镜像棋盘。

### 三条咬合的不变式

- 起跑线偏移 `[0, 13, 26, 39]`，而 `13 ≡ 1 (mod 4)`，所以四条起跑线正好落在
  配色循环的四个不同颜色上——**每个座位的起飞点天然就是自己的颜色**。
- 于是对**任何座位**都有：「相对进度是 4 的倍数」⇔「踩在自己颜色上」。
  引擎的 `is_own_color()` 因此不需要 seat 参数。
- 引擎侧由 `test_ludo.py::TestTrackColors` 锁死这三条不变式（起点配色、同色判据、
  每色恰好 13 格）。

### 赛道只走 49 格（`RING_END = 48`）

外圈有 52 格，但飞机**自己只走 0..48**：自己的航道入口就在相对进度 48，
绕到自己的航道口就拐进去；剩下的 3 格（52 − 49）是「起跑线之前」的那几格，
自己永远不走。于是：

| 相对进度 | 含义 |
|---|---|
| −1 | 基地 |
| 0..48 | 赛道（全局格 = `(progress + PLAYER_OFFSETS[seat]) % 52`） |
| 49..54 | 自己的终点航道（外 → 内，6 格） |
| 55 | 到达（停在中圈自己的三角里） |

**这是几何的必然，不是可选参数**：四条起跑线相距 13，各自的航道入口（左上基地
是 `(7,0)`、右上 `(0,7)`、右下 `(7,14)`、左下 `(14,7)`）都落在「自己起跑线 + 48」
上。任何一家的可走赛道长度都是 49。

### 虚线捷径：只有自己颜色那条能飞（相对进度 16 → 28）

赛道上每 13 格一处虚线，绝对索引 **3 / 16 / 29 / 42**，一色一条：**3 黄 / 16 蓝 /
29 绿 / 42 红**。但**只有落在自己颜色的那条上才能飞**——标准规则原文：「走到与
自己颜色相同且有虚线连接的格子」。别人的虚线对你无效。

因为「自己颜色」⇔「相对进度是 4 的倍数」，而 3/16/29/42 里**只有 16 是 4 的
倍数**，所以对任何座位，可用虚线都恰好是**相对进度 16** 那一条，飞 12 格到 28。

- 四条绝对虚线各自属于一个座位（相对进度都是 16，绝对位置不同）：
  蓝方 `(4,11)` / 绿方 `(11,10)` / 红方 `(10,3)` / 黄方 `(3,4)`。
- 从蓝方起飞点（相对 0，蓝色）顺时针走 3 格正好踩到那条**黄色**虚线——这是
  位置描述（蓝方遇到的第一条箭头），但**它不归蓝方用**。
- 画出来是旋转对称的一组箭头：黄箭头横穿上臂根部、蓝箭头竖穿右臂根部、
  绿箭头横穿下臂根部、红箭头竖穿左臂根部（与参考图逐条一致）。
- 画面上**自己那条的起点是实心圆、其余是空心圆**：四条一色一条，光靠颜色
  认不出哪条归自己（WCAG 1.4.1），形状是第二通道。
- 早先的实现在这里错过两次：① 只做了「相对进度 3 飞 12 格」，四条虚线全按
  `相对进度 % 13 == 3` 触发，于是**任何座位踩到任何一条虚线都能飞**（蓝方能在
  绿色虚线上起飞）；② 补了 `% 13 == 3` 之后，相对进度 42 那条会飞出 54、越过
  自己的航道入口，当时当成「几何必然的特例」加了 `arrow_target() → -1` 兜底。
  **加上「必须是自己颜色」这条标准规则后两个问题一起消失**——42 那条压根不会
  被任何座位踩到，`is_arrow()` 直接返回 False。

### 棋盘美术（按 tmp/飞行棋.png 重做过一版，勿回退）

- **外圈比内圈宽 2 倍**：逻辑上仍是 15×15，但第 0/14 行/列各占 2 个单位，
  总宽 = 2 + 13 + 2 = **17 个单位**（`ludoBoard.GRID_UNITS`）。所有坐标换算走
  `unitOf / cellRect / cellCenter`，**不要再写 `col * cell`**。
- **赛道是十字环**：沿第 0/14 行与第 0/14 列走，到四个凹角处切到第 4/10 行/列
  再折回。四个凹角是**斜切**（如 `(4,3) → (3,4)` 共角不共边），这是 4×13=52 的
  固有结果。**不要**为了正交补连接格（补了就变 56 格，与引擎的 52 不符）。
  被切掉的那一格（`CORNER_CUTS`）按对角线分成两半，各取转弯前后那一格的颜色。
- **基地是留白，不是色块**：四角只留棋盘底色（`#F1F1F1`），外角放一个黑框小
  停机坪（约 3.7 个单位见方，`apronRect`），内含 2×2 白环停机位。早期把整块
  6×6 涂成座位色，又重又挤，是「棋盘太紧凑太丑」的主因。
- **赛道只涂色、不画格线**，每格一个奶油圆（`#F2ECCE`）；航道同理。格心圆
  **带深色描边**——见下面的对比度说明。
- **中央 3×3** 被两条对角线切成 4 个三角，箭头尖全部指向棋盘正中心，每个三角
  与同色的臂相连，三角内一个奶油圆（位置就是该座位已到达飞机的停靠点，
  `CENTER_PARK` 取的是**三角重心**，坐标带小数）。
- **棋盘是固定美术**：4 个基地 / 4 条航道 / 中央四色三角永远都画，2 人局也一样。
  只画参赛的两色会让半个棋盘空白得像没渲染出来。座位色优先取对局状态、
  该座位没人时退回固定色表 `TRACK_COLOR_ORDER`。
- **棋子位置走 `piecePixel()`**：基地里的飞机落在停机位上（不走网格），其余按
  `cellFor` → `cellCenter`。停机位与 `apronSlotPixel` 共用同一份换算，
  所以画出来的白圆和飞机落点永远重合。

## 界面构成

```
┌─────────────────────────────┐
│                    [我 2/4 ▾]│  玩家进度：右上角半透明浮层（默认收起）
├─────────────────────────────┤
│                             │
│      标准十字棋盘（SVG 静态层）  │  52 格四色循环轨道 + 4 个黑框停机坪 +
│      飞机 = 动画覆盖层          │  4 条航道 + 中央四色三角 + 4 条虚线箭头
│                             │
├─────────────────────────────┤
│  [⚀]  点击骰子掷骰 / 等待 X 操作│  骰子面 + 回合提示（或临时消息）
│   [掷骰子]  [认输]  [?]      │  掷骰按钮常驻，轮不到自己时置灰
└─────────────────────────────┘
```

**棋盘 = SVG 静态层 + 棋子动画覆盖层**（v1.5.1 重构）：

- 静态部分（轨道 / 航道 / 停机坪 / 中央三角）用 `react-native-svg` 画，15×15 逻辑网格。
  格子太多，SVG 比 View 拼省节点。
- 棋子**不画进 SVG**：动画 SVG 的 `cx/cy` 必须 `useNativeDriver:false` +
  `Animated.createAnimatedComponent(Circle)`，既慢又和项目其它动画写法不一致。
  改成绝对定位的 `Animated.View` 圆片覆盖层后，位移走 `transform` 可以用原生驱动。
  覆盖层必须是 `Svg` 的**兄弟节点且在其后**（画在上层），并加
  `pointerEvents="box-none"`——否则会吞掉棋盘触摸，只有棋子本身是命中目标。
- **棋盘边长按可用空间推导**（`onLayout` → `edge = min(实测宽, 实测高)`，下限 224），
  内圈格 = `edge / 16`。不再是写死的格宽，小屏也能整盘放下。

## 交互设计

### 掷骰 → 选子 两段式

1. **掷骰按钮常驻**（≥47px 高），轮不到自己时**置灰不可点**而不是隐藏——
   隐藏会让按钮在 4 人局里反复出现/消失，拇指位置跟着跳。
2. 掷出后若有多架飞机可动，进入 `phase === 'move'`，提示变为「点击飞机移动」，
   可动的飞机**白环 + 半透明墨底垫 + 大一圈**，点击即走。
3. 无可动飞机时服务端直接移交回合，客户端靠 `dice_rolled` 里的 `current_seat`
   同步座位——**不带这个字段界面会停在「点击骰子掷骰」而实际已轮到别人**。

### 掷骰动效

骰子面（`icons.DiceFace`，矢量画点、不用 emoji）常驻在控制区，**起转 → 落定**
两段：

- **按下即起转**（`beginDieRoll`）：不等服务端回包，按下就有反馈（<100ms）。
  骰面每 80ms 跳一个随机点数，同时描边变主题色表示「在转」。
- **落定**（`settleDie`，由 `dice_rolled` 触发）：停在服务端给的**真实点数**上，
  弹一下（1 → 1.18 → 1，200ms）并震动 15ms（原生）。
- **最短起转 `DICE_MIN_MS = 420`**：本地后端回包只要几毫秒，不兜住的话动画等于
  没播。落定前先补齐不足的时长。掷 6 可连掷，一轮「6 + 起飞」是两段动画串行，
  起转时长直接乘以连掷次数，所以压到 420ms 而不是更长。
- 骰子面对**所有座位**的掷骰都动（别人掷骰时也能看到点数）——上一把掷了几点是
  接着决策要用的信息，不能只在轮到自己时才显示。`sync` 时用 `dice_value` 恢复，
  否则重连后骰面是空的。
- 计时器在卸载时清理（`setInterval` / `setTimeout` 各一个 ref）。

### 动画闸门：掷骰播完才允许行动

**掷骰动画播完之前，回合推进一律不生效**——玩家和人机一视同仁。否则会出现
「骰子还在转，飞机已经飞走了」，看不懂刚才那步是哪来的。

- `dice_rolled` **只入队**（`pendingRollsRef`），落定后才应用 `movable` /
  `phase` / `current_seat`。所以动画期间 `movable` 还是空的、`phase` 还是 `roll`，
  玩家点棋子**点不动**（不需要额外禁用逻辑，状态本身就没到位）。
- `piece_moved` 在动画期间**入队**（`pendingMovesRef`），落定后按序补播。
  人机是「掷完立刻走」，两条广播几乎同帧到达，不挡的话棋子会抢在骰子前面动。
- 落定后还要再等 `DICE_SETTLE_GAP_MS = 120`（骰子「弹一下」是 200ms）才放行
  积压的走子，两件事不要糊在一起。
- 闸门状态（`dieBusyRef` + 两个队列）在 `sync` / `game_start` 时清空——重连后
  整盘重建，积压的旧消息已经过时。
- 落定回调通过 `onDieSettledRef` 注册（由 socket effect 赋值），骰子动效不必
  知道 `piece_moved` 的细节，两边也不用互相依赖成一团；effect 清理时置空，
  免得上一轮的闭包被捞起来。
- **兜底超时 `DICE_TIMEOUT_MS = 2500`**：起转是乐观的（按下就转），万一服务端
  不回 `dice_rolled`（走子被拒、断线），骰子会一直转、闸门一直关，整个界面卡死。
  超时后停表并放行。
- 骰子描边是**动画状态的可观测信号**：起转 `colors.primary`、落定 `#111827`。
  `e2e_ludo_smoke.py` 靠它断言「按下即起转」与「起转时长不少于 0.45s」。

### 基地飞机必须可点（重要）

基地里的飞机（`progress === -1`）掷 6 时也是可动的（起飞）。早期渲染只给
轨道/航道上的飞机挂了 `onPress`，基地飞机是纯装饰——于是掷出 6 后界面提示
「点击飞机移动」却无处可点，玩家直接卡死。现在**所有棋子都是同一个
`Animated.View`**，可动时加高亮环并接管触摸，基地/轨道一视同仁。

**高亮范围就是服务端的 `movable` 列表**：停机坪的飞机只在掷出 6 时才进这个
列表，已到终点的飞机永远不进（`_get_movable_pieces` 保证）。

### 棋子移动动画（含其他人 / 人机）

- **路径由服务端给**：`piece_moved` 带 `path`（逐格经过的 progress 序列）与
  `segments`（每段是 `walk` / `jump` / `fly`）。加了跳格与虚线飞行之后，
  路径形状取决于落点（跳一次 + 飞一次、顺序还看是不是跳上虚线格的），
  **客户端按 `old+dice` 自己推会画错**——飞机停在半路、提示文案也对不上。
  `path` 缺失时才退回 `ludoBoard.progressPath()` 的「逐格走」兜底。
- 三段节奏不同：走子 `stepDuration(steps)=clamp(600/steps,55,115)`、
  跳格 `JUMP_MS=220`、飞行 `FLY_MS=460`（飞行途中还会放大到 1.3 再落回，
  让「飞过去」和「走过去」一眼可分）。用 `Animated.sequence` 串起来。
- **位置只由 `Animated.Value` 决定，不由 `gameState` 推导**——否则动画途中来一次
  `setGameState` 会把正在飞的棋子拽走。`gameState` 只负责颜色/可动/计数/回合。
- **撞机**：走子动画结束后，被撞的飞机从原格飞回基地（`CAPTURE_MS=260`），
  再统一按逻辑位置重排。
- **同格叠子**：落定后按逻辑 `progress` 分组，同格多子以半径 `CELL*0.20` 环形错位，
  否则 4 架叠成一架。
- 真人与人机走的是**同一条 `piece_moved` 广播**，动画一视同仁。

### 反馈

- 撞机：「击落 N 架敌机！」临时消息（2s 后消失）。
- 虚线飞行：「沿虚线飞行！」；同色跳格：「同色跳格！」——飞机突然跨好几格，
  **不解释会以为界面出错了**，必须说出来。
- 到达终点：「一架飞机到达终点！」。
- 连续三次掷 6：「连续三次掷6！所有飞机回基地」。
- 临时消息优先于回合提示显示，避免两条文案打架。

## 状态与协议

- `game_start` / `sync` **逐人下发**并附 `your_seat`（seat = `room.players` 索引）。
- `roll` → 广播 `dice_rolled`（`seat` / `dice` / `movable` / `extra_turn` /
  `penalty` / **`current_seat`**）。
- `move_piece` → 广播 `piece_moved`（含 `path` / `segments` / `captures` /
  `finished` / `extra_turn` / `current_seat`）。**`path`/`segments` 是前后端契约的
  一部分**，回归见 `test_bot.py::test_ludo_piece_moved_carries_jump_and_fly_path`。
- 认输/断线 → 广播 `player_surrendered`。**飞行棋的认输只是弃权，局可能继续**，
  所以走 `player_surrendered` 而不是 `game_over`；服务端在弃权者正轮到出手时
  必须 `_advance_turn`，否则回合停在已 finished 的座位上，整桌谁也动不了。
- 人机：`ludo_ai.best_move` 选子。一个房间可加多个人机（昵称带序号
  「人机·棋手2」），满员即止。bot 一个回合 = 掷骰 + 选子走，掷 6 加手会再次
  调度自己。

## AI 策略

`ludo_ai.best_move` 只做「选哪架飞机」这一个决策（掷骰是纯随机）。对每架
可动飞机算启发式分数取最高：

| 因子 | 权重 | 理由 |
|---|---|---|
| 撞机 | +120/架 + 对手进度×0.5 | 把对手踢回基地，收益最大 |
| 精确到达终点 | +90 | 多一架到达，直接推进排名 |
| 起飞（掷 6） | +45 | 否则 6 白白浪费 |
| 进入终点航道 | +35 | 进度 > `RING_END`(48) 后不会被撞，安全区 |
| 基础分 | +0.6 × 新进度 | 同等条件下推最靠前的那架 |
| 落点风险 | −18/个威胁 | 落点在主轨道且对手能在 1-6 步内精确踩到 |

威胁判定还要求 `op + gap <= RING_END`：对手若因此走进终点航道，就不会在赛道
发生撞机。

**「新进度」一律走引擎的 `resolve_landing()`**：同色跳格与虚线飞行是强制触发的，
按 `old+dice` 估算会低估收益、也算错落点危不危险（例如落到 12 实际会跳到 16，
再踩到虚线还会飞 28）。
`resolve_landing` 是只读的，AI 拿它推演没有副作用（有单测锁）。

## 结算

全员到达或只剩一人未完成时 `_finalize_ludo_game` 算排名（到达者按到达时间、
未完成者按已到达数），并把房间放回 `waiting`（房间只有等待中/游戏中两态）。

## 配色

- 四家棋色是 `theme.ludoColors`（对局屏与战绩回放共用），取值对齐标准棋盘：
  蓝 `#2E7FD6` / 绿 `#2E9E44` / 红 `#D8332B` / 黄 `#F2D024`。前三个 vs 棋盘底
  `#F1F1F1` 分别是 3.63 / 3.05 / 4.20 ✓；**黄只有 1.35:1**——任何够亮的黄压在
  浅灰底上都到不了 3:1，想达标就得暗成土黄、那就不再是棋盘上的那个黄了。
  所以第二通道**不是**加深底色，而是**给每个格心的奶油圆加深色描边**
  （`CREAM_EDGE`）：格子边界靠圆环成形，颜色只负责区分是哪一色。
  棋子同理靠深色描边成形（静态 `rgba(0,0,0,0.6)`、可动深墨 `#111827`）。
- **可动高亮曾经是金色 `#FFD700`**：它在米色棋盘上 1.31:1、在黄子上 1.41:1，
  两个方向都看不见。现在改成「深墨环 **+ 直径放大一档**（0.78→0.86 格宽）」，
  尺寸是第二通道——颜色不能单独承载信息（WCAG 1.4.1）。
- **棋子图案**（`icons.PlaneGlyph`，白色俯视客机剪影 + 深墨描边）：颜色不是唯一
  信息通道的第二重保障。棋子落在**自己颜色的格子**上是常态（同色跳格规则保证），
  光靠颜色它和格子糊在一起；图案 + 描边才分得开。
- **虚线箭头**用「深墨垫底 → 奶油白 → 本色虚线」三层描边：箭头会横穿赛道格、
  航道格和棋盘底三种底色，单色描边总有一种看不清（深墨压红格只有 1.9:1）。
  垫一层白三种底都成立。本色那层要够粗（0.22 单位 vs 垫底 0.38），否则整条
  箭头看上去是黑的、认不出是哪一色的捷径。箭头起点另有实心圆点标记
  「捷径从这里开始」。
- 停机位的白圆半径特意比棋子大一圈：棋子压在**同色底**上（红子放红停机坪、
  黄子放黄航道）全靠这圈白边成形。

## 已知坑（勿回退）

1. **`your_seat` 必须逐人下发**：曾用不存在的字段导致整局无法操作。
2. **基地飞机必须可点**（见上）。
3. **`dice_rolled` 必须带 `current_seat`**（见上）。
4. **认输要移交回合**（见上），`leave_room` / `_on_dc_timeout` 的 ludo 分支
   同样要 `_advance_turn`。
5. **起飞不触发同色跳格**：起飞点本身就是同色格，触发的话掷个 6 就白送 20 格
   （引擎在 `move_piece` 的起飞分支里直接跳过 `resolve_landing`）。
6. **不许跳进终点航道**：相对进度 48 是同色格（也是自己的航道入口），再跳 4 格
   就进了航道，会绕过「终点必须精确到达」这条规则。`resolve_landing` 的条件是
   `cur + 4 <= RING_END`。
6b. **虚线必须踩在自己颜色上才算数**：四条虚线一色一条、各归一个座位，
   只有自己那条能飞（标准规则）。漏了这条会变成「任何座位踩到任何虚线都能
   飞」。加上它之后，可用虚线恒为相对进度 16（四条里唯一 4 的倍数的那条），
   飞 12 格到 28，永远飞不过航道入口（48）。
7. **配色循环 / 赛道坐标 / 虚线位置的常量在两处**：引擎 `server/app/game/ludo.py`
   （权威，走子裁决）与客户端 `app/src/ludoBoard.ts`（只负责画）。改一边必须
   同步改另一边，否则会出现「箭头画在这里、飞机从那里飞」的错位。
   两边都要满足的四条不变式：① 每座位起点是自己颜色；② `progress % 4 == 0`
   ⇔ 自己颜色；③ 每色恰好 13 格；④ 每条虚线起终点同色、跨度 12。

### 迭子（同色叠机）

- **叠机**：同色多架停在同一格就是迭子（引擎不阻止同色共格，客户端按
  `stackOffset` 环形错位画开，否则 4 架叠成一架）。
- **不可飞越**：走子路径**经过**敌方迭子格 → 该走法非法，从 `movable` 里剔除
  （`_get_movable_pieces` 传了 game/seat 时才做这个判定，旧调用点与单测不受影响）。
  判定只看走子路径，终点格不算——落上去是同归于尽，不是穿越。
- **同归于尽**：正好落在敌方迭子上时，**双方全部回基地**（先判再写位置，写完了
  再判会把刚落下的那架也算进「同色叠机」）。服务端在 `path` 末尾追加 `-1`、
  `segments` 追加一段 `bounce`，客户端据此把飞机飞回停机坪并提示
  「撞上迭子，双方 N 架一起回基地」。
- AI 的 `_destination` 同样要判迭子（落上去收益是负的），否则它会主动送死。

### 落点危险提示

轮到自己时，把「对手任一飞机身后 1~6 步内」的格子标出来——掷任意点数都可能
正好踩上去。**半透明红罩 + 格心圆外多一圈红环**：环是形状通道，色觉障碍用户
靠「这个格子多了一圈」也能认出来（WCAG 1.4.1）。只在自己回合画（别人回合标红
没有决策价值，只会让棋盘更花）。纯客户端计算，服务端不参与。

### 虚线箭头的可见性

三层描边：**深墨垫底 → 奶油白 → 本方色虚线**。只画「白垫 + 本色」时，本色可能
与它横穿的那条臂撞色（绿箭头压红臂只有 1.6:1），小屏上根本看不出这里有捷径；
加深墨垫底后无论压在哪种底色上，箭头轮廓都 ≥3:1。箭头起点另有实心圆点。

## 待优化（未排期）
