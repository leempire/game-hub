# 飞行棋增强调研


## 2026-11-04：统一三档人机

简单：movable_pieces 随机。普通：原撞机/到达/直线风险启发式；困难：枚举对手六种骰子、按引擎真实跳格/飞行终点重算风险。骰子分布不随难度改变。

采用「有界迭代加深 + 合法动作随机/策略分档」。不采用改变骰子、资源费用或读取隐藏信息提高强度；保留无参调用的普通档兼容性。难度存在每个 bot 身上，可混合添加；搜索用输入副本在线程池运行，结束/续开后丢弃旧结果。

来源（中英文交叉核对）：
- [游戏难度与搜索评价研究，北京大学](https://ai.pku.edu.cn/docs/2021-07/20210715220553957416.pdf)：区分预算与实际表现，随机游戏需要多局测量。
- [Columbia：Alpha-Beta pruning and Checkers](https://www.cs.columbia.edu/~devans/TIC/AB.html)：时间预算迭代加深，完成一层才采纳结果。
- [TalTech：Game AI heuristics, difficulty, performance](https://courses.taltech.akaver.com/programming-in-csharp/lectures/game-ai-heuristics-difficulty)：搜索深度、预算及随机合法着法用于调节强度。

验证：`cd server && python test/bench_ai_difficulty.py --games 8`。对简单档完整8局、交替先手，胜局数：

| 简单 | 普通 | 困难 |
|---|---|---|
| 4/8 | 7/8 | 6/8 |

这是固定种子的小样本能力检查，不能据此估计 Elo 或保证每局困难都胜过普通。困难档代表更大搜索预算或更完整的策略；合作游戏指队友执行能力更强。全部动作仍由引擎校验。


## 2026-11-04：2v2与规则开关

`ludo.create_game(n,teams='off',capture=True,color_jump=True,exact_finish=True)` 默认保留原结果。2v2要求恰好4人，座位0/2同队、1/3同队；sync发seat_teams与winner_team。队友不互撞，也不形成敌方阻挡；双方仍各自操控4架，全队8架到达才胜，一名队员认输则整队弃权。终局两名胜者并列第一，另一队并列第二。

三个独立开关：capture关闭时不撞机且不受敌叠机阻挡；color_jump只控制落同色后的+4跳格，虚线飞行仍在；exact_finish关闭时超过终点直接到达，权威path截在55（不先越界再拉回）。动画速度slow/normal/fast仅影响客户端逐格时长，不能改变掷骰或裁决。AI使用同一真实落点与队伍谓词，不把队友算作撞击或威胁对象。

参考[飞行棋实物游戏说明书](https://assets.kogan.com/files/usermanuals/KA15IN1GTBW_UG.pdf)与项目既有调研。各地组队细则无统一权威版本；本作明确固定上述规则，不采用代走队友飞机或共享掷骰，避免引入新行动权限。
