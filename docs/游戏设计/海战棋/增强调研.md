# 海战棋玩法增强调研

调研时间：2026-10-12　方式：`byted-web-search` skill（豆包搜索）
现状基线：`server/app/game/battleship.py`（10×10、5 舰 5/4/3/3/2、无道具、命中不续射、AI 单一难度）

## 一、诊断：为什么「太简单」

现在的对局只有两段：**布阵** → **轮流盲打**。布阵之后玩家再没有做过任何一个决策——
每回合机械等价（点一个没打过的格子），唯一的变量是运气。掷骰子式的信息博弈能撑住
「消遣一局」但撑不住「想再玩一局」。

调研里所有成熟的增强手段，本质都是**给「布阵之后」补回决策点**。下面按这个视角组织。

## 二、玩法规则维度

### 2.1 特殊武器系统（Commanders / Sea Battle 2）★核心

Hasbro 的 `Commanders Battleship` 加入技能卡池（侦察 3×3、区域轰炸、单次损伤阻断、
定位轻型舰只、单轮多发），原文明确指出「**卡牌管理成为主要策略维度**」；平衡性靠
「卡牌数量有限，杜绝无限循环」。

Sea Battle 2（涂鸦海战）的「进阶模式」用点数购买配件：雷达、水雷、防空炮、空袭
（轰炸机/鱼雷机/B29）。

**关键机制——武器绑定舰船**（Sea Battle 2）：武器挂靠特定舰船，**该舰被击沉则武器失效**。
这条我认为是整个调研里最有价值的单点，理由：

- 它把**布阵与对战从两段拼接变成一条因果链**——布阵时你要为「武器舰」规划掩护，
  而不是随便摆完开打；
- 它天然自我平衡——不能囤积道具无脑滚雪球，对手有明确的反制目标（找出并击沉武器舰）；
- 它复用现成信息（`sunk` 已经广播了沉的是哪条船），实现成本低。

进阶武器的具体规格取自 The Technical Geekery 的 `Battleship Advance Rules`
与 Hasbro Deluxe Movie Edition：

| 武器 | 效果 | 限制 |
|---|---|---|
| 飞机/侦察 | 显示以选定格为中心的 3×3 区域概况 | 每局 1 次 |
| 导弹 | 普通射击，**若命中则对手须在本舰再标记一次命中并告知** | 首次未命中或直接击沉则第二发作废 |
| 超级炮组 | **仅当第一发未命中时**获得第二发 | 每局 1 次 |
| 范围导弹 | 3×3 区域内敌舰全中 | **仅 1 次，且须携带它的舰船仍在海上** |
| 水雷 | 触发后使该格「停摆」（预先布设） | 布阵阶段投放 |

### 2.2 命中续射（经典房规）

命中后获得额外一次射击机会，直到未命中为止。涂鸦海战（TapTap 评价：「打中了接着打」）
与雾线舰位都把它做成可开关的变体。

**收益**：节奏剧变，目标锁定阶段从「隔回合推进」变成「趁热打铁」，能一回合清掉一整条船，
翻盘与终局都更有戏剧性。

**代价**（来源明确点出）：**放大先手优势**——先手方天然多一个回合，续射把方差进一步放大，
可能一回合扫掉对手大半舰队。缓解手段：

- 先手的第一发不触发续射（补偿后手）；
- 或退一档做**「击沉续射」**（只有击沉才续射）——击沉是离散成就、需要累积数次命中，
  不像命中那样容易无限连锁。

### 2.3 Salvo 齐射制

每回合开火次数 = **自己存活舰数**（开局 5 发，沉一艘少一发）；坐标全部报完后，
防守方**只回报总命中数与总未命中数，不公开具体是哪几发命中**。

策略层级最高的变体：玩家必须靠「5 发里中 2 发」反推是哪两发，高质量的玩家会刻意
安排射击阵型（让每种命中组合都指向不同的舰位）。**但没有具体落点的反馈**，
与现在「一击一回包」的协议差异较大，UI 也需要一次性提交多发，
属于大改。

### 2.4 其他值得记录的变体

| 变体 | 规则 | 评价 |
|---|---|---|
| 布阵不相邻 | 舰与舰不可贴靠（经典纸笔规则） | 低成本、改变布阵心理学，雾线舰位列为其变体开关 |
| 机动舰队 | 每次行动后可让**一艘**友舰沿正交方向平移一格（不越界不重叠，带伤也可动） | 颠覆消耗战模型，命中不再是终结；但需重做「已锁定推理」的心智模型 |
| 扩大网格 | 12×12 / 15×15 / 20×20，并补舰填满面积 | 直接摊薄初始布局优势、拉长对局，需舰队配置可变 |
| 击沉不显示舰种 | 隐藏被击沉舰只的类型 | 增加推理难度，一行改动 |
| 情报延迟 | 命中情报延迟 2 回合才可见 | 增加不确定性 |
| 极速版 | 取消轮流，双方同时报点并即时结算 | 需并发回合机制 |

## 三、AI 难度分级

sinkships 给出的完整阶梯（含平均击穿弹药量），可直接映射为本项目的三档：

| 档位 | 算法 | 平均发数 |
|---|---|---|
| Ensign / 少尉 | 完全随机 | ~60 |
| Lieutenant / 中尉 | 棋盘格 parity 扫描 | ~50 |
| Commander / 指挥官 | **概率热力图**：统计每格能被多少种剩余舰位覆盖，打最高分格；命中后大幅提升邻格权重 | ~45 |
| Captain / 上校 | 搜索-歼灭双态 + parity + 中心权重 | ~42 |
| Admiral / 上将 | 全量合法部署枚举 + 信息熵增益 | ~40 |

**本项目现状**：只有一套固定策略（parity hunt + 线段延伸 target），相当于
「Lieutenant + 半个 Captain」。加档是低成本高收益——引擎是纯函数、AI 独立成文件
（`battleship_ai.py`），且雾线舰位也证明了三档难度是这个品类的标配。

## 四、视觉维度

主流实现走**「方格纸 + 圆珠笔涂鸦」的怀旧风**（Sea Battle 2 / 涂鸦海战）：
方格记事本背景、圆珠笔线条、手绘舰船、手绘爆炸，甚至有「被核弹炸过的地方会露出
方格纸下面的木桌面」。

对视觉的具体启发：

- **命中画叉 `X`、未中画圈 `○`** 是纸笔海战棋的通用记号——这是**形状通道**，
  天然满足项目「颜色不能单独承载信息」（WCAG 1.4.1）的约束，比现在靠颜色区分更好；
- 「露出木桌面」这类**分层透视**是低成本高记忆点的细节；
- ⚠️ 若采用纸质感，必须重算对比度——纸张底色偏浅，浅色记号压上去会低于
  图形 3:1 阈值（项目已有 2048 黄格 1.42:1、扫雷 5 号琥珀 1.99:1 等一批踩坑记录）。

现在的实现是干净现代风（深色盘面 + 色块标记），不是缺点，但辨识度弱于涂鸦风。

## 五、交互维度

- **响应时间**（腾讯交互微动效指南）：用户直接操作触发的反馈应控制在 **100ms** 内。
  本项目的开炮回包是本地后端（几毫秒），延迟不构成问题；关键是**点击后要立刻有「已锁定该格」的预反馈**，
  不能干等回包。
- **三级反馈升级**：未命中 / 命中 / 击沉应给出强度递增的反馈（形状 + 动效 + 文案），
  击沉是可庆祝事件。当前 `ShotEffect` 已有命中/落水动效，击沉缺一个显著的层级差。
- **双棋盘问题**：桌面版的乐趣有一半来自两块棋盘并排（CSS-Tricks 的实现特意让两块盘
  **绝对定位对齐**，以便命中能同时在两块盘上联动播放动画）。手机竖屏放不下两块 10×10，
  本项目用「单棋盘 + Tab 切换 + 未读红点」解决——方向正确，**待优化清单里的
  「敌方海域有未读命中时切过去」已经是它的自然延伸**。
- **布阵交互**：本项目已有点选 + 拖放双入口，调研中主流实现（Yandex/VPchat）也都是
  「手动拖动 / 自动随机」两条路，一致。

## 六、推荐方案（分层，按 收益/成本 排序）

### 第一梯队：低改动、立刻能感觉到的变化

1. **命中续射 + 先手补偿**——`room_manager._battleship_fire` 里回合推进加一个分支；
   配「先手第一发不触发续射」。这是玩家最能直接感知的节奏变化。
2. **AI 三档难度**——简单（parity 随机）/ 普通（现状 hunt-target）/ 困难（概率热力图），
   房间页选难度（对齐雾线舰位的三档）。`battleship_ai.py` 独立成文件，改动封闭。
3. **击沉反馈升级**——击沉时给一个明显强于普通命中的视觉/文案层级。

### 第二梯队：核心玩法增强 ★推荐主攻

4. **特殊武器系统（3 件，每局各 1 次，绑定舰船）**
   - `雷达`：显示选定格为中心的 3×3 区域内是否有敌舰（只报有/无，不报位置）；
   - `齐射`：一次性提交 3 格，分别回包；
   - `空袭`：3×3 区域范围打击（命中判定按格）；
   - 三件武器在**布阵阶段**分别挂靠到 3 条自选舰船上，**该舰被击沉则武器失效**。
   - 这是唯一一条能把布阵与对战缝成一条因果链的机制，也是「玩法太简单」的正面解。

## 八、v13：棋盘尺寸 / 舰队配置可变（2026-10-14，第三梯队第 5 条落地）

### 8.1 三档与它们的舰队

| 尺寸 | 名字 | 舰队 | 占格 |
|---|---|---|---|
| 6×6 | **闪电战** | 3 / 2 / 2 / 2（4 艘） | 9/36 = 25% |
| 10×10 | **标准** | 5 / 4 / 3 / 3 / 2（经典 5 艘） | 17/100 = 17% |
| 12×12 | **大战场** | 5 / 4 / 3 / 3 / 2 / 2（6 艘） | 19/144 = 13% |

⚠️ **6×6 与 12×12 的舰队配置是本作自己定的，没有来源**：调研只写了「棋盘尺寸 /
舰队配置可变（6×6 / 10×10 / 12×12）」，而变体清单类来源（Rare Pike、雾线舰位）
列的是**尺寸档位本身**，逐档舰队没给。取值的两条约束写在代码注释里：
①占格比例与标准档接近（太小则开局全靠猜、太大则一局拖不完）；
②最长的那艘 ≤ 边长 − 2，否则随机布阵的接受率会崩塌。

### 8.2 与已有的房间级设置同构

`battleship_pick_size` 与扫雷难度 / 军棋玩法 / 深空休眠地图**完全同构**：
只有房主、只有 `waiting`、改完**广播一条 `lobby` 给全房**（只回给房主的话，
别人看到的还是旧尺寸）。创建房间接口**不收**尺寸，建房给缺省档（标准）。
回归：`test/test_ws_battleship_size.py`（6 条）。

### 8.3 「尺寸只有一个来源」这条纪律落到哪儿

- **引擎**：`gs["size"]` 是唯一来源，模块级的 `BOARD_SIZE` 退化成**缺省值**；
  凡是「有多大」的判断一律 `len(board)` 或显式传进来的 `size`。
- **客户端**：尺寸与**舰队组成**都随载荷下发（`board_size` / `fleet`），
  客户端只把英文船名翻成中文 —— 舰队组成抄一份的话，加一档就要改两处，
  两边一旦不一致就是「布阵放不下 / 服务端回一句布阵不合法」。
- **AI**：`battleship_ai` 一行签名都没改 —— 它从**自己收到的棋盘**推尺寸
  （`len(board)`）与舰队（`fleet_of(len(board))`），所以三档共用同一份搜索。

### 8.4 踩到的两颗雷（都写进回归）

1. **默认武器挂靠写死了船号 5**（`{radar: 5, salvo: 4, strike: 3}`）——
   6×6 的舰队只有 1~4 号船，那份默认分配在那张图上**非法**。
   现在改成「按这一局的舰队推：三条最小的船」，标准档得到的仍是 5/4/3（与 v1.10 一致）。
2. **客户端的棋盘几何写死 10**：`BOARD_SIZE` 在屏幕里有二十来处（坐标刻度、
   放大镜跨度、随机布阵、`canPlace` 边界）。现在统一走载荷里的 `board_size`。

### 8.5 视觉那一条：**做了一半，另一半有意不做**（第三梯队第 7 条）

| 这一轮做了 | 为什么 |
|---|---|
| **命中画叉 `X` / 未中画圈 `○`** | 调研 §四点名的那条：纸笔海战棋的通用记号，而且是**形状通道** —— 灰度、色盲、低视力下都还分得清「中没中」（WCAG 1.4.1）。原来命中是一个实心方块、未中是一个实心点，**只靠颜色区分**。已沉的格子仍然画实心块，于是「叉（打中一格）」与「整块（这艘沉了）」也是两个形状通道 |

| 这一轮**没做** | 为什么 |
|---|---|
| **方格纸 + 圆珠笔的整体皮肤**（纸底、格线、手绘舰船轮廓、露出木桌面） | 它是**一次整体配色重算**，而这正是调研自己标注的风险：「若采用纸质感，必须重算对比度 —— 纸张底色偏浅，浅色记号压上去会低于图形 3:1 阈值」。实测更直接：现有五个船色是**为深色海面挑的**（`#FBBF24` 这类压到纸底上只有 ~1.5:1），而圆珠笔那种深蓝（`#1F3A93`）压在现有海面上只有 **1.14:1** —— 两套底色**互不兼容**，换纸底等于把船色、记号色、文字色一起重挑并逐条实测。这是独立一轮的量，硬塞进本轮只会换来一次没验证过的可访问性回归 |

### 8.6 仍未做的一条（第三梯队第 6 条）：Salvo 齐射制

**Salvo 齐射制这一轮没有做**：它是**协议信息模型的重做**（一回合提交多发、
对手只回「中了几发」而不回是哪几格），要连客户端「盘面不再逐格标记」一起改，
与尺寸那条不是一回事。规则原文与来源在本文件 §2.3（Hasbro 官方 Salvo 变体），
下次开工不用重新搜。**尺寸这一条之所以先做，是因为它复用现成的「房间级设置」
骨架、不动协议的信息模型** —— 先把风险最低的一条落地，而不是两条一起半途而废。
