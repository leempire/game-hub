# 海战棋 设计文档

- 屏：`app/src/screens/BattleshipScreen.tsx`（~1400 行，按阶段拆函数：
  `useShipDrag` 拖放 / `BoardTabs` 分段 / `ShotEffect` 动效 / `PlacementView` /
  `BattleView` / `GridBoard` / `CellContent`）
- 引擎：`server/app/game/battleship.py`　AI：`server/app/game/battleship_ai.py`
- 人数 2｜支持人机｜战绩落库

## 玩法

两阶段：**布阵**（把 5 艘舰摆进 10×10 海域 + 挂靠三件特殊武器）→ **开战**（轮流开炮）。
炮弹格显示命中/未命中；一艘舰的所有格都被命中即击沉（位置公开）。
先把对方 5 艘全部击沉者胜。

### v1.10 玩法增强

设计依据见 [`增强调研.md`](./增强调研.md)（联网调研，含来源）。
**要解决的问题**：布阵之后玩家再没有任何决策——每回合机械等价，唯一变量是运气。
下面两条都是给「布阵之后」补决策点。

**命中续射**：命中或击沉后回合保留，可接着再打一发，直到打空为止。
- **先手方的第一发不触发**（`gs["first_shot_done"]` 只由真实开炮置位，用武器不置位）。
  先手天然多一个回合，续射会把先手优势进一步放大，这是补偿。
- 连打能一回合清掉整条船——这是这条规则最爽的地方，不做连锁上限。

**特殊武器**（各每局一次）：

| 武器 | 效果 | 目标 |
|---|---|---|
| 雷达 | 探测选定格周围 3×3 海域**有没有**敌舰（只报有无，不报位置） | 1 格中心 |
| 齐射 | 一次性对 3 个格子开炮，逐格结算 | 3 格 |
| 空袭 | 对选定格周围 3×3 海域范围打击，每格独立判定（跳过已开火格） | 1 格中心 |

- **挂靠舰船**：布阵时三件武器分别挂到**三条不同**的舰船上（同一艘会成为支配策略——
  把武器全堆在最难找的船上）。**携带舰被击沉则该武器失效**。这条是整个增强的核心：
  它把布阵与对战从两段拼接变成一条因果链——布阵要为武器舰留掩护，而不是随便摆完开打。
- **挂靠关系对对手公开**（`opp_weapons`）：这正是「找出并击沉武器舰」这条反制成立的前提，
  藏起来机制就废了。只暴露舰名（5 艘船的名字本来就公开），不暴露位置。
- **使用武器 = 本回合全部行动**，用完换手、**不触发续射**。语义取自 Hasbro
  「一回合要么报一个坐标、要么启动一次特殊武器」；否则一次空袭命中多格会立刻续射出多回合。
- 旧客户端不发 `weapons` 字段时，服务端用 `DEFAULT_WEAPON_ASSIGNMENT`（雷达→驱逐舰、
  齐射→潜艇、空袭→巡洋舰）兜底，保证向后兼容。

**AI 三档难度**（人机）：简单（纯随机 + 打相邻格）/ 普通（parity 搜索 + 线段延伸，
即 v1.10 之前的原策略）/ 困难（**概率热力图** + 候选按热力排序）。
难度存在每个 bot 自己身上（`p["ai_difficulty"]`），一个房间可混搭。
实测平均击穿发数：**简单 61.9 / 普通 56.0 / 困难 46.3**（200 局随机布阵）。

## 界面构成

**一次只显示一块 10×10 盘**，顶部两个分段 Tab 切换（v1.5.2 起，见「单棋盘」一节）。

```
┌─────────────────────────────┐
│ ● 蓝方  轮到你开炮   ?  #CODE │
├─────────────────────────────┤
│ 击沉: 2/5      己方被沉: 1/5  │  战况统计
├─────────────────────────────┤
│ [ 我的海域 ] [ 敌方海域 ]      │  分段切换（高 ≈47px）
├─────────────────────────────┤
│ 攻击面板                      │
│  10×10  ·  命中橙 / 击沉红 /  │
│           未命中白点          │
├─────────────────────────────┤
│        [认输]  [退出]        │
└─────────────────────────────┘
```

布阵阶段换成：舰船选择条 + 分段 Tab + 棋盘 + 旋转按钮 + 「重新布阵」+「完成布阵」。

### 单棋盘 + 分段切换（v1.5.2）

原来两块 10×10 盘上下叠放，390×844 上每格只有约 30px。改成一次只显示一块后，
棋盘可以横向铺满：`boardEdge = min(winWidth - 16, 460)`，390pt 竖屏下每格约 37px。

- **默认停在哪块盘按阶段定**：布阵阶段「我的海域」，开炮阶段「敌方海域」
  （`useEffect` 跟 `phase` 走；用户手动切 Tab 不会被打断，因为 phase 不变）。
- **布阵阶段也能切到「敌方海域」**，显示一块等尺寸占位面板（对方舰位开战前
  服务端不下发），文案「布阵完成后可见」——保持布局稳定，也提前教会这个控件。
- **被击提示**：对方打过来而玩家正看着敌方海域时，「我的海域」Tab 上出现
  `被击 N` 药丸（文字 + 形状，不靠颜色）。切回该 Tab 即清零。
- Tab 选中态用「填充底色 + 加粗 + 下划线」三个通道，不单靠颜色（WCAG 1.4.1）。

**取舍**：37px 仍低于 44pt 建议值。10 列在 390pt 宽的竖屏上，即便不留边距也只有
39px（44pt 需要 440pt 宽），再放大只能靠横向滚动或双指缩放（未做）。剩下的补偿
是**两块盘不再挤在一起**、被击有 Tab 提示、格子比原来（约 30px）大 23%。桌面端
窗口够宽时每格能到 46px（`boardEdge` 封顶 460），已超过 44pt。

## 交互设计

### 布阵：点选 + 落位（两条路径并存）

- **点选路径**（原路径，保留）：点舰船卡片选中 → 点棋盘格子落位；点已放置的
  舰船可**拾起**重摆。旋转按钮切换横/竖（`horizontal`）；「重新布阵」一键生成
  合法布局。
- **拖动路径**（v1.5.2 新增）：**长按**舰船 320ms 后直接拖到目标格松手。
  两个拖动入口共用一份拖动态：
  1. 棋盘上已放置的舰——棋盘容器本身是单一手势层（`PanResponder`）；
  2. 舰船卡片——长按卡片后可直接拖到棋盘上（卡片自带 `PanResponder`，
     用 `pageX/pageY` 减棋盘原点换算盘内坐标）。

  拖动**保持舰体当前朝向**（旋转仍走旋转按钮）；落点非法（越界 / 压到别的舰 /
  出盘）时松手**静默回原位**，不弹错误提示。拖动中棋盘上有舰体预览：
  合法=实线白边，非法=虚线琥珀边（形状做第二通道），下方一行提示文字
  （`松手放置` / `此处放不下，松手回原位`）——文字通道，不靠颜色。

- 非法落位（越界/重叠）直接不响应，不弹错误提示——移动端弹窗打断感太强。

> 早期判断「RN 拖拽在 10×10 密集格上精度差、与页面滚动冲突」而只做点选。
> v1.5.2 补上拖动后发现两个关键点：①手势层容器加 `pointerEvents="box-only"`
> 后原生端局部坐标才相对棋盘本体；②Web 端必须给手势元素加 `touch-action: none`，
> 否则浏览器会把拖动当成页面滚动、发 `touchcancel` 取消整条触摸序列。

### 开炮后的落点动效（v1.5.2）

- **命中**：扩散爆环 + 中心闪光（琥珀，击沉用红）；**未命中**：白色水面涟漪。
- 时长 **360ms**（方法论 §2：命中/击沉属「值得注意的事件」，300-400ms）。
- 只动 `transform`（scale）与 `opacity`，`useNativeDriver: Platform.OS !== 'web'`。
- **单次播放不循环**（`Animated.timing`，WCAG 2.2.2），播完由父组件把节点卸载，
  切 Tab 重挂载也不会重放。
- 动效只是加强：命中/未命中的**常驻形状标记**（橙方块 / 白点）仍由 `CellContent`
  渲染，不因动效消失而丢失信息。
- 自己打的炮动效画在攻击面板上，对方打过来的炮画在己方海域上（按
  `shot.shooter_color` 区分）。

### 开战：点格子开炮

- 只在 `phase === 'battle'` 且轮到自己时格子可点，其余时候 `disabled`。
- 已开过炮的格子不可重复点击（服务端也会拒绝）。
- 命中 15ms 震动、击沉额外提示。
- 开炮后播放落点动效（见上）。**「最后一炮」白点只标自己打出的那一炮**——
  服务端每炮都逐人下发（含 `shooter_color`），据此区分，否则对方的炮会被错标
  在我的攻击盘上。

### 分段与只读盘：点击绝不能没有反馈（勿回退）

**己方海域盘是只读盘**（对手未沉舰的位置服务端根本不下发），点它本来什么也不该
发生。但它踩过一个很典型的坑：**武器条挂在分段 Tab 上方，任何分段都能点**，于是
「停在己方海域 → 点武器芯片 → 在只读盘上点目标」会一点反应都没有；之后在这块盘上
点普通攻击同样没反应。用户实测报的原文是「**点雷达，点棋盘中的一个位置，然后就没
反应了，之后直接点棋盘也没法普通攻击**」——全程零反馈，只会以为游戏坏了。

三条规则（都在 `BattleshipScreen`，改分段/武器逻辑时一起看）：

1. **进入瞄准时自动切到「敌方海域」**（`startWeapon` 里 `setViewTab('attack')`）。
   三件武器的目标都在敌方海域上，在己方海域上进入瞄准必然是无效态。
2. **瞄准中切到「我的海域」→ 取消瞄准 + 一句解释**（`handleTabChange`）。留着瞄准
   的话提示条写着「点击要探测的海域中心」而点哪都没反应，比报错更让人以为坏了。
3. **点己方海域盘 → 给一句话**（`handleOwnBoardPress`）：瞄准中自动切回敌方海域并
   说明「武器目标要选在「敌方海域」」；非瞄准态说明「这是你的海域，只能查看」。
   这要求己方盘**不能传 `disabled`**——RNW 下 `disabled` 是 `pointer-events:none`，
   点击根本到不了 `onPress`（同 Connect Four「满列不禁用」那条教训）。

反馈走 `notify()`（应用内 toast，2.6s 自动消失），不走棋盘下方那条 `noticeBar`：
noticeBar 在 `ScrollView` 末尾、棋盘（10 行 ≈370px）之下，小屏上会被挤出视口——
与俄罗斯方块「出局提示挂在页面底部被裁掉」是同一类事故。

回归：`test/e2e_battleship_weapons.py` 第 7 步（己方海域点武器自动切回、瞄准中切段
取消瞄准、点只读盘给出解释）。

### 命中/未命中标识（重要）

攻击面板的三种状态必须清晰可辨：

| 状态 | 表现 |
|---|---|
| 未命中 | 白色圆点（`rgba(255,255,255,0.9)`，深蓝底上高对比） |
| 命中 | 橙色方块 |
| 击沉 | 红色方块 |
| 最后一炮 | 叠加白色脉冲点（命中与未命中都有） |

**踩过的坑**：`GridBoard` 的 `attack` 模式读的是 `attackBoard` 这个 prop
（`atkVal`），但调用处曾传 `attackBoard={null}`、把攻击盘塞进了 `board`，
导致 `atkVal` 恒为 0——开炮后面板永远空白，玩家以为点击没生效。现在调用处
同时传 `board` 与 `attackBoard={game.own_attack_board}`，并加了 E2E 断言
（`test/e2e_battleship_smoke.py` 第 9 步）防止回退。

## 状态与协议

- `placement`（本家布阵）→ 广播 `placement_ready`；双方就绪 → `battle_start`。
- `fire` → 服务端逐人下发 `shot`，**每人一份自己的 game sync**（盘面私有，
  对方未击沉的舰位不下发）。
- `sync` 时按 `own_board` / `own_attack_board` / `incoming_board` / `opp_ships`
  区分「我的舰」「我打出去的弹」「对方打我的弹」「已击沉的敌舰」。
- 人机：`_bot_do_placement` 用 `bs_random_placement` 布阵（带幂等守卫，
  热重启重复调度不会二次布阵）；开炮走 `battleship_ai`。

## 结算

`battleship_fire` 在 `all_ships_sunk` 时调 `_set_game_over(room, color, 'all_sunk')`。

## 拖动预览要挂在棋盘外面（v1.17）

布阵时从**舰船卡片**长按拖动，手指一开始还在盘上方 —— 而预览原来画在棋盘里，
被棋盘的 `overflow: hidden` 按盘边整条裁掉，那一段完全看不见预览（只有下方一行
提示文字）。

现在预览挂在棋盘**外面的零尺寸锚点**上（量棋盘与容器的两个窗口原点、求差即得
偏移），拖到盘外也完整可见。棋盘组件那个 `overlay` 口子随之删掉 —— 没有调用方了。

⚠️ 顺带核实并**删掉了一条假的待优化项**：「雷达标记会叠在一起」。雷达**每局只能
用一次**（`_weapon_guard` 查 `weapons_used`），`own_radar` 最多一条记录 ——
那个「保留最近 N 个」的机制是为一个不可能发生的场景写的死代码。

## 已知坑（勿回退）

- **逐人下发**：`shot` 不能全员同一份广播，否则对方会看到自己不该看到的盘面。
- 布阵幂等：`_bot_do_placement` 必须检查 `placement_ready[bot_id]`，
  否则热重启后的重复调度会让 bot 二次布阵、覆盖已定布局。
- **`bs-<mode>-x-y` 的 testID 不能改**：E2E 靠它断言开炮后的命中/未命中标记
  （`bs-attack-x-y-hit` / `-miss`）。布阵盘改成手势层后格子由
  `TouchableOpacity` 变成纯 `View`，但 testID 与位置不变。
- **棋盘手势层与攻击盘分开**：只有布阵盘挂了 `PanResponder`；攻击/己方盘仍是
  逐格 `TouchableOpacity`（`disabled` 控制轮次），改动时别把两者合并。
- **拖动坐标换算**：原生端手势层容器必须 `pointerEvents="box-only"`，否则
  100 个绝对定位格会把 `locationX/Y` 全部压进 `[0,cellSize)` → 恒解析成 (0,0)
  （与五子棋同一坑）。卡片拖动走 `pageX/pageY - 棋盘原点`，原点由
  `measureInWindow` 在棋盘挂载 / 切分段时量好存进 ref——**不要在拖动开始的那一帧
  现量**，异步回调赶不上，落点会算错。
- **`mine` 判定**：`shot` 消息里的 `shooter_color` 是区分「我打的」/「打我的」
  的唯一依据，两者分别决定动效与「最后一炮」标记画在哪块盘上。
- **`weapon_used` 必须先于 `radar_result` 发出**（v1.10 踩坑）：`_broadcast_battleship_action`
  里先广播 `weapon_used`、再给使用者单独发 `radar_result`。测试若用「读到 X 才返回」的
  辅助函数先等 `radar_result`，会把排在前面的 `weapon_used` 一并吃掉，然后再等
  `weapon_used` 就**永久阻塞**（`receive_json()` 没有超时）。E2E 同理，注意读取顺序。
- **`.nth(0)` 挑格子时不能用 testid 后缀过滤已开火的格**（v1.10 踩坑）：
  格子元素 `bs-attack-x-y` **恒在**，开过炮只是在它**里面**多一个 `-hit`/`-miss`
  子元素。所以 `:not([data-testid$="-hit"])` 只筛掉标记元素自己，一个已开火的格子
  也筛不掉 → 辅助函数永远返回第 0 格 → 在它上面反复点击（服务端正确地忽略重复开炮），
  表现为「点了没反应、回合永远不动」。必须叠加 `:not(:has([...$="-hit"]))`
  **同时**保留后缀过滤（标记元素自己也以 `bs-attack-` 开头）。见
  `test/e2e_battleship_weapons.py` 的 `unfired_cell()`。
- **`ai_difficulty` 的 `useState` 必须在 `RoomScreen` 的 `if (loading)` 提前返回之前**
  （v1.10 踩坑）：放到提前返回下面，首次渲染少调一个 hook，React 直接报
  「Rendered more hooks than during the previous render」并整页白屏。
- **布阵期「添加人机」按钮受 `!isFull` 限制**：海战棋是 2 人房，对手一进来房间就满了，
  难度选择随之隐藏。所以「加人机选难度」的实际用法是**单人开局**（房主 + 1 个人机）。
  E2E 也要在对手加入之前查这个选择器。
- **己方海域盘不能传 `disabled`，点击也不能静默**（见「分段与只读盘」一节）：RNW 下
  `disabled` 等于 `pointer-events:none`，点击到不了 `onPress`，武器条又挂在分段上方
  任何分段都能点，于是「点武器 → 点只读盘」全程零反馈（用户实测报过）。

## 待优化（未排期，路线图候选）

- 10 列棋盘在窄屏上仍是 37px/格，低于 44pt；再放大需要横向滚动或双指缩放
  （五子棋已有放大镜手势可参考）。
- **v1.10 调研里未采纳的方向**（详见 `battleship-增强调研.md`，都是有意不做的）：
  Salvo 齐射制（协议要改成一次提交多发、只回总数，与「一击一回包」差异过大）、
  机动舰队（船可移动，需重做「已锁定推理」的心智模型）、扩大网格 / 舰队配置可变、
  涂鸦方格纸视觉风（改用需整体重算对比度）。
