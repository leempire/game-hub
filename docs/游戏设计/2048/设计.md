# 2048 竞速 设计文档

- 屏：`app/src/screens/Game2048Screen.tsx`　引擎：`server/app/game/game2048.py`
- 人数 **1-4**（1 人可开，单人刷分）｜无 AI｜战绩落库

## 玩法

**每个人各玩各的盘，只有排行榜共享。** 不是轮流行动——你随时可以滑，
不用等别人。

- 每人一份独立 4×4 盘面 + 独立随机源，但**种子相同**，出块序列完全一致，
  所以比的是策略不是运气。
- 合成 2048 即本人完成；棋盘无法再移动即本人卡死。
- 认输 / 中途退出**只结束你自己**（排名垫底），其他人照常继续。
- 全员结束后按名次结算：先合成 2048 的排最前（按达成先后），其余按总分降序。

## 交互设计

### 双输入路径：滑动 + 方向键

- **滑动**：`PanResponder` 以整块棋盘为热区，位移超过 `max(20, 棋盘宽×0.08)`
  才判定方向（阈值随棋盘尺寸自适应，小屏上固定 30px 偏大、轻扫会被吞掉）。
- **踩过的三个坑**（都会表现成「滑动没反应」）：
  1. **陈旧闭包**：`PanResponder` 用 `useRef(...).current` 建一次，回调永远闭包在
     首帧的 `sendMove` 上，而首帧 `game === null` 被守卫拦掉 → 滑动完全无效。
     必须用 `useMemo(() => PanResponder.create(...), [])` + ref 读易变状态
     （与 `GomokuScreen` 一致）。
  2. **手势被浏览器抢走**：Web 端横滑可能被当成页面平移/横滑返回手势，touch 序列
     被 cancel，`onPanResponderRelease` 根本不触发。棋盘加 `touch-action: none`
     （仅 Web），并让 `onPanResponderTerminate` 与 release 走同一套判定兜底。
  3. **被浮层打断**：指针划过排行榜浮层会触发终止请求，`onPanResponderTerminationRequest`
     返回 `false` 拒绝移交；浮层本身也设 `pointerEvents="none"`（纯展示）。
- **方向键**：56×56 按钮，四向。为什么两套都要：
  - 滑动快，是主路径；
  - 但手机放桌上单手玩、或手指有伤/戴手套时滑动不灵，方向键是可靠兜底；
  - 也方便 E2E 稳定触发（`testID="dir-up"` 等）。

### 实时排行榜（右上角可收起浮层）

按 scorebug 惯例给多人对局统计留位置，但**不能占布局高度**——小屏上
「排行榜 + 棋盘 + 方向键 + 底栏」叠起来会超出屏幕。所以做成贴棋盘右上角的
半透明浮层，默认收起：

- 收起态是一枚小胶囊：`第N/总数 · 我的分数`，点一下展开。
- 展开态每行：`名次 · 颜色点 · 昵称（自己标「我」）· 结束标记 · 分数 · 最大块`，
  自己那行淡紫底色高亮；已结束的人显示「2048!」或「已结束」。
- 浮层**不参与布局**（绝对定位），展开时半透明盖在棋盘上，不挤压棋盘尺寸。
- 排序与最终结算一致（达成 2048 优先，其余按分数），所以排行榜本身就是结算预告。
- 浮层是纯展示：面板本体与名次行 `pointerEvents="none"`，否则滑动手势经过它上方会被中断。
- **浮层可拖动**（展开后会盖住棋盘一角，所以允许拖走）：
  - 两个拖动热区：**收起/展开的胶囊**（点一下展开/收起，拖动改位置）和**面板的标题行**
    （纯拖动，行首有 `move-outline` 手柄图标提示可拖）。
  - 拖动结束后**停在原地**，不弹回；偏移用 `Animated.ValueXY` + `setValue`，不触发重渲染。
  - 位置夹在棋盘范围内（`lbClamp`）：基准是 `top/right = spacing.sm`，所以
    `x ∈ [-(boardEdge - sm - 浮层宽), sm]`、`y ∈ [-sm, boardEdge - 浮层高 - sm]`；
    浮层尺寸变化（展开/收起）时在 `onLayout` 里重新夹一次。
  - **与滑棋盘不打架**：浮层容器与面板都是 `box-none`（自身不吃指针、子元素可吃），
    名次行包一层 `none`（指针穿透到棋盘），只有胶囊与标题行是触摸目标；两个热区都
    `onPanResponderTerminationRequest: () => false`（拖动中拒绝把手势交出去）。
    胶囊用「位移 < 6px 算点击」区分点按与拖动，所以 E2E 的 `.click()` 仍然只是展开/收起。
  - Web 端浮层另加 `touch-action: none`——`touch-action` 不继承，棋盘上那条管不到
    这个兄弟节点。

### 结算弹窗

按名次列出全部玩家（名次 / 颜色点 / 昵称 / 最大块 / 分数）。

顶部大字**只有两种情况**：合出了 2048 → 「合成 2048，胜利！」；否则一律「游戏结束」。
副标题给名次（`第 N / M 名`），别人先合出 2048 时补一句「XX 合成 2048」。

> **2048 不是胜负对抗，是跑分竞速。** 排名第一 ≠ 胜利——分高只说明这局走得远。
> 早期文案写成「你赢了！/ 第 N 名」，把名次第一当成赢，是错的。
> 服务端的 `gs["winner"]` 记的是「排名第一的颜色」，**不要拿它直接当胜负**；
> 真正的判据是 `max_tile >= 2048`（= `game2048.WIN_TILE`）。
> 战绩落库同理：`_build_results_record` 里 2048 单独一个分支，只有合出 2048
> 记 `win`，其余记 `end`（界面显示「结束」）。回归见
> `test_history.py::test_2048_rank1_without_2048_is_not_a_win`。

### 棋盘尺寸自适应

棋盘外层是 `flex:1` 的容器，用 `onLayout` 实测剩余空间后
`boardEdge = min(实测宽, 实测高, 400)`，格子
`cellSize = floor((boardEdge - 2*PAD - 3*GAP) / 4)`（`PAD=5, GAP=6`）。
构造上保证 `2*PAD + 4*cellSize + 3*GAP ≤ boardEdge`——早期版本只按宽度算且
没扣格子间隙，方块会溢出棋盘圆角背景。字号也随格宽缩放。

### 格子配色（改过一版，勿回退）

经典 2048 调色板是**近白字压在黄橙底上**：`#f9f6f2` on `#edcf72` 只有 **1.42:1**，
128 以上的数字基本看不清。现在改成**统一深墨字 `#4A4239` + 把深橙格调亮**，
全部格子 ≥3.6:1（格内数字是 24px 以上的粗体，按 WCAG 大字阈值 3:1 计）。

唯一来源是 `theme.g2048Tile(value)`（对局屏与战绩回放共用，之前各写了一份）。
改配色时注意方向：**深色字要配浅底**——把格底调暗会让对比度更低，不是更高。

### 走子动画

- 引擎 `move_with_trace()` 除了盘面还返回逐块轨迹
  `{from:[r,c], to:[r,c], value, merged}`（合并产出两条指向同一目标的记录）。
  `move()` 保持原签名，是它的薄包装。
- 客户端用**棋子身份模型** `tiles: {id, r, c, value}[]`，每块是绝对定位的
  `Animated.View`。
- **位置由持续存在的动画值决定**：`TileView` 持有 `ax/ay`（目标像素坐标），渲染层
  只挂 `transform: translate(ax, ay)`，方块自身 `left/top` 恒为 0。位置变了就
  `Animated.timing` 朝新目标补间（~110ms）。
- **可中断**：后一次走子到来时，新动画会停掉同一个 Value 上未完成的补间，并以
  **当前视觉位置**为起点继续（JS 驱动下是当前 `_value`；原生驱动下原生节点保留
  自己的当前值），所以快速连滑不会回跳到上一格——这正是「把上一次补间干净收尾，
  再开始新动画」，而且不需要去读中途值（原生驱动读不到）。
  > 早先的实现是 FLIP（`left/top` 落到目标格 + `translate` 从「源−目标」补间回 0）：
  > 每次都要 `setValue` 一个瞬时 offset，连滑时会把正在补间的块**拽回上一格**再重滑，
  > 视觉上跳一下。改成「动画值直接朝目标补间」后没有这个问题。
- 一次走子分两阶段：**滑行**（合并双方都还在，各自保持旧值）→ **提交**
  （合并生效并弹一下、被吃的块消失、新块弹入）。
- **对账**：先用轨迹推出期望盘面，与权威盘面（扣掉新块）比对，不一致就整体重建、
  不播动画——宁可跳一下，不能显示错盘。（重建走 `tilesFromBoard`，方块 id 全新，
  天然不播动画。）
- **必须按 `(r,c)` 排序渲染**：方块位置由 transform 决定、与 DOM 顺序解耦，所以
  顺序只能由 `orderedTiles` 的排序保证——DOM 文本顺序必须恒等于权威盘面，
  `e2e_2048_smoke.py` 依赖 `g2048-board` 的 `inner_text()` 读盘。
- 棋盘尺寸变化（转屏/窗口缩放）时 `step` 变，方块**直接落位**不播滑行（避免把
  resize 播成一段动画）。

### 撤销与个人最佳（v1.18.1）

- **撤销只在单人局开放**，服务端硬性拒绝多人局（`len(gs["boards"]) != 1`）。
  多人局是「同种子竞速」，撤销会让两个人的局面不再可比，也会多出一个作弊面。
- 撤销栈在 `gs["undo_stacks"][pid]`，每步存 `{board, score, move_count}`，
  上限 `G2048_MAX_UNDO = 20`（只回退 20 步，够救手滑）。**只回滚盘面/分数/步数，
  不回滚 RNG**：撤销后重新走子会拿到不同的新块——单人局没有跨玩家公平性问题，
  这样也省下每步 625 个随机数的落盘。
- 客户端入口在底部「撤销」（`testID=g2048-undo`，仅 `player_count === 1` 时渲染）
  与 Web `Ctrl/⌘+Z`。**没有可撤销的步数时按钮不置灰**——点一下弹一句
  「还没有可以撤销的步数」（禁用态在 RNW 下等于点了没反应）。
- 撤销回包 `undo2048` 直接重建棋子（不播滑行动画）：整盘回退不是「走一步」。
- **个人最佳分**从战绩聚合：2048 的 `results_json` 从 v1.18.1 起带 `score`，
  `GET /api/history/stats` 的 `best_scores.2048` 取历史最大值。对局屏顶栏显示
  「最佳 N」，结算弹窗显示「新纪录！个人最佳 X」或「个人最佳 X」。
  **老记录没有 `score` 键，直接跳过**，最佳分从新记录开始累积。

## 状态与协议

- `game_start` / `sync` 逐人下发，**只带自己的盘面**，其余玩家只有
  `leaderboard` 条目（`user_id` / `color` / `score` / `max_tile` / `finished`）。
- `move2048` 广播也按人裁剪：`board` 与 `spawned` 只发给走子者本人，
  其余人只收 `leaderboard`。**盘面是私有的，不要改成全员广播。**
- 服务端对走子**没有任何回合校验**，只校验：房间在 playing → 你是本局玩家 →
  你自己还没结束 → 整局还没结束。改这段时不要引入 `next` / `current_seat`。
- 无 AI（`add_bot` 拒绝 2048）。

## 结算

- 单人结束：`_finish_2048_player` 标记 `game_over_flags[pid]` + 记录
  `finish_reasons` 与 `finish_order`。
- 全员结束：`_maybe_finish_2048` → `_compute_2048_ranking` → `_set_game_over`。
- 排名键：`(是否 reach_2048, 达成先后, -分数)`。
- **`ranking` 必须写回 `gs` 之后再调 `_set_game_over`**：后者内部触发战绩落库，
  而快照读的正是 `gs["ranking"]`，顺序反了会让存下来的快照排名永远是空的
  （回归：`test_history.py::test_finalize_2048_writes_ranking_before_persisting`）。
- 快照额外带 `players`（uid → username / nickname / is_bot / color）：
  战绩页要显示用户名。2048 的颜色是按座位顺序发的，1-4 人都可能拿到任意一色，
  **拿颜色当「红方/蓝方」既不对也无从分辨**。

## 已知坑（勿回退）

- **不要引入回合制**：本模式的核心就是「各玩各的」，任何 `next` 校验都会
  破坏设计。
- **盘面私有**：走子广播必须按人裁剪，否则等于把别人的盘泄露出去。
- 热重启：`rng` 状态随房间落盘（`persistence` 的 `__rng__` 编码），恢复后
  出块序列延续，不会重放。

## 待优化（未排期）

- 浮层拖动位置不持久化（切页/重开回到右上角）。目前是刻意如此：浮层的默认位置
  就是「最不挡棋盘」的那个角。
