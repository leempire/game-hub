# 五子棋 设计文档

- 屏：`app/src/screens/GomokuScreen.tsx`　引擎：`server/app/game/gomoku.py`　AI：`server/app/game/gomoku_ai.py`
- 人数 2（须满员开局）｜支持人机｜战绩落库 `game_records`

## 玩法

15×15 交叉点，黑先。横/竖/斜连成五子即胜，棋盘下满为和棋。
认输、断线超时 120s 判负。

## 交互设计

### 落子：单一手势层 + 长按放大镜 + 双指缩放

整块棋盘是一个 `PanResponder`，**没有**给 225 个交叉点各挂一个 Touchable
（那样在原生端会出现「点击任意位置都落到 (0,0)」，见下）。手势语义：

| 手势 | 行为 |
|---|---|
| 轻点（<300ms 且几乎不移动） | 在该交叉点放下**半透明预览子**（第一次）；再点同一处才真正落子 |
| 长按（≥300ms，1×） | 弹出放大镜，手指拖动微调落点，抬起后落点变成待确认的预览子 |
| 双指捏合 | 缩放棋盘（1× ~ 2.5×），围绕两指中点缩放 |
| 放大态下单指拖动 | 平移查看（拖动过 `PAN_SLOP=4px` 才算，所以轻点仍能落子） |
| 拖动中移出棋盘 | 落点保持在最后一次有效交叉点 |

### 落子二次确认（第一次点击只放预览子）

**为什么加**：五子棋格宽只有约 25px（远低于 44pt），一次误触就直接落子且无法
撤销，而五子棋一步失误往往就输了。二次确认让「点在哪儿」先变得可见，第二下才是
承诺——这是对小棋盘触控目标不足最直接的一层补偿，和放大镜、双指缩放互补。

行为细则：

- 第一次点空交叉点 → 该处出现**半透明预览子**（`opacity: 0.4`），棋盘下方出现
  提示条「再点一次同一位置确认落子（点别处可改位置）」（`testID="gomoku-pending-hint"`）。
  预览子本身不解释接下来要干嘛，这句文案是必需的（状态/手势不可见是移动端最常见的坑）。
- 再点**同一位置** → 真的落子。
- 点**另一个空位** → 预览子跟着移过去。
- 点**已有棋子** → 撤掉预览（当作「算了」）。
- 回合交接 / 任何一方落子 / 终局 → 预览自动清除（否则上一手的预览子会留在盘上，
  看起来像多了一颗棋）。
- 长按放大镜松手后，落点直接进入「待确认」状态，不必再点一次。

三条输入路径（轻点 / 长按放大镜后拖动 / 放大态轻点）都汇聚到 `handleCellPress`，
所以拦截只需要一处；改手势层时**不要**绕过这个函数直接调 `socket.move`。

**为什么需要放大镜**：390px 宽屏上 15×15 每格仅约 25px，远低于 44pt 建议值，
纯点击必然误触。放大镜把「手指遮挡下的粗定位」转成「放大后的精定位」，这是
在物理尺寸受限时唯一可行的解法，不要因为「点不准就加大棋盘」而回退它。

**为什么还要缩放**：放大镜是「临时放大 + 立刻落子」，缩放是「持续放大 + 反复落子
+ 看全局」——2.5× 时格宽约 62px，已越过 44pt 建议值，可以像大棋盘一样直接点。
两者互补，不要用一个替掉另一个。

### 双指缩放（实现说明）

- **手势分流**：单指与双指都在 `onStartShouldSetPanResponder` 就接管（单指的轻点
  必须拿到 grant 才能落子），真正区分放在 `onPanResponderStart` / `Grant` / `Move`
  里按 `evt.nativeEvent.touches.length` 判断——第二个手指落下时不会重走
  should-set 协商，只能从事件里拿触摸点数量。双指一出现就 `clearDrag()`（撤销
  待弹出的放大镜与预览），release 时也不会落子。
- **渲染层与坐标系分离**（**关键**）：视口（手势层）尺寸固定、不参与 transform；
  棋盘内容包在 `Animated.View` 里，变换是
  `[{translateX: off.x}, {translateY: off.y}, {scale: zoom}]`，且
  `transformOrigin: 'top left'`。于是

  ```
  视觉位置 v = off + zoom * p      ⇒     棋盘坐标 p = (v - off) / zoom
  ```

  `locationX/locationY` 恒为**视口坐标**，落子/预览/放大镜一律先换算成 `p` 再算交叉点。
  这样「缩放后点哪下哪」不会错位——历史事故是原生端 `locationX` 相对被触摸的子 View，
  225 个 cell 让每次触摸都解析成 (0,0)。
- **约束**：`zoom ∈ [1, 2.5]`；平移夹在 `off ∈ [boardPixelSize*(1-zoom), 0]`，保证
  内容始终盖满视口（不会露出棋盘外的空白）。
- **换算方式是绝对式不是增量式**：捏合起点记下 `(zoom0, off0, 中点0, 距离0)`，
  每帧由起点重算，避免夹取造成的漂移；中点移动自然带来双指平移。
- **复位**：放大态右下角浮出「复位 1×」按钮（`testID="gomoku-zoom-reset"`），
  点击动画回到 1×/零偏移。缩进去必须出得来，所以不采用「双击复位」——双击会和
  落子冲突（会连下两子）。
- **放大态下放大镜也能用（v1.17）**：原来它渲染在棋盘**内容层**里，会跟着
  `scale`/`translate` 一起被放大平移，飘到棋盘外面去，所以放大态下干脆禁用了长按。
  现在它画在**视口层**（`boardWrap` 之内、内容层之外），位置用视口坐标，
  放大倍率改成 `max(2, 当前 zoom)` —— 放大态下它的价值不再是「再放大」，
  而是**把手指压住的那块画面挪出来**，所以与屏幕持平最合适。
  手势分派也跟着改：放大态下**手指先动 = 平移**、**先按住不动 = 弹放大镜精瞄**
  （定时器先到就把 `panStartRef` 置空，这次手势整个让给精瞄）。1× 的行为完全不变。

### 触控实现要点（改手势层前必读）

- 棋盘**视口**必须带 `pointerEvents="box-only"`。原生端 `locationX/locationY`
  是相对**被触摸的子 View** 的，棋盘里 225 个绝对定位 cell 会让每次触摸的局部
  坐标都落在 `[0, cellSize)` → 恒定解析成 (0,0)。设成 box-only 后子 View 不再
  是触摸目标，坐标才相对棋盘本体。Web 端 RNW 本就用 `currentTarget` 计算
  `locationX`，且 `box-only` 会被 RNW 编译成「自身 auto + 直接子元素 none」，行为一致。
- 视口要 `overflow: hidden`：缩放后的内容不能溢到顶栏/按钮上。
- Web 端视口要 `touch-action: none`（仅 Web），否则捏合会被浏览器当成页面缩放抢走。
- 225 个 `tabIndex={0}` 的 cell 是**纯测试用**的可发现性锚点（无手势处理），
  E2E 靠它们定位棋盘；棋子另有 `testID="stone-x-y"` 供计数断言。
- 手势回调里读状态一律走 `ref`（`gameRef` / `isMyTurnRef` / `cellSizeRef` /
  `zoomRef` / `offRef`），PanResponder 在 `useMemo` 里只创建一次，闭包会过期。

### 落点提示：能连五 / 必须堵（v1.17）

轮到自己时，棋盘上会标出两类空点：

- **实心点** = 我落这里立刻连五（这一手直接赢）；
- **空心环** = 对手落这里就连五（不堵就输）。

判据是**纯局部**的（假设落一子、扫四个方向数连子），与「活三」那种要评估后续
形状的不同，所以本地算不会与服务端漂移 —— 同重力四子棋的提示标：**提示可以本地
算，「谁赢了」永远由服务端裁决**。同一个点两边都能连五时按「自己赢优先」只标赢点。

**两个标记都靠深墨描边成形**：木色棋盘 `#DEB887` 上，绿只有 1.78、琥珀只有 0.87，
自己都到不了 3:1（白子 1.70、飞行棋黄子 1.35 是同一条教训）。形状是第二通道
（实心 / 空心），棋盘下方另有一行图例说明。

### 反馈

- 落子：10ms 震动（原生）+ 弹入动画（仅最新一子播放，避免全盘重放）。
- 轮到自己：回合提示文字脉冲闪烁 + 30ms 震动。
- 胜利：五连金环脉冲（`winPulse` 透明度循环）。
- 预览：拖动/悬停时显示半透明预落子。

## 状态与协议

- `game_start` / `sync` 逐人下发（各自带 `your_color`），不能全员同一份广播。
- 走子：`{type:'move', x, y}` → 广播 `{type:'move', x, y, color, next}`。
- 人机：房主在等待大厅「添加人机」，轮到 bot 时延迟 0.8-1.2s 走
  `gomoku_ai.best_move`，走正常广播路径。

## 结算

`make_move` 判定五连/和棋时立即调 `_set_game_over` 把房间转 `finished`
（**不是**在 ws 层补，见「已知坑」）。结算弹窗只有「返回房间」——续开新局
统一回房间大厅由房主点开始。

## 最近一步标记

最后一手棋子上压一枚**黄点 + 深墨描边**（`testID="gomoku-last-mark"`，尺寸随格宽
`cellSize * 0.26`）。四个棋类（五子棋 / 翻转棋 / 点格棋 / 中国象棋）共用同一套
视觉语言，色值取 `theme.ts` 的 `lastMoveMark` / `lastMoveMarkEdge`。

原来的实现是一个 6px 纯色小点（黑子上白点、白子上 `#333`），既小又和「五连金环」
之类的装饰混在一起，用户看不出哪一手是刚下的。黄点单独用在这几个游戏的所有
背景上都不达标（vs 白子 1.29:1、vs 木色棋盘 ~1.9:1），描边是让它在任何底色上
成形的那条通道。

## 配色

- 棋盘木色 `#DEB887`；棋盘线与白子描边同为 `theme.boardLine` / `stoneEdge`（`#6B4F0C`，
  vs 木色 4.12:1）。**白子填充 `#f5f5f5` 对木色只有 1.70:1**，它的可见性完全靠描边——
  原描边 `#ccc` 只有 1.16:1，等于没有，务必别改回去。
- **胜利五连的环是深红 `#C62828`，不是金色。** 金色 `#FFD700` 在木色棋盘上 1.32:1、
  在白子上 1.29:1——白棋赢的那一局等于没高亮。深红在三种背景（木色 3.03 / 黑子 3.10
  / 白子 5.16）上都过 3:1。
- **脉冲限次**：回合脉冲 3 轮、胜利脉冲 2 轮后停在常亮态，不做无限循环（WCAG 2.2.2）。
- 最后一手标记永远落在**反色**的石头上（黑子→白点 17.4:1、白子→深灰点 11.6:1），
  所以它不受「浅色子对比度低」影响——这条曾经被误记为待优化项，已核实并删除。

## 已知坑（勿回退）

1. **终局必须落 `finished`**：早期 `dots_make_move` 漏调 `_set_game_over`，
   房间停在 `playing`，玩家点「返回房间」后房间页 sync 到 `status=playing`
   立刻又把人弹回对局页。五子棋本身没踩到，但同批代码共用一个模式，
   新增终局路径时务必确认。
2. **原生端白屏**：对局屏里裸写 `window.addEventListener` 会在原生端挂载即
   TypeError（`window === global` 且无此 API）。Web 专属逻辑必须走
   `onConfirmLeave`。
3. **落盘时机**：`make_move` 的写盘收口在 `_finish_action`，必须等
   `gs["next"]` 切换**之后**才落盘，否则热重启后同一人连走两步。
