# 终极井字棋：设计与实现

日期：2026-11-03。状态：用户已确认草图与本文；已实现并通过下述验收。

## 已确认的需求

- 新增 GameHub 游戏「终极井字棋」，使用调研中的封盘版规则。
- 同时支持双人联机，以及简单、普通、困难三档人机。
- 手机保留完整棋盘概览，在放大的当前小棋盘中选格；先预览，再确认落子。
- 正常思考不限时；联网断线沿用 120 秒保座，超时判负，剩余秒数由服务端下发。
- 沿用现有房间、准备、房主开始、换座、重连、结算返回房间、战绩和帮助通路。
- 在现有 `dev/wqqxxx` 分支开发和提交；覆盖 Android 兼容路径、手机网页和桌面网页。

## 规则

1. 大盘为 3×3，九块小盘各为 3×3，共 81 格。双方用 X、O，X 先手。
2. 首手可在任意小盘的任意空格落子；之后落点在小盘中的相对位置，指定对手下一小盘。
3. 某小盘先出现同方横、竖、斜三连，即归该方并关闭；剩余空格不可再下。
4. 小盘填满无三连即为和棋盘，关闭且不归任何一方。
5. 被指定的小盘已关闭时，可在任意尚未结束的小盘选择空格。
6. 赢下的小盘在大盘横、竖、斜三连即获胜；不能用和棋小盘连线。
7. 全部小盘结束且无人形成大盘三连，整局和棋；首版不提前按「已无潜在三连」结束。
8. 落子后先结算小盘与整局，再确定下一小盘。若本手关闭了自身且把对手指回自身，则下一手自由选盘；若已终局，不能再落子。
9. 先手沿用棋类座位约定：座位 0 为 X，座位 1 为 O。大厅换座可交换先手，不另加自动轮换规则。

规则来源与已排除的变体见 [增强调研.md](增强调研.md)。

## 方案与范围

采用现有服务端权威引擎、房间 WS 和 Expo/RN 页面实现，使用现有依赖。游戏内规则、合法落点及下一手目的地由服务端提供。

小屏输入已选「全盘概览＋放大小盘＋确认」：仅全盘点选的格子偏小；全盘缩放需要额外手势，概览与精确输入分开更直接。草图用于验证操作，不会直接作为正式组件交付。

首版提供标准双人房间、人机、玩法帮助、断线续局、认输/退出确认、战绩最终盘面。悔棋、棋钟、其他房规、独立离线入口和逐手回放不在本次范围。

## 界面与操作

- 顶部：X/O 身份、当前回合、房号、规则帮助。符号与文字同时承载身份，不只靠颜色。
- 全盘概览：九个小盘保留棋子；已赢盘叠加大 X/O，和棋盘标「和」。概览用于选盘或查看，点击不会直接落子。
- 指定小盘回合自动选中该盘；自由选盘时可点任何未结束小盘。查看其他盘不改变本回合合法区域，只读状态有文字反馈。
- 放大小盘：九格有效触控区均至少 44px；选空格出现半透明预览，换选或取消不改服务端状态。
- 预览区：显示「下一步对手：右上小盘 / 任意未结束的小盘」；本手终局时显示相应结果，不误报还有下一回合。
- 固定可见的「确认落子」提交当前预览，提交中避免重复发送；网络断开时清空待确认预览，明确提示正在重连。
- 服务端新状态到达后重新校验/清空过期预览，不能确认旧版本落点。非本人回合、封盘、占用格均有明确状态或反馈。
- 认输和离开使用应用内确认弹窗，接统一返回保护；结算仅「返回房间」，续局在大厅准备后开始。
- 布局按可用高度收紧概览，必要时允许内容滚动；确认与危险操作可达，不能被固定棋盘高度挤出视口。验证 320×640、390×844 与桌面布局。
- 颜色复用/新增于 `theme.ts`；主要按钮沿用项目触控尺寸和对比度要求，动效有限次，仅使用平台兼容路径。

## 三档人机

复用加/移人机、负 id 座位、自动准备和回合调度。将当前仅海战棋的难度选择接线扩展到本游戏，难度存于该 bot 的 `ai_difficulty`。

实现方案：简单以随机合法落子为主；普通检查即时胜负和对手下一手威胁并做浅层搜索；困难在相同规则引擎上用有界迭代加深/alpha-beta 搜索，同时评估小盘归属、大盘威胁与下一手指派。普通搜索预算约 0.15 秒，困难约 0.5 秒，作为实现初值，按实测调整；困难不宣称无敌。

搜索放线程池，输入为公开盘面的副本，不阻塞 WS 事件循环。返回前核对房间、原对局对象、回合和版本；认输、离开或续开后的陈旧搜索结果直接丢弃。思考时沿用「人机思考中」反馈。

## 服务端与客户端边界

内部游戏键 `uttt`；路由 `UltimateTicTacToe`，深链 `/uttt/:code`。这些为实现命名，不影响用户看到的中文游戏名。

- 纯引擎：九个小盘、各盘归属/和棋状态、当前指定盘、走子记录和终局状态；不认识墙钟、WS 或数据库。
- 房间层：分配座位颜色、开局、落子、认输、退出、断线判负、终局回大厅和最终落盘，复用现有统一收尾。
- 同步视图：包含九盘、各盘状态、`active_board`（自由选盘为 null）、当前方/本人方、合法落点和预览目的地、最后一步、终局结果、单调版本号。所有信息公开，按本人身份下发视图。
- 客户端动作只提交小盘号、格号和当前版本。服务端拒绝非整数/布尔值、越界、错误回合、错误指定盘、封盘、占用格与陈旧版本，返回中文错误及必要的最新状态。
- 使用本游戏动作/状态消息接现有 WS 分发，开局与重连继续使用 `game_start` / `sync`。具体字段在实现计划及 `docs/接口协议.md` 中统一，不另写一套客户端裁决。
- 成功动作完成全部状态变更后统一落盘；热重启恢复棋局，客户端重连回当前状态。Bot 任务沿用恢复调度约定。

## 验收

- 引擎：首手自由、九种指派、封盘/和棋、指向已结束盘自由选盘、赢盘同手指回自身、大小盘横竖斜三连、全部结束和棋、非法动作无副作用。
- WS：双人准备开局、双端一致、错误回合/盘/版本被拒、重复确认只生效一次、重连与热恢复、正常思考不自动结束、120 秒断线判负、认输/返回/续开及战绩。
- AI：三档始终返回合法动作、不改输入、终局不走、较强档即时胜负/威胁测试；固定种子对局记录棋力与搜索耗时，验证搜索中房间变化不会落入新局。
- UI：概览选盘、放大选格/取消/确认、预览指派与自由选盘、封盘与终局可辨认、离线/对手回合防错、三个视口尺寸、触控区与返回保护。
- 按仓库要求跑全量后端 pytest、TypeScript、相关 E2E 与视觉/静态审计；运行 lint，区分已有问题与新增问题。Android API 路径做组件检查，真机/APK 发布由维护者完成。

## 实现与验收记录

- 版本在房间内跨局单调递增，上一局迟到的确认不能落入新局；搜索返回还检查原对局对象与当前回合。
- 对局中直接离开先保存双方战绩，再移出玩家，复用 WS 结算通知。异步大厅广播在执行时读取最新成员，避免退出者回流。离开返回首页，结算返回房间保留席位。
- 人机难度保存在已有玩家 JSON 中；历史列表显示难度，最终盘面复用对局概览组件，无数据库迁移。
