# 蜘蛛纸牌调研（2026-10-22）

首版（2026-10-22）为经典单人单花色随机牌局；2026-10-23 按用户要求调整为房间合作接龙，最新取舍见末节。

## 来源与交叉核验

| 维度 | 来源 | 结论 |
|---|---|---|
| 规则（英文，一手） | [MobilityWare 帮助](https://mobilityware.helpshift.com/hc/en/11-spider/faq/586-how-do-i-play-spider-solitaire/) | 104 张牌，10 列，初始 54 张、余牌 50 张；完整 K 到 A 收走；随机牌局不保证可解 |
| 规则（中文，一手） | [JoyPip 蜘蛛纸牌](https://joypip.com/zh-cn/game/spider/) | 连续递减牌组可搬移，空列可接任意牌组；每次给十列各发一张，有空列不能发牌 |
| 视觉（英文，一手） | [Brainium](https://brainium.com/games/spider/) | 易读牌面、克制动效；用牌桌与白牌形成明显层次 |
| 交互（英文，一手） | [MobilityWare](https://www.mobilityware.com/spidersolitaire/) | 手机点选移动、横竖屏、撤销和提示是成熟做法 |
| 交互（中文，一手） | [JoyPip 操作说明](https://joypip.com/zh-cn/game/spider/) | 先选牌组，再选目标列；再次点选取消；提示只代表合法移动，不保证通关 |
| 难度（一手） | [微软纸牌合集](https://www.microsoftcasualgames.com/solitaire) | 常见 1/2/4 花色；按用户范围只实现单花色 |
| 实现 | [Expo SDK 57](https://docs.expo.dev/versions/v57.0.0/)、[React Native ScrollView](https://reactnative.dev/docs/scrollview)、[Pressable](https://reactnative.dev/docs/pressable) | 沿用现有 RN 组件与导航，不引入新依赖 |

## 采纳与边界

- 采用经典单花色规则、自动翻牌和收齐、合法移动提示、撤销、随机新牌局。
- 点选牌组后再点目标列；目标带文字标记。牌宽至少 48，明牌露出至少 44；窄屏横向滚动，长列纵向滚动，避免把 10 列强行缩小。
- 服务端是唯一规则来源，客户端只显示服务端给出的合法移动，不复制规则。
- 使用现有房间落盘保存个人牌局，每账号一局，单人牌局不公开、不接受加入、不因离线判负或被 30 分钟清理。
- 每次成功操作落盘；最多保留最近 200 步撤销，避免长期往返移动造成存档无限增长。
- 首版不采纳：多花色、多人竞速、固定关卡、必胜牌局求解器、拖放、计时排名、装扮和货币。可解性策略于 2026-10-23 按用户反馈调整，见下文。

## 实现顺序

1. 纯规则引擎与边界测试：发牌、移动、翻牌、收齐、胜利、撤销和隐藏信息。
2. 接入私有单人房间、WS、存档、重开及历史快照；验证断线/重启续玩与账号隔离。
3. 接入目录、图标、帮助、导航和返回保护；实现手机可滚动牌桌。
4. 后端全量测试、TypeScript、lint、真实浏览器 E2E 与视觉审计，更新说明文档。

## 新局可解性优化（2026-10-23）

用户反馈完全随机洗牌导致卡局过多。对照中文、英文一手来源后，改为服务端筛选有完整解的新局。

| 来源 | 核验与取舍 |
|---|---|
| [MobilityWare 官方规则](https://mobilityware.helpshift.com/hc/en/11-spider/faq/586-how-do-i-play-spider-solitaire/)及[随机与可解牌局说明](https://mobilityware.helpshift.com/hc/en/11-spider/faq/588-what-s-the-difference-between-random-shuffle-and-winning-deal-1490399133/?p=web)（英文，一手） | 区分随机洗牌与至少有一个解的 Winning Deal；可解性需要完整解的依据，单看开局有合法移动不够。采用有解牌局的方向，保留经典空列发牌限制。 |
| [JoyPip 官方规则](https://joypip.com/zh-cn/game/spider/)（中文，一手） | 随机牌不保证可解，提示仅指合法移动；核对十列、五轮余牌与空列规则。保留规则与提示边界，调整新局生成方式。 |
| [Blake 与 Gent，The Winnability of Klondike Solitaire and Many Other Patience Games](https://arxiv.org/abs/1906.12314)（研究原文） | 深度优先搜索、重复状态表与剪枝是纸牌验证的可行手段。采用有界搜索与状态去重；不引入通用求解框架、不宣称有限搜索能证明无解。 |

- 采纳：每副随机牌实际搜索到八组收齐才接纳；尝试次数与搜索状态数均有界，失败后用已验证牌局的等高列和对应余牌置换兜底。
- 不采纳：仅增加开局可移动牌数、只筛前几步、运行中改暗牌或余牌、为发牌放宽规则、无上限搜索、扩展难度选项。它们不能直接证明整局可解，或会改规则、阻塞请求。
- 不新增自动代打与解法提示；生成时的解只在服务端内存短暂存在。旧存档原样续玩，新策略从新开牌局生效。

## 房间合作模式（2026-10-23）

- 用户确定规模：1 人 1 倍，2 人 1.5 倍，3–4 人 2 倍；所有人操作同一牌桌。沿用本仓库扫雷的建房、准备、开始、共享盘面与重连机制，合作结算采用全队完成目标。
- [Solitaire.now 官方多人说明](https://solitaire.now/faq/how-does-multiplayer-solitaire-work)（英文一手）采用房间、准备和服务端同步开局，但玩法为各自独立牌桌竞速。本次采纳房间流程，不采纳竞速；合作和人数扩容是用户明确指定的本项目规则，不冒称经典规则。
- [JoyPip 官方规则](https://joypip.com/zh-cn/game/spider/)（中文一手）与 [MobilityWare 官方规则](https://mobilityware.helpshift.com/hc/en/11-spider/faq/586-how-do-i-play-spider-solitaire/)（英文一手）交叉核对递减移动、完整 K 到 A、空列补牌限制。保留这些规则，将 104/10/8 按比例扩为 156/15/12 或 208/20/16，仍保留五轮余牌。
- [Expo SDK 57](https://docs.expo.dev/versions/v57.0.0/)及 [React Native ScrollView](https://reactnative.dev/docs/scrollview)支持沿用现有组件和受约束的滚动区域；保留固定牌宽，扩大横向牌桌，不缩小手机触控尺寸。
- 采纳共享版本校验：同时操作同一版牌面只接纳一次，拒绝者收到最新视图并重新选择；无关队友操作保留选牌。全局撤销须确认，明确会回退队友的最近一步。
- 取消首页直达、私有房间、每账号唯一牌局、局内直接重开、永不清理的个人存档特例。保留旧盘面并转为普通房间；未新增多花色、AI、语音聊天、个人积分或复杂的牌组占用锁。
