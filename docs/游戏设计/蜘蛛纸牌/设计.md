# 蜘蛛纸牌：单人单花色

范围以用户确认的经典单人牌局为准：随机开局、撤销、重开与续玩。依据见 [增强调研](增强调研.md)。

## 规则

- 104 张黑桃牌，每个点数八张。前四列各六张，后六列各五张；每列只翻开最上面一张。
- 点选一张明牌及其下方连续递减的牌组，接到点数恰好多一点的明牌上；空列接受任意可移动牌组。
- 露出的暗牌自动翻开；K 到 A 的完整明牌顺序自动收走；收齐八组获胜。
- 剩余 50 张分五轮，每轮十列各发一张；存在空列时不准发牌。
- 撤销恢复整个操作前的牌面、翻面、余牌、收齐数及步数；最多保留最近 200 步。胜利后结算，不再撤销。
- 不自动宣判“无解”；玩家可以撤销或新开一局。随机牌局不保证可解。

## 接入与存档

- 游戏键 `spider`，目录分类“单人休闲”。点击“开始 / 继续牌局”直接进入，不展示建房或等人流程。
- 使用现有服务端房间、WS 和 SQLite 存档，每账号最多一份牌局；不在公开房间列表出现，不接受其他玩家加入。
- 离线不判负；个人牌局不参与多人房间的闲置清理；启动恢复后也不移走离线玩家。
- 每次合法操作经 `room_manager` 完成全部状态变更后落盘，再确认给客户端。退出等待当前操作确认。
- 新牌局须确认；未完成的旧局记为“结束”，完成局记为“胜”。终局经 `_set_game_over` 回到 waiting，并存历史快照。
- WS `revision` 在操作、撤销和重开后递增；重复或过期操作拒绝并下发当前视图。

## 手机交互与视觉

- 牌宽 54px；明牌至少露出 44px，暗牌压缩。10 列放入横向滚动区，长列纵向滚动。
- 点选 → 带“可放”文字的目标列；再次点同一首牌取消。提供“提示”，不自动代打。
- 深绿牌桌、白牌、手写 SVG 黑桃；颜色来自 theme.ts，牌桌与白字实测对比度 12.18:1。
- 发牌、撤销、提示、新牌局、保存返回始终在牌桌外；错误在提示行说明，不静默。
- 新牌局与返回确认复用 `useModalBackGuard`；对局路由加入 `PROTECTED_SCREENS`，Web 与原生返回均接入。
- 历史快照复用 `SpiderBoard` 只读展示，暗牌仍不可见。

## 协议

- 建局/续玩：`POST /api/rooms {"game":"spider"}` 返回本人的唯一牌局。其他账号 GET / leave 返回 403，join 返回冲突，WS 拒绝非成员。
- 初次 WS 收 `sync {room,game:null}` 后发 `start`，服务端回 `game_start {game:视图}`；续玩 `sync.game` 为当前视图。
- 操作：`spider_action {action:"move"|"deal"|"undo"|"new", revision:int, source?:int, index?:int, target?:int}`，列与牌索引从零开始。
- 成功回 `spider_state {game:视图}`；失败回 `error {message}`，并在有本人牌局时回 `spider_state` 对账。
- 视图：`columns:(number|null)[][]`（null 是暗牌）、`stock_count`、`completed`、`move_count`、`revision`、`can_undo`、`can_deal`、`legal_moves:[{source,index,target}]`、`finished`、`winner`、`reason`。
- 不下发余牌顺序、暗牌点数或撤销历史。客户端只消费合法着，不实现规则。

## 验证

规则测试覆盖非法输入不变更、移动与翻牌、整组收齐与撤销、发牌顺序、终局、牌数守恒和存档编码。
协议测试覆盖非本人访问、过期操作、断线/清理/重启续玩、新局与终局战绩。
浏览器在独立临时后端和数据库上验证手机牌桌、实际移动、发牌、撤销、刷新、返回、帮助、新局、真实胜利和战绩。
