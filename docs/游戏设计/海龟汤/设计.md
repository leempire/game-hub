# 海龟汤设计

首批收录三批 23 道网上已公开题，完整来源与许可见 `server/content/turtle_soup/README.md`。

1–8 名真人共同推理，AI 为独立主持，不占席位。主持始终需要调用在线模型，因此不论房间人数，房主 AI 积分至少 100 才能开局。复用通用 AI 服务的模型、low 思考深度、实际用量扣费、负余额阻断和幂等流水，不在 UI 公开费率。

## 一局流程

1. 房主开局，服务端从公开题库随机抽取题目，排除房内所有参与者已玩过的题。开局即为本局所有人记录已玩。没有共同未玩题时明确拒绝开局，不清空记录、不悄悄循环复用。
2. 所有人看到标题和汤面，汤底、关键事实和内部题号仅保留在服务端。玩家可以自由提交「提问」（1–200 字）或「猜汤底」（1–500 字），一次只处理一个请求；忙碌时其他人可以继续编辑但不能提交。
3. AI 基于固定汤底和公开问答，对普通提问只回答「是 / 否 / 不确定」。未设定、无关、歧义、复合问题或要求泄露答案时都允许回答不确定，不编造新事实。
4. 只有「猜汤底」触发完整真相评估。语义已覆盖关键事实且没有关键矛盾时，AI 判定基本猜出，本局合作通关，向参赛者公布固定汤底。允许遗漏无关枝节，不能仅提到一个关键词就通关。
5. 最多 80 次提交，达到上限结束并揭晓；房主也可确认「结束并揭晓」。支付人退房或断线保座超时结束本局，不把当前局费用转嫁给新房主。已发送的请求仍按实际用量结算。
6. 终局保留参赛者结算回看，房间回 waiting，其他人准备后由房主续开。新局重新检查当前房主积分，抽题继续排除所有人的已玩记录。

## 权威、并发与隐私

- 纯引擎位于 `server/app/game/turtle_soup.py`，只处理局号、提交、枚举结果、核心事实覆盖、结算和白名单视图，不访问 IO、墙钟或账户。
- 主持 Agent 可读固定答案，玩家文字只作为不可信数据；模型响应不向客户端透传，自由文字及秘密字段全部丢弃，仅采用受限枚举和判定。
- 每次动作含 match_id、revision、request_id，服务端验证成员和对局；同一请求幂等，旧局/旧版本不得扣费。待处理提交先持久化，再交通用账号串行锁；等待期间不锁住 WS 收消息循环。
- 请求返回先结算 usage，随后检查房间对象、对局对象和待处理请求是否仍相同；已离开/已终局的迟到回答不再影响对局。
- 断线保座沿用 120 秒。全员离线时不新发 AI 请求；在途回复可正常落盘，下次重连看到结果。热重启不重发未完成付费请求，标记「上次主持请求中断，请重新提交」，保留题和问答。
- HTTP 房间、进行中 WS、匿名分享不含汤底和关键事实；个人战绩仅向实际参赛账户提供终局答案。公开题库不能打进 Web bundle / APK。

## 客户端与战绩

共用 GameShell / GameResult、AppModal、主题与键盘 padding 避让。汤面常驻卡片，问答记录显示提问人、提交种类、主持状态和受限回答。模式切换不提交，提交按钮按忙碌、联网与服务端 can_submit 禁用。错误留在输入区，保留草稿。返回有 Android beforeRemove 和 Web onConfirmLeave 双路径；深链入局与结算回房使用已有保座流程。

合作通关为仍在局玩家记 win；主动离开记个人 lose。主动揭晓/达到上限记 lose，因支付人离开等中止则其余人记 end。个人快照只保留汤面、汤底、结局、提问次数与猜中者，不保存玩家自由输入；公开分享进一步去掉汤底与猜中者。

### 自动渐进提示

主持在原有同一次调用中返回私有 `progress`（on_track / stalled / off_track / unclear），服务器只把枚举回答和已经触发的固定提示下发。每题三档辅助提示，按顺序逐步具体，不改变来源题面或汤底。已回答至少 3 次且距上一提示至少 3 次回答后，明确跑偏或没方向可触发下一档；连续 6 次没有进展也触发。正常推进重置停滞计数，失败请求不计数，通关或达到提交上限不再提示。模型自由生成的提示不予采用，避免提示注入泄底。次数与提示进度随房间持久化，重连不会重置或重复发提示；旧房恢复时补齐对应题目的提示阶梯。

提示显示在触发它的回答卡片下，所有参与者可回看。完整提示阶梯、私有进展判定和未来提示不下发、不写入公开战绩。无需新增 AI 调用。
