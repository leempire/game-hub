# 俄罗斯方块对战设计文档

- 屏：`app/src/screens/TetrisScreen.tsx`　客户端预演：`app/src/tetris.ts`
- 引擎：`server/app/game/tetris.py`（无 AI，与人机无关）
- 人数 1-4（1 人即可开）｜不支持人机｜战绩落库（含每人终局盘面回放）

## 玩法

10 列 × 20 行。方块自上而下落，玩家左右移动 / 旋转 / 落底，一行填满即消除。
**各玩各的盘**，同时开局、实时共享分数排行榜——与 2048 同一套「跑分竞速」模板，
区别是方块序列由服务端给、且消多行会给对手**顶攻击行**。

- 方块序列：所有玩家共用**同一个 7-bag 随机种子**，所以拿到的是完全一样的方块
  顺序（公平，比的是摆放不是运气）。
- 消行得分：1/2/3/4 行 = 100/300/500/800，**乘以当前等级**；每消 10 行升 1 级。
- 攻击行：一次消 2/3/4 行分别给每个对手顶 1/2/4 行带空洞的行（消 1 行不攻击）。
  被顶的盘整体上移，**下落中的方块也跟着上移**（最多顶到最上一行）。
- 单人结束：**堆到天花板、方块没地方放了**才出局（被攻击行顶到天花板同理）。
  全员结束才结算，排名键是 `(是否撑到最后, 出局先后倒序, 分数)`。

```
║ │ 10×20 深色井               │   0           ║

└──────────────────────────────────────────────┘
```

二十行的盘面很高，HUD 若散在页面浅底上会像一列调试读数。**把「分数 / 行数 /
等级 / 被顶 + 下一块 + 棋盘」收进一块深色面板**，整体才像一台游戏机——和 UNO 的
牌桌、海战棋的水面是同一个做法：游戏面比页面暗，格才跳得出来。

**HUD 放在棋盘右侧而不是上方**，这是竖屏下的关键取舍：高度是稀缺资源（导航栏、
顶栏、提示条、操作区、认输都是固定开销），而 10 列的棋盘横着用不完屏宽。
挪到侧栏后实测格宽 **390×844 上 23px → 26px、360×640 上 13px → 18px**，
面板也不再有「比棋盘宽一大截」的空白。屏幕更矮时高度约束先生效（`useCellSize`
取两者的小值），侧栏宽度固定 92px。

- 面板 `tetrisPanel` vs 井底 `tetrisBoard` 1.45 —— 井看得出是凹进去的。
- **下一块预览自带一小块井底**：紫 T / 红 Z / 蓝 J 直接压在面板上只有 2.1~2.3，
  达不到图形阈值 3:1；压井底则 ≥4.48（实测值见 `theme.ts`）。
- **空位描一道 `tetrisGrid` 细线**（vs 井底 1.71）把 10 列引出来。试过「把空位
  填充调亮」，结果整块盘面变成一片浅灰、格子之间依旧没有分界，反而更看不清——
  引列要靠线，不靠填充。
- 认输与 UNO 一致：**描边幽灵按钮**（破坏性操作不该和「落底」抢注意力）。

## 交互设计

### 方块形状与踢墙顺序**由服务端下发**，客户端一格规则都不重写

客户端为了手感必须在本地预演（左右 / 旋转 / 硬降都要立刻响应，不能等一次往返），
预演就要知道「转一下变成什么形状」「贴墙转的时候往哪边挪」。所以
`sync` / `game_start` / `tetris_state` 都带一份 `shapes`（七种方块 × 四态的完整
旋转表）与 `kicks`（踢墙尝试顺序）。

**不让客户端自己写旋转表**：象棋的合法着法、飞行棋的走子路径都是同一条教训——
多一份实现必然漂移。这份表只有 7×4×4 个坐标，跟着每次状态一起发，还省掉了
「客户端要记住表」的状态管理。

> 服务端仍然是**盘面的唯一权威**：客户端预演只是渲染，真正裁决在服务端。

### 每块方块一次往返：本地攒动作，锁定后整段重放

服务端没有任何「按时间推进」的状态（这个项目里所有游戏都是请求—响应模型，没有
周期性 tick 的先例）。重力由客户端按自己的节奏推进，动作**累积成一串**，到
**方块锁定**时一次性发上去：

```
按键/重力 → 本地立刻执行 + 记进 pendingRef（手感零等待）
落定（下不动了 / 点了硬降）→ socket.tetrisActions(pending) → 服务端重放
服务端回 tetris_state（权威盘面 + 新方块 + 分数）→ 客户端 adopt 覆盖本地
```

好处：零信任（服务端拿同一套引擎重放客户端动作，盘面永远以服务端为准），
每块方块只要一次往返，也不需要每房间一个后台任务（否则要处理任务泄漏、
SQLite 高频写盘、热重启恢复 tick 状态三件事）。

### 锁定后**冻结输入**，等回包再放开

服务端回包里才有「下一块是什么」和「消了哪些行」。回包到之前如果继续操作，
本地只能猜（下一个方块未知、消行规则又要再实现一份），必然与重放结果分叉。
所以 `awaiting` 期间左右/旋转/降落一律吞掉——一个往返而已，本地后端几毫秒，
公网也就百毫秒级。

### 被攻击时**丢掉本地未上报的动作**

收到 `last_action: 'garbage'` 的 `tetris_state` 说明服务端刚把整盘上移了，本地
那份已经不是同一个基准。此时把 `pendingRef` 清空、直接采用权威盘面：丢掉的
最多是一帧内的一两次移动，而拿旧基准去重放会画错整块。

### 棋盘渲染：把「下落中的方块」直接烙进盘面再画

`displayBoard = stamp(本地盘面, 当前方块)`，然后老老实实画 200 个格子（不做
绝对定位的浮动层）。这样盘面与 DOM 顺序天然一致（E2E 可以直接按
`t-c-<row>-<col>` 逐格读），落点幽灵框也只是「多标几个格子」。

- **虚线幽灵框**：轮到自己时把方块按到底的位置画成虚线空心框。用亮一档的
  `tetrisGhost #64748B`（vs 盘面 3.73 ✓）而不是空位槽那种暗色——幽灵是**要看见
  的信息**，暗色在深盘上根本看不出边框；虚线 + 空心底再补一层「不是实体块」的通道。
- **每格描一圈墨边**（`tetrisEdge #0B1220`，vs 各填充色 3.87~12.23 ✓）：两个同色
  方块紧挨着（I 横条四格）不描边会糊成一大条，看不出「一格一格」——这是形状信息。
- **空位槽 `#1F2937`（vs 盘面 1.21）是纯装饰**：空位不承载信息，块的位置由方块
  自身的亮色（vs 盘面 ≥4.48）与墨边确定。

### 触控：五个按钮 + 单击旋转 + 左右拖动实时移动（v1.9.1 改）

主要操作按钮统一 `paddingVertical: spacing.sm + 6`（≈47px，HIG ≥44pt）；棋盘上
**单击 = 旋转**、**左右拖动 = 方块跟着手指一格格挪**（`applyDrag`）、下滑 = 软降、
上滑 = 旋转。手势的 `onPanResponderTerminate` 与 `release` 走同一套判定——Web 端
浏览器会中途把手势 cancel 掉，不补这一刀就是「滑了没反应」（2048 踩过同一个坑）。

- **拖动是「实时」的，不是松手时按总位移补算**：手指每跨过 0.8 格就走一格
  （`DRAG_STEP_RATIO`），这样才像在搬这块方块；松手才动的话手感上和点两次
  按钮没区别。
- `gs.dx` 是本次手势的**总**位移，所以要揣一个累加器 `consumedRef` 记住
  「已经兑现了多少格」，剩下的才是还欠的格数；快速甩动时 move 回调可能只来
  一两次，**松手时再跑一遍同一个函数**把余量补上（同一个累加器，不会重复扣款）。
- 单击判定用 12px 的 `TAP_SLOP`，小于它才算「点了一下」——比一格（≈21px）小
  得多，所以单击永远不会误触发一次移动。

### 出局提示**盖屏**，不能挂在页面底部（v1.9.1 修）

自己出局、别人还在玩时，弹一层盖住整屏的浮层（`t-out-overlay`）：说明原因
（被攻击行压死 / 方块顶到天花板 / 主动认输）+ 还有几个人在继续 + 「返回房间」。

**这条原来挂在页面最底下**（认输按钮下面），而 20 行的棋盘很高：实测
**390×844 上「返回房间」bottom=850 > 844**、**360×640 上 top=657 > 640**，
页面又没有滚动容器，于是手机上是整个被裁掉的。出局之后棋盘不再有方块、
重力与按键全部空转（`curRef` 为 null），玩家看到的就是「盘面冻住、再也不出
新的方块」而**看不到任何原因**——这正是用户报的「被顶之后卡住」。出局是必须
被看见的状态，做成盖屏浮层后与视口高度无关。

顺带把文案里的 `\n` 与两行结构写清楚：标题一行（你已结束 / 本局结束）、
原因一行、按钮占满卡片宽度（卡片是纵列容器，**不能**直接用 `primaryBtn` 的
`flex: 1`——纵向 `flexBasis: 0` 会把它压扁）。

### 排行榜：右上角可收起胶囊

`第 N 名 · M 人` 胶囊点开是实时排行浮层（分数 / 行数 / 已结束标记）。4 人局也
不会横向溢出。

## 已知取舍

- **没有 hold（暂存）与 next-next 预览**：需要额外的服务端状态与协议字段，
  先不做；「下一块」预览够用。
- **不校验客户端节奏**：服务端只重放动作、不校验时间，所以理论上可以无限加速。
  信任级别与 2048 一致（客户端决定节奏），不做反作弊。
- **`garbage_count` 是本次发送量**：一次动作序列通常只锁一块，所以「本次发送量」
  就是每个受害者收到的行数；本局累计值另有 `garbage_received`。
- **断线超时只结束本人但不再单独广播**：其余玩家的排行榜会在自己下一次动作时
  更新（认输路径已单独广播，见 `_handle_surrender` 的 tetris 分支）。
- **方块没有「可视区上方的缓冲区」**：20 行棋盘就是整个可视区，`spawn()` 把方块
  放在第 0 行。所以被攻击行顶的时候方块只能夹在第 0 行（不会像真实俄罗斯方块那样
  先退进缓冲区），"顶上去了放不下" 就是出局。要真做缓冲区就得让
  `is_valid`/`lock`/客户端预演三处都支持负行号——收益只是几帧的视觉过渡，不值。
