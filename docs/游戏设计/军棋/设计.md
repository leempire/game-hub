# 军棋（陆战棋）设计文档

- 屏：`app/src/screens/LuzhanqiScreen.tsx`　棋盘渲染：`app/src/screens/LuzhanqiBoardView.tsx`
  几何：`app/src/luzhanqiBoard.ts`　展示层：`app/src/luzhanqi.ts`
- 引擎：`server/app/game/luzhanqi.py`　AI：`server/app/game/luzhanqi_ai.py`
- 人数 2（须满员开局）｜支持人机｜**明棋 / 暗棋两种玩法**（房间内可选）
- 战绩落库（快照含**全量真相**与棋盘地形，可回放）
- 调研：`增强调研.md`（玩法 / 视觉 / 交互三个维度，含棋盘拓扑的原始几何来源）

## 玩法

12 行 × 5 列 = 60 个停靠点，双方各占 6 行（30 点）；两半之间夹着一排
**3 个前线**（可穿过的铁路）+ **2 个山界**（没有边，过不去）。

每方：**5 个行营 + 23 个兵站 + 2 个大本营 = 30 点**，行营不能放子，
所以可用布阵点恰好 **25 个**，正好放 25 枚棋子。

- 行营：二线的列 1/3、三线的列 2、四线的列 1/3（`○`）
- 大本营：端线的列 1 与列 3（`◆`）

```
row 0  ■ ◆ ■ ◆ ■   端线
row 1  ■ ■ ■ ■ ■   底线   ── 整行铁路
row 2  ■ ○ ■ ○ ■   四线
row 3  ■ ■ ○ ■ ■   三线
row 4  ■ ○ ■ ○ ■   二线
row 5  ■ ■ ■ ■ ■   锋线   ── 整行铁路
       ┊ ↑ ┊ ↑ ┊   前线（列 0/2/4）· 山界（列 1/3，无边）
row 6  ■ ■ ■ ■ ■   锋线   ── 整行铁路
row 7  ■ ○ ■ ○ ■   二线
row 8  ■ ■ ○ ■ ■   三线
row 9  ■ ○ ■ ○ ■   四线
row 10 ■ ■ ■ ■ ■   底线   ── 整行铁路
row 11 ■ ◆ ■ ◆ ■   端线
```

**铁路** = 4 条整行横线（底线 ×2、锋线 ×2）+ 列 0 / 列 4 两条贯通竖线
+ **中路只有中缝那一段** `(5,2)-(6,2)`。共 35 条边。
**公路** 98 条（含 32 条斜线，绕行营形成 X 形通路；端线之间没有斜线）。

> 这两处最容易记错：**横向铁路在底线与锋线**（不是二线/四线），
> **中路列 2 的纵向铁路只有中缝一段**。见 `增强调研.md` §1.7 的来源。

**棋子**（每方 25）：司令 1、军长 1、师长 2、旅长 2、团长 2、营长 2、连长 3、排长 3、
工兵 3、地雷 3、炸弹 2、军旗 1。

**布局约束**：军旗必须在大本营；地雷只能在最后两排；炸弹不能在第一排；行营不能放子。

**走法**：军旗 / 地雷不可移动；大本营内的棋子不可移动；公路一步；铁路直线不限格数、
工兵可在铁路上任意拐弯；行营里的棋子不可被攻击、每次只能走一步。

**碰子**：军衔大者胜、同级同归于尽；炸弹与任何棋子同归于尽；工兵吃地雷（工兵存活）、
炸弹撞地雷同归于尽、其余撞地雷自己被吃；**司令阵亡则该方必须亮出军旗位置**。

**胜负**：吃军旗即胜；无棋可走判负；连续 120 半回合无吃子判和。

## 界面构成

```
顶栏   我方身份 + 玩法（明棋/暗棋）+ 对手名｜帮助按钮｜房间号
掉线条 对方掉线倒计时（秒数由服务端下发，界面不写死）
战报条 **留死高度**，显示上一条碰子结果 / 当前阶段提示
布阵条 仅布阵阶段：「双方布阵中 / 对方已确认布阵 / 已确认，等待对方」+ 随机 + 确认布阵
棋盘   5 列 × 12 行，两半之间留 0.5 格高的前线带
棋子盘 我方存活棋子与剩余数量（军棋 25 枚，记不住自己还剩什么是常事）
底栏   认输 / 退出房间（都要二次确认）
```

## 交互设计

### 布阵：默认阵型 + 点两子交换（本游戏独有的一个阶段）

25 枚棋子逐枚拖放在手机上极难受（腾讯天天军棋也是给「默认布局 + 保存布局」）。
本作的做法：

1. 开局服务端给**双方各发一套随机生成的合法阵型**（不是固定套路，免得每局都被
   同一套强阵型锁死）；
2. 玩家**点两枚棋子交换位置**，另给「随机」重掷、「确认布阵」提交；
3. **交换是否合法只在服务端判定** —— 地雷只能在后两排、军旗必须在大本营、
   炸弹不能在第一排，客户端一行约束都不写（同象棋「合法着法由服务端下发」）。
   非法交换服务端回一条 `error`，客户端清掉待交换态。

双方都确认才进对局。**布阵阶段对手的半场是扣着的**（明棋也一样）——
明棋的传统是「各自摆好、摆完同时亮出」，边摆边被盯着看反而怪。

### 经典阵型预设（v1.17）

布阵要摆 25 枚子，逐枚交换在手机上很费时。除了「随机」重掷，布阵条上还有一排
**经典阵型芯片**：双喜临门 / 午夜风铃 / 飞花逐月 / 飘香一剑 / 三节阵 ——
点一下整套摆好，而且是**有讲究**的阵型，不是掷骰子。

- 引擎里是 `_PRESET_ROWS`（6 行 × 5 列的文本表，**第一行是锋线**，`·` 是行营）
  + `preset_layout(color, name)`：照自己这半边写，两个颜色各自镜像一次
  （黑在上 `row = 5 - i`，红在下 `row = 6 + i`；列不镜像，双方各按自己的视角读同一张图）。
- ⚠️ 阵库对炸弹**两种写法混用**（飞花逐月/三节阵写「弹」，其余三套写「炸」），
  照抄原文，别去统一 —— 那是来源里的原样。
- ⚠️ 阵型表是常量，理论上必然合法，`room_manager` 里**仍然过一遍
  `validate_layout`**：将来往表里加阵型时手滑写错一个字，会当场被拦住而不是
  变成一局摆不满 25 枚的棋。
- **名单由服务端随视图下发**（`view_for` 的 `presets: [{key, label}]`），
  客户端只渲染芯片、一行规则都不写（同房间设置那条约定）。

### 两步落子 + 服务端下发合法落点

棋盘 12 行，在 390×844 上格高约 41px、格宽约 62px；360×640 上格高只剩 ~25px，
都达不到 44pt。所以走子用**两步式**（点自己的子 → 高亮落点 → 点落点），
误触可以在提交前撤销 —— 与象棋同一条取舍。

合法落点由服务端 `legal` 下发（扁平 `[fr,fc,tr,tc]`）。军棋的「铁路直行 +
工兵拐弯 + 行营规则」复杂到没有第二份实现的必要。

⚠️ **`legal` 只算收件人自己的**（不能像象棋那样把轮走方的全发下去）：
暗棋里「某个位置有子可动」本身就泄露了「它不是地雷也不是军旗」。

### 碰子反馈

- 战报条**留死高度**（30px），出现/消失不推挤棋盘（俄罗斯方块「出局提示被挤出
  视口」的教训）。
- 碰子那一格画一圈醒目描边 + 震动 20ms。
- 暗棋·不公开身份时，战报只说「我方/对方棋子阵亡」，**只有自己那一枚报得出名字**。

### 视角翻转

红方渲染在下方、黑方做 180° 上下翻转（同象棋），只翻行不翻列。
testID 用**屏幕坐标**，所以 E2E 点 `lz-cell-6-0` 点到的就是自己半场第一排。

### 棋盘美术

**地形全部靠形状区分**：铁路画粗双线（粗线打底 + 中线回填）、公路画细线、
行营画圆圈、大本营画圆角方块、山界画双层折线、前线画虚线。
两条线的颜色差只有 1.35:1，靠色相是分不出来的。

棋子是「奶油小方块 + 本方色描边 + 汉字」，**汉字本身就是信息通道**（WCAG 1.4.1）。
暗棋的对手棋子画**深色牌背 + 五角星**，与正面的汉字形成形状 + 文字双通道。

### 可落点：两种形状

空位画**实心圆点**、可吃的敌子画**一圈环**——形状区分，不只看颜色。

## 状态与协议

`game_to_sync` / `view_for` 下发的载荷（逐人裁剪）：

```jsonc
{
  "cells": [[{"c": "red", "p": "siling"}, null, ...], ...],  // 暗棋下对手的 p 是 null
  "topology": { "kinds": [...], "rails": [...], "roads": [...],
                "fronts": [...], "mountains": [...] },       // 棋盘地形（唯一来源）
  "phase": "setup" | "playing",
  "mode": "open" | "hidden",
  "reveal": true,                    // 暗棋下阵亡是否公开身份
  "next": "red",  "your_color": "red",
  "ready": {"red": false, "black": true},
  "flag_revealed": {"red": false, "black": true},
  "alive": {"siling": 1, ...},       // 己方剩余棋子
  "battles": [ ... ],                // 已裁剪的战报
  "legal": [[fr,fc,tr,tc], ...],     // **只算收件人自己的**
  "last_move": {"from": [..], "to": [..], "by": "red"}
}
```

消息一览：

| 方向 | 消息 | 说明 |
|---|---|---|
| C→S | `room_setting` `{key: "mode"\|"reveal", value}` | 房主在等待大厅里选玩法（v1.15 起走全站统一的房间级设置入口，两项各自独立） |
| C→S | `luzhanqi_setup` `{action: swap\|random\|confirm, a?, b?}` | 布阵三个动作 |
| C→S | `luzhanqi_move` `{from_x,from_y,to_x,to_y}` | 走子（x=列, y=行） |
| S→C | `game_start` | 进对局屏（`phase: "setup"`）；**客户端靠它导航** |
| S→C | `luzhanqi_setup` | 只回给改阵型的那个人 |
| S→C | `luzhanqi_ready` | 广播「谁确认了」 |
| S→C | `luzhanqi_begin` | 双方确认，进入对局（逐人裁剪） |
| S→C | `move` | **逐人下发**（战报按收件人裁剪、legal 只算他自己的） |
| S→C | `game_over` | `{winner, reason}` |

`move` 里另带 `newly_revealed: [{color, at}]` —— 司令阵亡时把**亮出来的那面军旗
在哪**一起发下去。只发一个布尔值没用：对手知道「军旗亮了」却看不见它在哪，
这条规则就白设了。

## 结算

吃军旗 / 无棋可走 / 认输 / 断线 / 判和。终局弹窗只有「返回房间」，
房间回到 `waiting` 可续开（同其它游戏）。

## 最近一步标记

复用跨游戏那一套：「黄点 + 深墨描边」。有子时画在棋子右上角（同象棋，中心会盖住
汉字），空格上直接画在格心。

## 已知坑（勿回退）

1. **`game_start` 不能发成 `luzhanqi_setup`**。进对局屏那一次必须是 `game_start`，
   因为**客户端是靠 `game_start` 导航到对局页的**；发成别的消息，房主（他刚点过
   「开始游戏」，房间页有自愈）能进去，**加入方永远停在房间页**。
   E2E 第一次就是红在这一步。
2. **空格子也必须能点**。第一版只给「有棋子的格子」挂了 `onPress`，
   于是**走子落到空格上根本点不了**（E2E 抓到）。现在渲染的是**整张 12×5 的格子层**，
   棋子只是格子里的一层视觉。
3. **`legal` 只能算收件人自己的**。发「轮走方全部着法」会泄露
   「某位置有子可动」=「它不是地雷/军旗」。
4. **布阵阶段对手的半场不能下发**（明棋也一样）——`view_for` 里
   `hide_other = mode == "hidden" or phase == "setup"`。
5. **`_opponent_color` 必须带 `game`**：军棋用红/黑，不传 `game` 会把 `black`
   翻成 `white`，认输/断线判负的赢家直接判反。
6. **`_build_snapshot` 必须有 `luzhanqi` 分支**：漏了不报错，只会让战绩页点开一片空白。
7. **快照要带 `topology`**：战绩页复用对局屏那一份棋盘画法，没有地形就画不出线。
8. **AI 只能拿 `view_for` 的产物**。`best_move(view)` 的入参就是真人看到的那份视图，
   `gs` 压根没传进去 —— 暗棋下它同样看不见对手的棋子身份（契约见
   `test_luzhanqi_ai.py::test_beliefs_come_from_position_not_from_identities`）。

## 待优化项

- **布阵阶段没有倒计时**：一方不确认就干等（本项目所有游戏都没有走子限时，
  这是有意的；但布阵是个明确的「等待对方动作」状态，值得单独考虑）。
- **暗棋 AI 的信念集只用到「最后 8 条战报」与位置约束**：更完整的做法是把
  每次交战的相对大小约束挂在棋子上（棋子移动后跟着走），现在只挂在格子上。
- **明棋 AI 没有做多步搜索**：现在是「静态分 + 一层威胁检查」，够用但不算强。
- **兵站/行营/大本营的位名**（棋眉、咽部、脐部、旗台…）没有进界面 ——
  只在帮助里讲了规则，没有做「点位术语」的提示。
- ⚠️ **`server/app/game/luzhanqi.py` 725 行**（超过项目自己定的 500 行线）。它是纯引擎、
  无 IO、注释密度高（地形表 + 走法 + 碰子 + 视图裁剪四段），真要拆得按
  「地形 / 走法 / 对局 / 视图」分，是独立一轮。
