# 军棋（陆战棋）调研

> 2026-10-14。新增第 13 个游戏前的联网调研，中英文各一轮，按「玩法规则 / 视觉 / 交互」三个维度
> 分别搜，核心结论交叉验证 2 个以上来源。**「采纳 / 不采纳」清单在第 4 节，有意不做的方向写了理由，
> 不要重新评估。**

## 0. 本次要回答的问题

1. 二人军棋的**棋盘到底长什么样**（60 个停靠点分别是什么、铁路连哪些点、山界挡在哪）——
   这是整轮调研里唯一一个「查不到就没法动手」的问题。
2. 明棋 / 暗棋的信息模型差在哪，暗棋的「裁判」到底裁什么、公开多少信息。
3. 走法与碰子的完整规则，以及各平台之间有分歧的地方。
4. 移动端该怎么画、怎么操作。

## 1. 玩法规则

### 1.1 棋盘（多来源一致）

- 12 行 × 5 列 = **60 个停靠点**，双方各占 6 行（30 点）。
- 停靠点分三类：**兵站**（长方形，棋子摆放位）、**行营**（圆形，安全区）、**大本营**（每方 2 个）。
- 每方：**23 个兵站 + 5 个行营 + 2 个大本营 = 30**。行营不能放子 → 每方可用布阵点恰好 **25 个**
  （23 兵站 + 2 大本营），正好放 25 枚棋子。
- 两半之间还夹着一排 **5 个特殊位置**：3 个**前线**（可穿过）+ 2 个**山界**（不可穿过）。
  所以英文维基记作 **65 个 space**（60 停靠点 + 5 个非停靠点）。
- 每方 6 行从自己前线往后退依次叫：**锋线、二线、三线、四线、底线、端线**。
- 行营位置：二线的列 1/3（**左前营 / 右前营**）、三线的列 2（**中营**）、四线的列 1/3（**左底营 / 右底营**）。
  「军旗上方的底营又叫旗营」。
- 大本营：**端线的列 1 与列 3**（「左二」「右二」）。

来源：全国计算机博弈大赛《二人军棋项目规则》（`computergames.caai.cn/jsgz07.html`）；
抖音百科·军棋（`m.baike.com/wiki/军棋/695322`，含「每方 23 兵站 + 5 行营 + 2 大本营」与完整位名表）；
边锋游戏《四国军棋规则（二）》（`gameabc.com/subjectinfo/9_205_8.html`，行名与营名的原始出处）；
英文维基 Luzhanqi（65 space / 3 前线 / 2 山界）。

### 1.2 棋子与布局约束

每方 **25 枚**：司令 1、军长 1、师长 2、旅长 2、团长 2、营长 2、连长 3、排长 3、工兵 3、地雷 3、炸弹 2、军旗 1。

布局约束（各来源一致）：
- **军旗**必须放在两个大本营之一；
- **地雷**只能放在**最后两排**（底线 + 端线）；
- **炸弹**不能放在**第一排**（锋线）；
- **行营不能放子**。

### 1.3 走法

- **军旗 / 地雷不可移动**；**大本营内的棋子不可移动**（进去就出不来，所以大本营只适合放军旗与地雷）。
- **公路线**（细线）：任何棋子每次只走**一步**。
- **铁路线**（粗线）：其他棋子只能沿**直线**不限格数移动，路径被任何棋子挡住就走不过去；
  **工兵**在铁路上可以**任意行走（可拐弯）**，走遍整个连通的铁路网。
- **行营**：里面的棋子**不可被攻击**；行营里的棋子每次只能走一步（按公路走法）。

来源：全国计算机博弈大赛规则原文；萌娘百科·军棋；腾讯《天天军棋》规则页。

### 1.4 碰子

- 军衔：司令 > 军长 > 师长 > 旅长 > 团长 > 营长 > 连长 > 排长 > 工兵。**大的吃小的，同级同归于尽**。
- **炸弹**与任何棋子相碰**同归于尽**。
- **工兵**碰地雷：地雷被挖掉，**工兵存活**；**炸弹**碰地雷：同归于尽；
  **其他棋子**碰地雷：**来犯者自己被吃**（地雷留下）。
- **军旗**：被任何棋子碰到即**该方失败**（吃掉军旗者胜）。
- **司令被消灭（被吃或同归于尽）后，该方必须亮出军旗所在位置**（暗棋里这是唯一一条强制的信息公开）。

### 1.5 胜负与和棋

- **吃掉对方军旗即胜**（全国计算机博弈大赛官方规则**不要求**先挖光地雷）。
- **无棋可走判负**——即「吃光对方所有能移动的棋子」；军旗 / 地雷 / 大本营里的棋子都不能动，
  所以只剩这些时就是无棋可走。
- **和棋**：连续无吃子达到上限判和（QQ 军棋规则页原文「一局游戏中连续 70 步没有吃子则自动算和棋」）。

### 1.6 三种玩法：明棋 / 暗棋 / 翻棋

| 玩法 | 布子 | 信息 | 需要裁判 |
|---|---|---|---|
| **明棋** | 双方各自摆好，摆完**同时亮出** | 全部公开 | 不需要 |
| **暗棋** | 棋子立起、正面朝自己 | **只看得到己方棋子**，对方是背面 | **需要**（本作由服务端担任） |
| 翻棋 | 全部背面朝上打乱铺开，轮流翻子 | 翻出来才知道 | 不需要 |

**暗棋的信息模型（本次最关键的一条）**——抖音百科·军棋「暗棋」节原文：

> 走棋前，对战双方先布局，将棋子互相背对并立置。一方先行棋，然后轮流走子。
> **整个过程玩家只会知道己方及对方的棋子是否出局，无法知道对方具体棋子信息。**

即：碰子只公布**结果**（我方阵亡 / 敌方阵亡 / 同归于尽），**不公布阵亡棋子的身份**。
民间玩法里裁判也只喊「红下」「黑下」「同下」（采风网·玩军棋，原文：
「裁判拿起来看后宣布『红下』、『黑下』或『同下』……裁判不能说『吃了』『对了』『炸了』等话语透露信息」）。

但**部分网游变体把阵亡棋子亮给双方**（信息量大得多、上手快）。本作**两种都做，房间内可选**。

### 1.7 棋盘拓扑的精确数据（本轮最大的产出）

通俗文章对「铁路在哪几行」记错得非常普遍，所以这一节以**能拿到原始几何数据**的来源为准。

**主要来源**：维基共享资源的官方棋盘矢量图
[`File:陸戰棋 board.svg`](https://upload.wikimedia.org/wikipedia/commons/b/b1/陸戰棋_board.svg) ——
直接解析它的路径数据：**粗线（`stroke-width:20`）恰好 7 条**，细线（`stroke-width:5`）给出全部公路，
`r=50` 的圆是行营，端线列 1/3 画的是大本营，列 1/3 中缝上两个 `r≈70` 的大圆正是**山界**。

**交叉验证来源 ①**：51CTO《Openharmony 军棋工兵寻径算法的实现》

[0,1,1,1,0]  三线
[0,1,1,1,0]  二线
[0,0,0,0,0]  锋线   ← 整行铁路
[0,1,0,1,0]  中缝   ← 只有列 0/2/4 通（列 1/3 = 山界）
[0,0,0,0,0]  锋线   ← 整行铁路

[0,1,1,1,0]  三线

**交叉验证来源 ②**：幻想游戏网《军棋陆战棋棋盘术语》的 ASCII 连接图，斜线走向逐条吻合：

三个来源互相独立却完全一致，因此下面这张表可以直接编码：

#### 点位类型（`row 0` = 上方玩家端线，`row 11` = 下方玩家端线）

```
row 0  (端线)  P  H  P  H  P
row 1  (底线)  P  P  P  P  P
row 2  (四线)  P  C  P  C  P
row 3  (三线)  P  P  C  P  P
row 4  (二线)  P  C  P  C  P
row 5  (锋线)  P  P  P  P  P
       ── 前线（列 0/2/4，可穿过）· 山界（列 1/3，无边）──
row 6  (锋线)  P  P  P  P  P
row 7  (二线)  P  C  P  C  P
row 8  (三线)  P  P  C  P  P
row 9  (四线)  P  C  P  C  P
row 10 (底线)  P  P  P  P  P
row 11 (端线)  P  H  P  H  P

P = 兵站   C = 行营   H = 大本营
```

#### 铁路（粗线）：7 条直线段 = 35 条边

| 段 | 走向 | 覆盖 |
|---|---|---|
| R1 | 横 | `(1,0)—(1,4)` 上方底线 |
| R2 | 横 | `(5,0)—(5,4)` 上方锋线 |
| R3 | 横 | `(6,0)—(6,4)` 下方锋线 |
| R4 | 横 | `(10,0)—(10,4)` 下方底线 |
| R5 | 竖 | 列 0，`row 1..10`（含 `(5,0)-(6,0)` 过界段） |
| R6 | 竖 | 列 4，`row 1..10`（含 `(5,4)-(6,4)` 过界段） |
| R7 | 竖 | **只有 `(5,2)-(6,2)` 一段**（中路只在中缝是铁路，每方阵地内列 2 是公路） |

> ⚠️ **最容易记错的两处**：①横向铁路在**底线与锋线**（不是二线/四线）；
> ②中路（列 2）的纵向铁路**只有中缝那一段**，并不贯穿全盘。

#### 公路（细线）：98 条边

- **横向 32 条**：`row ∈ {0,2,3,4,7,8,9,11}` 每行 `(r,c)-(r,c+1)`（铁路行那 4 行不是公路）。
- **纵向 34 条**：列 0/4 各只有端线那一段（`(0,0)-(1,0)`、`(10,0)-(11,0)`）；列 1/2/3 各 10 段，
  列 1/3 **缺 `(5,1)-(6,1)`、`(5,3)-(6,3)`**（那就是山界）。
- **斜向 32 条**：**端线之间没有斜线**，斜线只在底线↔四线↔三线↔二线↔锋线之间，
  且每条都是「行列各差 1」的对角步。每方 16 条，呈锯齿状（行营周围形成 X 形通路）。
  上方玩家的 16 条：
  ```
  (1,0)-(2,1) (2,1)-(3,2) (3,2)-(4,3) (4,3)-(5,4)
  (1,4)-(2,3) (2,3)-(3,2) (3,2)-(4,1) (4,1)-(5,0)
  (1,2)-(2,1) (2,1)-(3,0) (3,0)-(4,1) (4,1)-(5,2)
  (5,2)-(4,3) (4,3)-(3,4) (3,4)-(2,3) (2,3)-(1,2)
  ```
  下方玩家上下镜像（`r → 11 − r`）。

#### 邻接总账（校验用）

```
横向 12 行 × 4 = 48    （16 铁路 + 32 公路）
纵向 5 列 × 11 = 55 − 2（山界）= 53   （19 铁路 + 34 公路）
斜向 32（全公路）
合计 133 条边 = 35 铁路 + 98 公路
```

## 2. 视觉维度

- **棋子是长方形小方块**（不是方形棋子，也不是立体棋子）——所以 5 列 × 12 行的棋盘在竖屏上
  天然合适：格宽 ≈ 56px、格高 ≈ 40px → 棋盘约 280×480，竖屏放得下 HUD 与操作区，
  不需要横向滚动（对比：扫雷高级被压到 22px 是踩过的坑）。
- **棋盘地形必须靠形状区分，不靠颜色**：铁路画**粗线/双线**、公路画**细线**、行营画**圆圈**、
  大本营画**碉堡/半圆**、山界画**山形**、前线画**虚线**。这是棋盘自带的视觉语言，
  主流实现（QQ 军棋、天天军棋、二国军棋 HD）全都照搬实体棋盘的画法。
- **棋子**：奶油/象牙底 + 深墨汉字 + 本方色描边。**汉字本身就是信息通道**，
  天然满足 WCAG 1.4.1（不能只靠颜色传达信息）。
- **暗棋的敌方棋子画牌背**（五角星军徽 + 斜纹），与「汉字正面」形成形状 + 文字双通道。
- 实体棋盘常见配色：木色/米黄底 + 深色线 + 红黑双方。可参考本项目象棋的
  「奶油圆盘 + 本方色圆环」双通道成形思路。

## 3. 交互维度

- **走子用两步选择**（点自己的子 → 高亮合法落点 → 点落点）。这是棋类 App 的通行范式
  （「Tap a piece to view its legal moves, then select a highlighted square to make your move」，
  见 Chess Board / 3D Chess 等 App 说明），也是本项目象棋已有的做法——
  用来补偿棋盘格子达不到 44pt 的问题（HIG 建议主控件 ≥44pt）。
- **合法落点由服务端下发**（同象棋 `legal` / UNO `playable` / 飞行棋 `path`）：
  军棋的「铁路直行 + 工兵拐弯 + 行营规则」复杂到没有第二份实现的必要。
- **布阵**：主流手游（腾讯天天军棋）的做法是「**默认布局 + 可保存的专用布局**」——
  25 枚棋子逐枚拖放太费时，手机上尤其难受。本作取「**服务端发一套合法默认阵型 + 点两子交换 + 随机按钮**」。
- **碰子反馈必须被看见**：战报条**留死高度**，出现/消失不推挤棋盘
  （俄罗斯方块「出局提示被挤出视口」的教训）。
- **信息面板**：翻棋玩法的主流实现有「每个棋子的数量与状态」面板（QQ 军棋翻翻棋：
  「亮起的点表示翻起，灰色的点表示未翻起，空洞则表示被吃掉」）——
  军棋 25 枚棋子，一个「我方存活棋子」盘能显著降低记忆负担。

## 4. 采纳 / 不采纳清单

### ✅ 采纳

| 条目 | 理由 |
|---|---|
| **明棋 + 暗棋双模式**（房间内可选） | 用户要求；两者共用一套引擎，只差「下发给谁多少信息」 |
| **暗棋「只公布谁出局」与「公开阵亡身份」两种信息模型，房间内可选** | 用户拍板；经典规则与网游变体各有受众 |
| **服务端当裁判** | 暗棋的裁判天然由服务端担任，不需要额外机制 |
| **司令阵亡亮军旗** | 各来源一致；暗棋里唯一一条强制信息公开，也是军旗可被攻打的唯一线索 |
| **无棋可走判负 / 吃军旗即胜** | 官方规则原文；「吃光对方能动的子」在引擎里就是「轮到他没有合法着法」 |
| **铁路直行不限格数 + 工兵拐弯 + 行营不可被攻击 + 大本营内不可移动** | 规则核心，全部来源一致 |
| **默认阵型 + 点两子交换的布阵** | 用户拍板；服务端唯一判定合法性，客户端一格规则都不写 |
| **两步落子 + 服务端下发合法落点** | 本项目象棋已验证的范式 |
| **棋盘地形图由服务端整张下发** | 深空休眠 v9 的教训：几何只有一份实现。军棋地形有 133 条边，两份实现必然漂移 |

### ❌ 不采纳（**含理由，勿重新评估**）

| 条目 | 不采纳的理由 |
|---|---|
| **翻棋** | 用户只要求明棋 / 暗棋。翻棋是**另一套开局**（随机铺开 + 轮流翻子），会引入第三种信息模型与一套翻子交互，等于再做半个游戏 |
| **「先挖光对方三颗地雷才能扛旗」** | 部分平台房规。与全国计算机博弈大赛官方规则不符，且会把单局显著拉长 |
| **每步 30 秒走子限时 / 超时判负** | 本项目 12 个游戏**一个都没有**走子限时，加进来会变成孤例；拖时间由认输 / 断线 / 房间回收兜底 |
| **斜线公路按「山界可进入」等地方房规** | 来源明确标注为地方变体（「允许棋子进入山界藏身」），标准版与大赛版都不采用 |
| **四国军棋（4 人 2v2）** | 用户要的是 2 人对战；四国需要九宫棋盘 + 一套裁判协议，是独立一轮 |
| **AI 难度分级** | 用户拍板单一强度（与象棋 / 四子棋一致） |
| **每步 30 秒之外的其它限时（布阵倒计时等）** | 同上，本项目没有限时的先例；布阵拖时间由房间回收兜底 |

## 6. v13 补研：**把「有点呆」的人机改强**（2026-10-14，用户中途要求）

用户原话：

> 军旗的人机有点呆，后面也改一下

这一节是「怎么改强」的调研与实现记录。**调研按项目规矩先做**
（中英文各一轮：军棋 / 陆战棋的机器博弈论文，以及它的西方同名游戏 Stratego）。

### 6.1 调研结论：这类游戏的主流做法是什么

| 做法 | 代表 | 对我们的可行性 |
|---|---|---|
| **MCTS / UCT + 着法评估** | 《自动走子程序》用 UCB&MCTS，并**只对少数高价值棋子做协同搜索**（论文原话：25 枚棋子 × 12 兵种 × A 种走法 = `A^25`，「维度灾难」）| 需要把「不确定性」塞进模拟里，本作 0.8 秒预算下模拟次数太少、噪声盖过信号 |
| **信念搜索 + 概率推断（不完全信息）** | **Ataraxos**（2026 击败 Stratego 世界冠军，15:1）、DeepNash（DeepMind，无模型 RL）| **暗棋的正路**。但两者的重活都在「学出来的」策略/信念模型上，本作没有训练管线 |
| **概率型智能体**（每个未知敌子一个概率分布 + 评估函数） | *Designing agents for the Stratego game*（TU Cluj，2018）| ★ **本作采用的**：对手每个未知格维护候选身份集合、按概率取期望 —— 这正是本作暗棋已有的骨架，缺的是「信念要跟着棋子走」与「威胁要按概率加权」 |
| **演化博弈树搜索 + 神经价值网络** | *An Evolutionary Game Tree Search Algorithm of Military Chess Game*（2020）| 明棋的正路是搜索没错，但神经价值网络对本项目是杀鸡用牛刀 |

一句话结论：**明棋（完全信息）该搜索；暗棋（不完全信息）该把信念集做扎实**。
这也和本作现有的两套代码路径天然对得上。

### 6.2 改了什么（`app/luzhanqi_ai.py` 重写）

| 处 | 改动 |
|---|---|
| **明棋** | 新增 **negamax + alpha-beta 搜索**（迭代加深、吃子优先排序、时间预算掐在 `_TIME_BUDGET`）。原来只有「静态评估 + 一层威胁检查」。**无棋可走按判负**处理（军棋的真实规则）—— 不写这条，搜索会以为「站着不动」是安全的 |
| **暗棋 · 信念跟着棋子走** | `last_move` 是对手走的 ⇒ 它搬到的那个格子**不可能是地雷/军旗**（那两个不能动）。以前没有这条，于是「刚出门的那枚」在信念里仍然可能是地雷，AI 不敢用小兵试探它 |
| **暗棋 · 威胁按信念加权** | 每个未知格子的威胁从「只要够得着就算危险」改成 **`Σ p(b) × 它能吃掉我时我丢的价值`**。原来那版把「未知」一律当成最大威胁 —— 一枚其实是地雷的邻居能让它一局不敢动 |
| **暗棋 · 兵种级收窄** | 从战报里数出**已经全灭的兵种**，从所有格子的候选里剔掉（`reveal=False` 时数不到，那就什么都不剔 —— 宁松勿错） |
| **暗棋 · 安全的试探** | 撞一个「刚走过路」的未知子额外加分（它不可能是雷/旗，等于免费探一张牌） |

### 6.3 怎么量「真的变强了」

两个脚本，都在版本库里：

- `test/luzhanqi_ai_v1.py` —— **旧实现的冻结快照**（逐字复制，不许改）。
- `test/bench_luzhanqi_ai.py` —— 对局台：新版分别和「随机走子」「旧版」各打一批
  （红黑各半，**两边的步时预算相同** —— 旧版基本不吃时间，新版是迭代加深，
  所以这份表量的是「同样一步 0.1 秒时谁更强」）。

实测（`--games 10 --ms 100`，红黑各半）：

| 模式 | 对手 | 新版战绩 |
|---|---|---|
| 明棋 | 随机走子 | 胜 10 / 负 0 |
| 明棋 | **旧版** | **胜 8 / 负 1 / 和 1** |
| 暗棋 | 随机走子 | 胜 7 / 负 2 / 和 1 |
| 暗棋 | **旧版** | **胜 5 / 负 1 / 和 4** |

> 读法：**明棋 8:1、暗棋 5:1**（各另有和棋）—— 两个模式都赢面明显。
> 暗棋那一栏的「和」是**双方都不敢接触**的结果（军棋 120 手无吃子判和），
> 不是没分出胜负；而它对随机走子能 7:2，说明它并不是「只会缩」。
> ⚠️ 样本只有 10 局/档，**这是「方向对了」的证据，不是精确胜率**。

### 6.4 有意不做的

| 项 | 理由 |
|---|---|
| **MCTS / 自我对弈训练** | 0.8 秒预算下模拟次数太少、方差盖过收益；真要做得先有一台常驻的训练管线，那是另一个项目 |
| **给明棋加置换表 / 静态搜索（quiescence）** | 明棋的分支因子大、单局手数长，现在的迭代加深已经能吃满预算；再加一层是「用复杂度换一点点棋力」，等有实测说「明棋人机还是不够」再说 |
| **让 AI 记住上一手自己走过什么**（防重复走子） | 现在的 `best_move` 是**无状态**的（每次只看视图），加记忆要改接口与落盘；而且「和棋」不是这一轮要修的问题 |

（阵库编号 1~4 与「三节阵」，每条都带一句布阵思路，如双喜临门「两头皆师，后续不同，
一跟炸旅，一跟旅炸；三将亡而旗不亮」）。

**核对过的事**：这五套的 5 个行营位置恰好落在本作 `CAMP_CELLS` 上、军旗都在
`HQ_CELLS`、地雷都在最后两排、炸弹都不在第一排 —— 即**逐格对得上本作的布阵约束**，
所以可以直接抄进引擎（`_PRESET_ROWS`），不必手工调整。

⚠️ **炸弹在阵库里有两种写法**（飞花逐月与三节阵写「弹」，其余三套写「炸」）——
照抄原文，两种都映射到 `ZHADAN`，别去「统一」它们。

⚠️ **有意不做的**：
- **「记住上次布局」**：要跨房间/跨会话存偏好，而本项目所有游戏都没有「记住上次选择」
  的先例（扫雷难度、军棋玩法、深空休眠地图一律每房重选）。加一个只对军棋生效的
  偏好存储，是为一处便利开一条新基础设施。
- **布阵倒计时**：本项目所有游戏都没有走子限时（`设计.md` 已记过），布阵拖时间由
  房间回收兜底。
