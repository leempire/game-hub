# 扫雷（竞技淘汰制）设计文档

- 屏：`app/src/screens/MineScreen.tsx`　引擎：`server/app/game/minesweeper.py`
- 人数 1-4（1 人可开，单机刷分）｜无 AI｜按难度 1/2/3 条命 + 结算排名

## 玩法

多人同盘竞速挖雷，**各翻各的、同时进行**（没有回合，也就没有「移交回合」这回事）。
每人按难度有 1/2/3 条命，踩雷扣一条命，**命扣完才淘汰**（观战到本局结束），
其余玩家继续。全员淘汰或所有安全格被翻开时结算。

| 难度 | 棋盘 | 雷数 | 每人命数 |
|---|---|---|---|
| 初级 | 9×9 | 10 | 1 |
| 中级 | 16×16 | 40 | 2 |
| 高级 | 30×16 | 99 | 3 |

命数与盘面大小同向：盘越大、信息越散，越容易看漏，容错也就越多。初级一条命
等于「一次失误就出局」，和「小盘信息少、踩雷基本是看错」的体感匹配。

主动弃权（认输）与断线超时**直接淘汰，不消耗剩余生命**——这两种情况人已经不在
局里了，留着命没有意义；服务端会把 `lives_left` 一并清零，界面不会出现
「已淘汰但还剩 2 条命」。

## 交互设计

### 三条输入路径：翻开 / 插旗 / chord

移动端**没有**右键，因此顶栏保留「翻开 / 插旗」模式开关（意图明确、误触少），
长按插旗是并列的第二条路径，chord 则是数字格上的一次点击。

| 操作 | 行为 |
|---|---|
| 点未翻开格（翻开模式） | 揭开（空白自动展开）；问号格也可以直接翻开 |
| 长按未翻开格（~400ms） | 三态轮换：空 → 旗 → 问号 → 空 |
| 点未翻开格（插旗模式） | 同上三态轮换 |
| 点已插旗格（翻开模式） | **无效**（防误触，需切到插旗模式继续轮换） |
| 点已翻开的数字格（翻开模式） | chord：周围旗数 == 数字时一次揭开其余邻格 |

**三态标记（v1.18.1）**：问号是**纯笔记**——不进 `flagged` 集合、不参与 chord
计数与通关判定、不阻挡翻开，翻开时自动清掉。只有旗子才是「确定有雷」的断言。
服务端 `flag()` 返回 `state ∈ flag|question|none`，广播 `flagged` 消息同时带
`flagged`（兼容旧客户端）与 `state`/`questioned`。桌面扫雷的三态轮换比
「切模式再点一次才能拔旗」少一步操作，也保住了翻开模式下点旗格无效的防误触。

- **长按插旗**：阈值 400ms（`delayLongPress`）。长按触发后置
  `longPressConsumedRef`，`onPress` 见标记即消费掉本次触摸并返回——否则一次
  长按会「插旗 + 翻开」双动作。`onPressIn` 每次触摸开始先复位标记，避免标记
  残留吞掉下一次点击。
- **chord**：点已翻开的数字格。服务端校验「该格已翻开且是数字」且「周围旗数
  等于数字」，不满足**静默忽略**（正常但无效果的操作不报错）。满足时把其余
  未翻开且未插旗的邻格逐格走与 reveal 相同的裁决路径（`_reveal_cell`），所以
  **插错旗会踩雷淘汰自己**——这是 chord 的固有风险，也是它的价值。
- 长按与五子棋的「长按放大镜」不冲突：两者在不同对局屏，同一屏内长按只有一种含义。
- 「翻开模式下点旗格无效」是刻意设计：移动端手指粗，误点旗格会把已标好的雷
  取消掉，代价远大于收益。

### 玩家统计条（可折叠）

4 人局横排放不下，故默认**展开**（2 人一行、4 人自动折两行），右侧 chevron
可收起成一行（`testID="mine-players-toggle"`）。单人局无 toggle。

每个存活玩家显示 `♥ 剩余/总数`（`testID="mine-lives-N"`）：心形图标 + 数字。
**颜色不是唯一通道**——命只剩一条时图标从实心变空心、数字转琥珀色，配合数字
本身，色觉障碍者与「一眼扫过」都能读出紧张程度。淘汰者显示「已淘汰」。

### 棋盘适配：统一 44px + 双向滑动

格子尺寸是**固定 44px**（Apple HIG 44pt / WCAG 2.5.5 AAA），三个难度完全一致，
不再按屏宽缩放。棋盘放不下就**双向滑动**（外层横向 ScrollView 套内层纵向）。

| 难度 | 棋盘像素 | 390×844 屏上的表现 |
|---|---|---|
| 初级 | 396 × 396 | 轻微横滑 |
| 中级 | 704 × 704 | 双向滑动 |
| 高级 | 1320 × 640 | 双向滑动 |

**为什么改**：原来是「按屏宽缩放、下限 22px」，初级 39px 尚可，中级和高级都被
压到 **22px**——连 WCAG AA 的 24px 底线都不到，手指点不准，这是「容易误触」的
根源。既然可以滑动，就不该再为了塞进屏幕牺牲触控尺寸。

**踩坑（勿回退）**：外层横向 ScrollView 的 `contentContainerStyle` **不能**加
`alignItems: 'center'`。横向 ScrollView 的内容容器是 row，`alignItems` 管的是
交叉轴（高度）——一旦居中，内层纵向 ScrollView 就按内容高度（棋盘全高）撑开，
等于没有高度约束，`overflow-y` 永远不触发，**纵向滑动直接失效**。
用默认的 stretch 让内层撑满可视高，居中交给内层的 contentContainer
（`flexGrow: 1` + center）。回归：`test/e2e_mine_board.py` 第 5~6 步。

### 反馈

- 翻开：10ms 震动；长按插旗：10ms 震动；踩雷：15ms + 淘汰动画。
- 正确标雷计入个人统计（只有插在真雷上的旗才计分）。

## 状态与协议

- `reveal` → 广播 `revealed`（含 `cells` / `hit_mine` / `lost_life` / `lives_left` /
  `eliminated` / 统计）。`lost_life` 为真但 `eliminated` 为假时**再补一条
  `life_lost`**（带剩余命数），否则客户端只能把「踩雷」一律当成淘汰。
- `sync` / `game_start` 的 `game` 载荷带 `lives`（本局每人几条）、每个玩家的
  `lives_left`、`difficulty`、`daily`、`revealed`、`flagged`、`questioned`。
- `flag` → 广播 `flagged`：`{x, y, flagged, questioned, state, seat}`，`state` 是三态
  （`flag` / `question` / `none`）。问号不进 `flagged` 集合。
- `chord` → 走与 reveal 相同的裁决路径（`_reveal_cell` 逐格判定），广播同样形状的
  `revealed`（多带 `chord: true`）；不满足条件时**不广播、不回错**。
- 踩雷扣完最后一条命 → 广播 `player_eliminated`（含昵称，供其余玩家看到
  「谁出局了」）；命没扣完只播 `life_lost`。
- 认输 = 主动弃权淘汰，走 `player_eliminated` 而非 `game_over`。
- 协议细节见 `docs/接口协议.md` 第八节。

## 结算与排名

全员淘汰或安全格翻完时结算。排名规则（`mine_compute_ranking`）：

1. 幸存者排前，组内先比**正确标雷数**，再比**翻开格数**，最后比**用时**（短者在前）；
2. 淘汰者按淘汰先后垫底。

**用时（`elapsed_ms`）是 v1.18 补的**：游戏定位是「竞速」，但在此之前排名
完全不看时间，慢慢插旗的人可能赢过快的人。计时**只在房间层写入**（引擎不读墙钟，
要能在单测里瞬间跑完）：语义是「本局第一次翻开 → 该玩家最后一次翻开」的跨度，
不是「从开局到现在」——后者会把等待时间算进去，也会让先开始玩的人在平局时吃亏。
全程没翻过格子的人为 `null`，界面不显示 `0.0 秒`。

结算面板显示每人的标雷数、翻格数与用时——把「为什么是这个名次」摊开给玩家看。

### 每日固定盘与最佳用时（v1.18.1）

- **每日固定盘**（房规 `daily`，store `mine_daily`）：雷盘种子取 UTC 日期
  `yyyymmdd`（`create_game(seed=..., daily=True)`），同一天同一难度所有人拿到
  **同一份种子**。第一下翻开的 3×3 安全区仍随落点移动，所以是「同种子」而不是
  逐格完全相同的雷盘——这是 `generate_mines` 的安全区语义决定的，文档不要写成
  「每次完全一样」。顶栏难度胶囊会标「· 今日盘」。
- **各难度最佳用时**：扫雷战绩的 `results_json` 从 v1.18.1 起带 `elapsed_ms` 与
  `difficulty`，`GET /api/history/stats` 聚合成 `best_times.{beginner|intermediate|advanced}`。
  对局屏顶栏奖杯旁显示当前难度的最佳，结算面板在破纪录时显示「新纪录！」。
  **老记录缺这两项，直接跳过**，最佳用时从新记录开始累积。

## 配色

- 数字色是 `minesweeper.ts` 的 `NUMBER_COLORS`（对局屏与战绩回放共用），沿用传统
  色相但每档都加深到在翻开格 `#EDEFF2` 上 ≥4.8:1。**经典配色里 5 号琥珀 `#FF8F00`
  只有 1.99:1**——那不是色觉问题，是所有人都看不清。
- 旗子 `#B91C1C`（在覆盖格 `#CBD5E1` 上 4.36:1）；踩中的雷格 `MINE_CELL` 同色，
  因为上面压着白色警示图标，需要白字 ≥4.5:1（原 `#EF4444` 只有 3.76）。

## 已知坑（勿回退）

- **测试勿依赖随机雷盘**：单测涉及随机布局时要用引擎保证的确定量（如首翻格
  必安全）或从状态里筛确定目标，不要 `list(set)` 取下标或 reveal 随机格
  （`test_ranking_order` 曾因此 flaky）。
- 断线超时（120s）在扫雷里是**淘汰**而非判负——这是竞技淘汰制的语义，与其他
  游戏的「断线判负」不同。弃权/断线淘汰时要把 `lives_left` 一起清零，否则界面
  会显示「已淘汰但还剩 2 条命」。
- **踩雷 ≠ 淘汰**（v1.7.2 起）：`_reveal_cell` 扣命、命扣完才置 `alive=False`。
  任何「踩雷就淘汰」的旧假设都要重新看一遍——引擎、WS 广播、客户端提示三处
  是分开的（`lost_life` / `life_lost` vs `eliminated` / `player_eliminated`）。
- **chord 必须复用 `_reveal_cell`**，不要另写一份雷盘判定——踩雷/统计/胜负只有
  一条裁决路径，否则两条路会漂移。
- **长按必须消费本次触摸**：`onLongPress` 后 `onPress` 会（在部分平台/交互下）
  再触发一次翻开，导致「插旗 + 翻开」双动作。用 `longPressConsumedRef` 在
  `onLongPress` 里置位、`onPress` 里消费，`onPressIn` 复位。
- **已翻开的数字格不能 `disabled`**：chord 要点它。禁用条件只留「已淘汰」。
- **chord 无效果时不要回 error**：条件不满足（数字格未翻开 / 旗数不符）是正常
  操作，前端与服务端都静默。
