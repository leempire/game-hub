# 谁是卧底设计

首版面向 4–8 名玩家（至少一名真人，可添加 AI 人机），各用一台设备，通过 GameHub 的「多人桌游」进入房间完成看词、描述、投票和结算。对局交流限定为轮到本人时提交的一条文字线索。规则来源和版本差异见[增强调研](增强调研.md)。

## 联机方式的取舍

| 方案 | 体验与开发取舍 |
| --- | --- |
| 外部语音，房内发词和投票 | 接入成本最低，适合同处一地或已在通话中的玩家。远程陌生设备还要另约通话。 |
| 站内预设描述词 | 操作快，便于将来加入人机。每组题都要编写足够多的合理描述，自由联想空间较小。 |
| **采用站内轮流输入一句线索** | 保留自由描述，让手机和浏览器玩家能在房内打完整局。文字动作限定在自己的发言回合，随对局状态同步。 |

白板、爆词翻盘、独立文字讨论回合、自定义词包留作扩展。

## 首版规则

1. **开局发词。** 房间容纳 4–8 名玩家（至少一名真人，可添加 AI 人机），沿用房主开局、其他人先准备的流程。4–6 人分配 1 名卧底，7–8 人分配 2 名。服务端随机抽取一组相近词，随机指定哪一个是平民词，再洗牌分配阵营。玩家只收到自己的词，需要从描述推断阵营。首个发言座位随机，以后各轮轮换起点。
2. **轮流描述。** 每名存活玩家有 45 秒，最多提交一条 1–60 字的纯文本线索。服务端检验发言资格、长度以及规范化后是否出现本人的完整词语。拒绝时保留草稿并提示原因，计时继续。只使用本人的词校验，避免借错误响应试探另一组词。语义是否贴切由玩家判断。超时记为跳过。
3. **同时投票。** 活着的人可以用 30 秒选中另一位存活玩家并确认。确认后锁票，超时记为弃票。投票期间公开已提交人数，结束后公开各候选人的汇总票数。唯一最高票出局，随即揭晓该玩家的阵营。
4. **平票重投。** 最高票并列时开启一次 30 秒重投，所有有合法候选人的存活玩家都可投，候选人限并列者且排除本人。重投再次并列或任一轮投票没有有效票，本轮无人出局。
5. **胜负。** 卧底全部出局，平民胜。剩余卧底至少一名且人数追平或超过平民，卧底胜。先检查阵营胜负，再在第 8 轮结束仍无胜负时判和。阵营胜负计入正常参与者战绩，被投出的队友仍可随阵营获胜，主动退出或断线超时记个人负局。
6. **结算。** 向本局参赛者揭晓两个词、阵营与胜负。房间回到 `waiting`，非房主重新准备后可续开。自编面向中文玩家的日常词对，例如「雨伞 / 雨衣」，从服务端词库发放，同房续开避开刚用过的一组。

以上人数、时长、重投和第 8 轮和局是首版默认值。后续需要开放可调房规时，由 `room_settings.py` 注册并在等待大厅选择。

## 对局状态与房间接入

- **纯引擎。** 在 `server/app/game/undercover.py` 处理发词、线索、选票、淘汰、胜负和逐人视图。房间层传入开局名单、词对、随机源和超时事件。引擎只处理数据和事件。对局阶段放在 `game_state`，外层房间继续使用 `waiting` 和 `playing`。
- **期限和动作。** 扩展 `room_timing.py` 的单房截止任务，按阶段计时，持久化剩余毫秒。发言轮到下一人时刷新阶段标识。每次投票或重投共用同一个阶段标识，避免先到的票把其他同时提交的票判旧。对局动作校验成员、资格、对局标识、阶段标识以及服务端截止时间。每位玩家在同一阶段的重复请求最多生效一次，过期请求补回当前视图。状态先完成更新和落盘，再走现有发送链下发。
- **断线与退房。** 单人掉线沿用 120 秒保座，其他人继续。阶段到期照常跳过该人的线索或把未投票记为弃票。保座内重连恢复本人词、已提交状态和当前阶段。主动退房及保座超时共用退出裁决，重算当前发言顺序、候选人和胜负。投向已退出者的选票作废，受影响玩家可在原期限内重投。出局者可留在对局页只读，回大厅后房间页按 `in_game` 判断是否自动入局。全员离线暂停阶段推进，房间沿用空闲回收。热重启从持久化剩余时间恢复，等待首位在局玩家回来再继续。
- **终局与战绩。** 沿用统一回大厅与幂等战绩回调。用开局名单生成逐人结果，退出导致大厅名单变化时仍保留当局参与记录。全体弃局按中止处理。终局为参赛者保存两个词、阵营、淘汰顺序、汇总票数和胜负摘要。局内自由文本和个人投票选择只用于当前局，终局后从房间状态清除。公开战绩只使用裁剪后的整体结果。

## WebSocket 和信息权限

| 接口 | 内容 |
| --- | --- |
| `undercover_clue` | 对局标识、阶段标识、线索文本。仅当前发言人可提交。 |
| `undercover_vote` | 对局标识、阶段标识、目标玩家 ID。仅存活玩家可投。 |
| `game_start` / `sync` / `undercover_state` | 复用逐人视图。公共部分包含轮次、阶段、剩余时间、发言顺序、线索和已揭晓的淘汰结果。私人部分只有本人词和本人可用操作、投票状态。 |
| `game_over` | 向参赛者下发终局摘要并广播大厅状态。大厅状态保持现有房间对象结构。 |

逐人视图和终局摘要各自用字段白名单构造。用实际 WebSocket 和 HTTP 返回验证权限，重点检查房主、其他阵营、出局玩家、非成员、重连和匿名战绩。词对编号、抽取状态、未揭晓身份和未公布票况属于服务端状态。

## 移动端与接入顺序

- **对局屏。** 复用 `GameShell` 与 `GameResult`。顶部显示当前阶段、轮到谁和剩余秒数，下方为可折叠的本人词卡、可滚动的线索列表和固定操作栏。只有轮到自己时显示输入和发送，投票用玩家列表和独立确认按钮。切到后台时收起词卡。状态用文字与图标表达，主按钮触控区至少 44pt，沿用已有键盘避让和 Android、Web 返回确认。
- **先引擎与词库。** 用固定词对和随机源验证不同人数的分配、轮转、超时、弃票、平票重投、两阵营胜负和第 8 轮和局。
- **再接房间、传输和战绩。** 覆盖建房人数、准备、重连、主动退房、超时、热重启、旧局请求、同时投票和战绩幂等。复用现有入房、好友邀请和返回房间流程。6 位房间号继续作为分享入口。
- **最后接三端入口。** 更新 `games.tsx`、图标、`help.tsx`、房间人数与入口、客户端消息类型、战绩快照。三处路由同步接线，并纳入 `backGuard.PROTECTED_SCREENS` 与 `onConfirmLeave`。用四个独立浏览器会话验收发词隐私、完整回合、断线恢复、终局回房和续开，另验证小屏和 Android 真机键盘。按项目门禁跑后端 pytest、前端 lint 与类型检查、视觉审计和相关 E2E，并同步接口协议、使用指南、设计索引和测试矩阵。


## AI 人机

房主在等待大厅沿用 add_bot / remove_bot 增删人机，可一真人加三人机开局，最多八席；AI 不设难度档位。模型接入、账户串行锁、开局门槛、用量结算和失败流水统一由 [通用 AI 服务](../../AI接入与积分.md)负责。每局固定开局房主为支付人，房主转移不转移当局费用。

`undercover_agent.py` 只接收 `undercover.view_for` 的结果及当前 bot ID，系统提示约束线索长度、不能爆词和合法候选人；玩家文字作为不可信数据处理。`undercover_bots.py` 每房间一个串行 worker，依据阶段挑选有权操作的人机，同阶段各人机各投一次，不因别人的票导致重复调用。所有动作仍走 `room_manager.undercover_action`，不得绕过超时、阶段、线索或候选校验。

当局真人全部离线时暂停 AI 和倒计时，不因机器人在线而继续消耗。仍留在局内的真人即使已淘汰，也能观看人机继续完成比赛；纯真人房维持原有的存活真人在线规则。已发送的请求不会因断线或换阶段而取消结算，返回时检查房间对象、对局状态对象和 phase_id，过期答案丢弃。持久化请求标识和已尝试标记，热重启不重复发起同一次付费动作；中断的发言由阶段超时处理。模型不可用、非法回答或积分不足时通知支付人，人机按现有超时跳过或弃票，不编造免费替代线索。
