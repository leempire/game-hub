# 谁是卧底玩法与实现参考

调研时间 2026-11-25。以中英文检索核对节目方、游戏开发者和运营方发布的资料。

## 一、GameHub 首版建议（草案）

建议采用 4–8 名真人的好友房。玩家各用自己的设备收词，在当前回合提交一条自由文字线索，随后投票。服务端发词、推进回合、统计票数并裁定胜负。房主身份只用于房间管理。分配与人数参考 JoyPip，文字线索参考 Word Spy，单独收词参考 Yanstar 和 kawu。[JoyPip 规则](https://joypip.com/zh-cn/game/undercover/) · [Word Spy 规则](https://partygamehub.app/games/word-spy/) · [Yanstar 私人房说明](https://www.yanstarstudio.com/undercover-faq) · [kawu 联机说明](https://kawu.com/zh/shei-shi-wodi)

| 草案选择 | 理由 |
| --- | --- |
| 4–6 人设一名卧底，7–8 人设两名卧底。所有玩家开局只看自己的词，本局词对和阵营分配保持固定 | 小局容易凑人，较大的局有两名卧底。每个人都要根据线索推断自己是哪一方，卧底也需要靠线索辨认同伴。[JoyPip 规则](https://joypip.com/zh-cn/game/undercover/) · [Yanstar 发词规则](https://www.yanstarstudio.com/undercover-how-to-play) |
| 每名存活玩家依次提交一条简短的自由文字线索，随后直接投票 | 玩家可以回看线索并自行找出差异，不依赖麦克风或语音通话。自由输入保留同一个词可以有多种描述的空间。[Word Spy 联机说明](https://partygamehub.app/games/word-spy/) |
| 存活玩家各投一名其他存活玩家。唯一最高票者出局并公开阵营。最高票并列时仅在并列者间重投一次，重投仍并列则本轮无人出局 | 隐去投票进行中的实时票数，结算时再公布候选人的得票。一次重投给玩家改判机会，也给票务阶段确定的结束点。kawu 的变体还会请并列者补述，草案省去这一步。[kawu 平票说明](https://kawu.com/zh/shei-shi-wodi) · [Undercover Word 投票示例](https://www.undercoverword.com/how-to-play) |
| 每轮结算先判卧底是否全部出局，满足则平民赢。仍有卧底且其存活人数达到或超过平民，卧底赢。第 8 轮结算后若两个阵营仍未达成胜利条件，判和局 | 阵营人数追平是已有玩法。第 8 轮判和是 GameHub 草案，用来限制反复平票或弃票造成的长局。轮数及判和对实战节奏的影响要靠试打验证。[kawu 胜负规则](https://kawu.com/zh/shei-shi-wodi) · [JoyPip 八轮规则](https://joypip.com/zh-cn/game/undercover/) |
| 投票淘汰者继续看本局公开信息，终局统一公开两词和所有玩家阵营 | 观战可保留参与感，局中仍能让存活玩家继续从线索推理。[kawu 观战说明](https://kawu.com/zh/shei-shi-wodi) · [Yanstar 规则](https://www.yanstarstudio.com/undercover-how-to-play) |

建议把白板、爆词和显式身份变体留待后续试打。它们分别增加独立胜负分支、额外动作和另一种开局信息，优先用核心循环验证词对与节奏。同机轮传适合同场聚会，站外语音是其他产品的联机方式。GameHub 对局交流限定为按回合提交的文字线索，玩家投票时可以回看。临时加人、人机、自定义题库和特殊角色可待好友房跑通后再评估。[快手规则](https://sogame.kuaishou.com/about/undercover) · [Yanstar 规则](https://www.yanstarstudio.com/undercover-how-to-play) · [kawu 联机说明](https://kawu.com/zh/shei-shi-wodi)

## 二、经交叉验证的基本玩法

大多数玩家拿同一个词，少数玩家拿一个意思相近的词。玩家轮流描述，随后用投票选出怀疑对象，游戏根据淘汰结果继续或结束。线索要让同词玩家看得懂，又要避免直接公开自己的词。快手还要求描述与词有关且不能使用词里的字。Yanstar 和 kawu 明确平民与卧底开局看词猜身份。[快手规则](https://sogame.kuaishou.com/about/undercover) · [Yanstar 规则](https://www.yanstarstudio.com/undercover-how-to-play) · [kawu 规则](https://kawu.com/zh/shei-shi-wodi)

《快乐大本营》公开节目页可核实节目有名为「谁是卧底」的环节。节目页只有片段信息，人数、投票门槛及终局条件可从各自发布规则的产品核对。[芒果TV 节目片段](https://w.mgtv.com/b/45300/3192882.html?lang=zh-cn&showId=)

## 四、联机交互与小屏呈现

- **各自收词**。Yanstar 的私人房支持分享链接或房间号，也提供同机轮传模式。kawu 联机房让玩家各看各的词，场外用语音或视频发言。GameHub 草案沿用已有房间入口，在不同设备上显示各自的词。[Yanstar 私人房说明](https://www.yanstarstudio.com/undercover-faq) · [kawu 联机说明](https://kawu.com/zh/shei-shi-wodi) · [GameHub 移动端体验设计方法论](../../移动端体验设计方法论.md)
- **让玩家知道轮到谁**。Word Spy 的在线模式按顺序输入短线索，JoyPip 则使用可点选的预设线索。竖屏建议沿用 GameShell 顶栏，局内按座位展示发言、等待及出局状态，下部保留当前阶段的主要操作，投票时仍能看本轮线索。[Word Spy 规则](https://partygamehub.app/games/word-spy/) · [JoyPip 规则](https://joypip.com/zh-cn/game/undercover/) · [GameHub 游戏设计规范](../README.md)
- **用卡片区分个人词语、线索和结果**。Undercover Word 的界面示例把私人翻词、当前发言人、投票进度和结算分开呈现。GameHub 可沿用主题、字号和触屏反馈，个人词卡点按显隐，阶段与出局状态用文字随卡片呈现。投票时可显示已投总人数，到结算再显示票数和出局结果。[Undercover Word 界面示例](https://www.undercoverword.com/how-to-play) · [GameHub 游戏设计规范](../README.md)

## 五、对实现的影响

- **状态与视图**。服务端保存词对、座位阵营、存活状态、线索、选票和轮次。开局、动作响应及重连都按接收者生成视图。公共视图可包含阶段、截止时间、当前发言人、线索与已结算票数。当前玩家的词和未公开选票仅随本人视图下发。投票淘汰可公开阵营，终局再揭晓词和剩余身份。[GameHub 接口协议](../../接口协议.md)
- **阶段推进**。用私发词 → 按存活座位顺序描述 → 统一投票 → 必要时重投 → 结算或下一轮。服务端校验阶段、轮次、座位和候选资格。倒计时暂按每人发言 45 秒、每次投票或重投 30 秒试打。发言超时跳过，投票超时按弃票处理，零张有效票时本轮无人出局。重投按并列候选及存活且非本人校验，遇到没有合法候选的席位自动跳过。重连恢复当前阶段和本人词。长断线退局如何影响阵营人数适合结合现有房间实现后定。[GameHub 接口协议](../../接口协议.md) · [GameHub 游戏设计规范](../README.md)
- **针对中文词对试打**。词库使用自编、常见、可从相似角度描述且有明显差异的词对，例如「豆浆／燕麦奶」。服务端可以拦截直接写出自己完整词语的线索，模糊提示和同音仍由玩家判断。分别试打 4、6、7、8 人档，关注首轮淘汰偏差、平票重投频率和和局比例，再定轮数上限与倒计时。[快手线索规则](https://sogame.kuaishou.com/about/undercover) · [Word Spy 线索说明](https://partygamehub.app/games/word-spy/)

## 六、AI 人机与用量计费（2026-11-28）

- [CoMet 研究](https://arxiv.org/pdf/2505.18218v1)和 [CK-Arena](https://arxiv.org/html/2505.17512v2)都采用给 Agent 分别发私有词、依据公共描述推断和投票的方式。采纳独立玩家视图，不把完整引擎状态交给模型；不预告阵营，不共享其他人机的私有上下文。保留真人自由文字线索，不采用固定描述菜单。
- [方舟 Chat API](https://ark.volcengine.com/region:cn-beijing/docs/chat-api)与 [DeepSeek-V4.1-Flash 文档](https://ark.volcengine.com/region:cn-beijing/docs/deepseek-v4-1-flash)说明 JSON 输出、用量和推理参数；[上下文缓存文档](https://console.volcengine.com/ark/region:cn-beijing/docs/context-cache)说明缓存命中需以实际 token 数据为准。使用 Agent Plan Chat Completions、指定 economy 模型和 `reasoning_effort=low`，稳定系统提示前缀，不人为声称命中缓存。
- 采用每个阶段每个 bot 至多一次模型请求，不自动重试；设置输出上限和超时。所有返回先按实际 usage 扣费，再解析动作。非法回答和过期回答也产生实际消耗，仍扣费，过期动作不入引擎。未知用量记为 unknown 供运维核对，不按估算 token 扣费。
- 调用与积分封装在通用 `ai_service.py` / `ai_credits.py`，游戏 Agent 只构造私有上下文、选择动作。未采用在纯引擎内直接请求模型的方式，避免网络和账号权限污染规则层。
- 不开放积分获取渠道。管理员设置余额；UI 只显示整数，不公开 token 单价和算法。积分整体采用原金额单位的 100 倍，含付费人机开局门槛为 100；纯真人及本地算法人机免门槛、免扣费。余额低于 0 才阻断局内后续调用，等于 0 仍允许最后一次调用。
