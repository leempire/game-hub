# 翻转棋（黑白棋）设计文档

- 屏：`app/src/screens/ReversiScreen.tsx`　引擎：`server/app/game/reversi.py`　AI：`server/app/game/reversi_ai.py`
- 人数 2（须满员开局）｜支持人机｜战绩落库

## 玩法

8×8 棋盘，黑先。落子后夹在中间的对方棋子全部翻成己方颜色，**必须能翻转**
才可落子。双方均无合法着时结束，子多者胜。

## 交互设计

### 合法着提示

- 当前可落子的位置显示半透明圆点（`legalMoves`，客户端用与服务端同一套
  规则计算，仅用于提示；服务端仍是唯一裁决方）。
- 提示点是**脉冲**的（v1.5.2 起）：所有提示点共享同一个 `Animated.Value`，
  同步缩放 **1 → 1.25 → 1**，**限次 3 轮**（每轮 1.6s = 800ms 放大 + 800ms 缩回，
  总 4.8s < 5s），跑完停在常亮态。限次是硬要求——自动播放且超过 5 秒的运动必须
  能停（WCAG 2.2.2）；也不用高对比闪烁（WCAG 2.3.1）。缩放幅度属于「小元素的
  轻微变化」（方法论 §2）。`useNativeDriver: Platform.OS !== 'web'`。
  原实现是静态圆点。共享一个 `Animated.Value` 比每个点各跑一条动画省得多，
  视觉上也整齐。
- 悬停/按下显示「会翻转哪些子」的预览（`preview`）。

这是本游戏最重要的交互：黑白棋新手最大的障碍是「看不出哪里能下」，
把合法着直接标出来比写十行规则文案都有效。

### 动画

- 新落子：淡入。
- 被翻转的棋子：**错峰翻转**。`animFlipped` 是 `Map<坐标, 错峰序号>`（用 Map
  而非 Set：错峰要按服务端下发的翻转顺序逐个延迟，Set 会丢顺序），每枚延迟
  `65ms`、单枚 200ms（收 100ms + 放 100ms，落在方法论 §2 的 200-300ms 区间），
  让「谁翻了谁」可被眼睛追踪。**错峰总跨度封顶 400ms**，一次翻十几枚也不会拖到
  1 秒以上（§2「克制有度」），超过上限的棋子并到同一拍。
  原实现是 120+120ms 且**没有错峰**（全部同时翻，一次翻 8 枚会「啪」地全变），
  本次补上错峰并压缩单枚时长。
- 非己方回合不显示任何可操作提示，避免误以为可以落子。

### 坐标标注

8×8 棋盘带行列标注：**列 A-H 在顶部、行 1-8 在左侧**。复盘时用户可以说「D3」，
不用再数「从左数第四列往下第三行」。字号 `fontSize.xs`（12px，≥ 项目可见文字
10px 下限），颜色 `colors.textMuted`（vs 浅底 ≈4.6:1）——它是「可承载信息的
最低一档」，`textFaint`（2.54:1）禁止承载信息。棋盘宽度计算已扣掉左侧标注列宽
（`AXIS_W = 16`），避免小屏横向溢出。

### 反馈

- 落子 10ms 震动（原生）；轮到己方 30ms 震动 + 回合文字脉冲。
- 翻转棋子数在顶栏比分上即时更新。

## 状态与协议

- `game_start` / `sync` 逐人下发（各自带 `your_color`）。
- 走子 → 广播 `move`（含 `flipped` 坐标数组）。
- 对方无合法着时服务端**自动 pass**，广播 `pass`；双方都无合法着时
  `game_over`（`reason: 'score'`）。
- 人机：`reversi_ai.best_move`；无合法着时 bot 也会走 pass 分支。

## 结算

`reversi_make_move` 在双方均无合法着时调 `_set_game_over(room, winner, 'score')`，
结算弹窗展示最终比分。

## 最近一步标记

最后一手落子的格子上压一枚**黄点 + 深墨描边**（`testID="reversi-last-mark"`），
与五子棋 / 点格棋 / 中国象棋共用同一套视觉语言（`theme.ts` 的
`lastMoveMark` / `lastMoveMarkEdge`）。黄点压在绿底 3.63:1、压在白子上只有
1.29:1，**描边是让它三种背景都成形的必需通道**。

> **踩坑（勿回退）**：渲染端一直有这段标记代码，但 `handleMove` 只更新
> `board`/`next`/`score`，**没有往 `prev.moves` 里追加**——`lastMove` 永远是
> `null`，标记从来没画出来过（等于死代码）。改棋盘类屏幕的落子处理时，
> 顺手确认 `moves` 有没有被维护。回归：`test/e2e_reversi_smoke.py` 第 5 步。

## 配色

- 棋盘绿 `theme.reversiBoard`（`#2E7D32`）——对局屏与战绩回放共用，之前两处
  各写了一个绿（`#2E7D32` / `#157A46`），已收口。
- **「最后落子」标记是黄点 `#FFD54F` + 深墨描边**。单色做不到：黄点在绿底上 3.63:1
  够用，但压在白子上只有 1.29:1；那圈深墨描边保证「黑子 / 白子 / 绿底」三种情况
  都看得见。原标记 `#FF5722` 在绿底上只有 1.62:1。
- **坐标标注文字** `colors.textMuted`（vs 浅底 ≈4.6:1）。
- **合法着提示是空心环**（`colors.stoneBlack` / `colors.stoneWhite` 描边，不满填）。
  原先是半透明实心点 `rgba(26,26,26,0.35)` / `rgba(200,200,200,0.5)`，压在棋盘绿
  `#2E7D32` 上只有 **1.51:1**（低于图形 3:1）；改成不透明描边的空心环后实测
  **黑 3.39:1 / 白 4.70:1**。空心还顺带给了形状通道——环 ≠ 实心棋子，不会看混。
  注意 `textMuted` 对棋盘绿只有 1.06:1，换色走不通，只能走「不透明 + 描边」。

## 已知坑（勿回退）

- **pass 计数**：`gs["pass_count"]` 用于判定终局，客户端不要自行推断 pass，
  一律以服务端广播为准。
- 与五子棋共用「终局必须落 `finished`」的房间状态契约，新增终局分支时同样适用。
