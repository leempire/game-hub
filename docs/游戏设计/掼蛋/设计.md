# 掼蛋牌桌设计

首版为四人固定对家、从 2 打过 A 的联机房。牌桌以现有斗地主界面为参照，沿用牌面、点选抬起、中央公牌与放大选牌。Android、手机浏览器和电脑浏览器使用同一套座位与对局状态，手机竖屏可完成整场。规则差异和采用理由见 [增强调研](增强调研.md)。

## 布局取舍

| 方案 | 适合 | 取舍 |
| --- | --- | --- |
| 四方牌桌和单排手牌，手机横屏入局 | 电脑及横屏短边足够的设备 | 桌面结构直观，手机玩家需要先转屏，短高视口仍容易挤压中央。 |
| 顶部三席和单排横滑手牌 | 手牌很少的牌局 | 页面简洁，满手 27 张时看牌需要来回滑动，跨屏选同花顺时难以核对所选。 |
| **按可用空间重排四席与手牌** | 电脑、手机竖屏、手机横屏和窄浏览器窗口 | 大窗保留四方桌，窄窗与短窗各有紧凑布局，需要验证牌角热区和多行选择。 |

建议采用第三种。四席的相对位置固定。本人在下、搭档在对面，上家在左、下家在右。四席的行动顺序从本人起为「你 → 右侧下家 → 对家 → 左侧上家」。座位同时显示昵称、自己或队友标记、行动或完成状态。对手及搭档的余牌到报牌门槛后显示具体数值。

### 信息和尺寸

- **顶栏。** 复用 `GameShell` 的房号、连接状态和帮助入口。比分条显示第几副、两队级别，以及当前打几、哪队在打这个级别。窄屏将三张座位卡并排，队友居中，昵称截断时保留完整读屏标签。
- **中央。** 只常显当前要压的有效一手，附牌型、出牌人和回合提示。过牌标在各席，中央有效牌保持，直到有人压过或新一圈开始。贡还牌期间中央原位改为「谁给谁、在等谁」，出牌栏切换成还贡操作。接风时直接显示「小林接风，重新领出」。短高窗口用紧凑座位条和牌面序列，公牌过长就换行或缩成带花色的角标。
- **手牌和动作。** 窄屏把「过牌 / 提示 / 出牌」放在手牌下沿，直接可触达。短高横屏可将三枚按钮移至手牌侧边，以实际剩给手牌的宽度计算排数。窗口缩放、分屏、旋转和字体变化只重排组件，手中已选牌按实体 ID 保留。必要时让细节区或大牌网格独立滚动，手牌操作栏保持可见。
- **手牌宽度预算。** 按扣除安全区、边距和侧栏后的实测尺寸算。紧凑牌面宽 `48`，独立水平命中区步长从 `24` 起，容纳 `n` 张的最低宽度为 `48 + 24 × (n − 1)`。320 宽扣两侧各 12 后为 296，采用 `9/9/9`。390 宽同样扣边后为 366，可排 `14/13`。27 张紧凑单排需要至少 672 宽。典型 667 宽手机横屏采用两排。电脑可用牌宽 `60`、步长 `28`，27 张单排需要 788 宽。牌数减少时按容量合并，选牌过程中保持同手牌的排序和布局稳定。以上是起始预算，设备安全区、文字缩放和实测命中会影响排布。
- **视觉。** 原创浅色扑克，左上角将数字和花色上下排，27 张叠放时只依赖露出的牌角也能辨认。红桃级牌加「配」字或可辨形标记，其他级牌有等级标记。选中用位移、描边和辅助状态，行动席写「行动中」。配色统一走 `theme.ts`。主控件和放大选牌格以至少 `48 × 48` 逻辑单位为目标。 [斗地主牌桌实现](../../../app/src/DoudizhuTable.tsx) · [UNO 手牌实现](../../../app/src/UnoHand.tsx) · [GameHub 移动端规范](../../移动端体验设计方法论.md)

### 选牌与提醒

- 点一下切换单张选中，已选牌抬起，命中位置保持固定。点「出牌」才提交。两副牌的相同牌面有独立 ID，同一张牌在紧凑手牌、放大网格和跨行布局中共用选中状态。桌面支持鼠标、可见键盘焦点和空格或 Enter 激活焦点项。
- 「放大选牌」用非叠放的多列网格，牌区可滚动，底部保留所选张数和同一组操作。紧凑区能明确区分可见角标与命中区，大牌网格提供完整替代路径。两种方式都能跨行挑选一手牌。
- 服务端给出提示候选，点「提示」只预选。含逢人配的组合先展示服务端判定的牌型与替代结果，例如「同花顺 · 红桃 5 当黑桃 10」。提交随回合变化而失效的选择时重新核对牌权与手牌；拒绝后保留仍在手的牌并提示原因。过牌、接风、抗贡和双下分别有明确文字。首次开局提供牌型与炸弹阶梯的速查入口。

## 多副牌的房间流程

- 房主凑齐四席开局。真人须在线，人机自动准备。服务端打乱两副牌，并随机选择首副领出席。座位在整场内固定。副内经历发牌、贡还牌（第二副起）、出牌和结副，结副摘要显示名次与升级。房主在桌内继续下一副，房间维持 `playing`。整场过 A 或因退出等原因结束后，才走 GameHub 的结算、战绩和回大厅流程。
- 贡牌阶段由服务端按规则分配贡牌与领出者。进入还贡后，收到贡牌的座位只选服务端允许的实体牌。双贡等待两人提交，确认期间分别存储自己的选择，再统一交换。重连后恢复当前副、行动席、已完成状态和当前可用操作。
- 服务端统一判牌及生成提示，逐座下发玩家自己的手牌、合法贡还候选、公开公牌和公开余牌，搭档与对手走同一套权限。未公布的还贡选择、其他座位的手牌与未报精确余牌留在服务端。重连同步、动作广播与战绩快照沿用相同公开边界。复用斗地主的扑克展示思路和 GameHub 公共壳层，掼蛋的双副牌 ID、四座与跨副状态单独建模。 [GameHub 联机约定](../../../CLAUDE.md#客户端不实现规则服务端权威) · [接口协议](../../接口协议.md)

## 人机对战

房主可在等待大厅添加或移除人机，最多三席。每席可独立选择难度。单人可开局，真人和人机都按座位分队，开局前可换位。人机出牌、过牌、还贡都通过同一套校验，贡牌和抗贡仍由引擎按规则处理。牌桌显示正在思考的座位，无真人在线时暂停人机行动，真人重连后继续。

- 简单档优先出较小的牌，有机会时直接出完手牌。
- 普通档领出时优先出较长的普通牌型。搭档占着牌权时通常过牌，能一手出完时直接走完。
- 困难档也参考已报的余牌数，在适当时机给只剩一两张的搭档送牌，并尽量保留炸弹和逢人配。还贡时先考虑可还的单牌，减少拆对。

人机只读取本人的手牌、可还贡候选及公开牌桌。使用规则引擎的牌型模板生成候选，难度只改变动作选择。 [人机调研](增强调研.md#人机对战参考)

## 验收样例

| 情形 | 验收点 |
| --- | --- |
| 320×568 与 390×844 竖屏，667×375 横屏，1440×900 桌面 | 首副显示 27 张，四席和公牌可辨。点准相邻牌、同面值的两张实体牌和跨行组合。旋转、缩放和字体放大期间保留选牌。扩大选牌能完成同一手牌。 |
| 跟牌和百搭 | 检查 A 的高低两端、级牌在连续结构中的自然点数、四五六张炸与同花顺的边界、十张炸、四王炸。检查双百搭领出钢板与跟三连对，以及回合变化后旧提示失效。 |
| 接风与过 A | 覆盖有人压住走完玩家的末手、所有在打的座位都过后的接风、两种结副条件、`3/2/1` 升级、封顶到 A、打 A 时 `1+4` 留在 A。A 队在对方较低级别上拿头游时，下一副才轮到它打 A。 |
| 贡还和重连 | 覆盖同队头游末游单贡、同点双贡的首出席、两名贡方各持一个大王的抗贡、无常规还贡候选、双还贡有人先提交时重连。检查四个客户端的原始消息，确认私牌、报牌门槛和待公布动作符合各自权限。 |
| 键盘与触屏 | 用电脑键盘完成选牌、跟牌和过牌。用 Android 和手机浏览器完成放大选牌、还贡、结算回房和返回确认。 |
| 人机 | 用一个真人和三种难度的人机开局，检查自动准备、逐席隐藏私牌、连续人机回合和双贡时两名人机依序还牌。断线期间验证人机暂停，重连后续打。 |
