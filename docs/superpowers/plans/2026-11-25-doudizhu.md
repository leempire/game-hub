# 斗地主实现计划

> 执行采用 Superpowers 的分任务实现与验证。用户已要求执行。

**目标**：在 GameHub 中提供三人斗地主房间、UNO 式房规、断线恢复、战绩和自适应牌桌。

**架构**：纯 Python 引擎负责发牌、动作合法性和结算。房间层锁定配置并落盘，WS 层按座位发送状态，React Native / Web 端共用一套牌桌。

**设计**：[斗地主设计](../../游戏设计/斗地主/设计.md)。

## 任务

- [x] 用确定性牌例测试 14 类牌型、两个带牌开关、全不叫重发与首叫者兜底、正常计分和中途离开。实现 `server/app/game/doudizhu.py`，公开 `create_game`、`bid`、`play`、`pass_turn`、`hint`、`depart`、`view_for`、`snapshot`。注册 `room_settings.py` 的「经典」「严格带牌」及三项房规。
- [x] 用三连接 WS 测试房规同步、隐藏手牌、按版本校验、重连和结算。由 `room_manager.py` 管理开局与结束，`ws.py` 发送逐人 `game_start`、`doudizhu_state`、`sync.game`。动作走 `doudizhu_action {action,match_id,revision,bid?,cards?}`，提示走仅私发的 `doudizhu_hint`，终局 `game_over.summary` 及 `sync.doudizhu_result` 只含公开快照。更新数据库战绩。
- [x] 实现牌桌及放大选牌。在游戏目录、房间导航、三处深链、返回保护和帮助处接入。按座位渲染，使用响应式单行或双行，提示仅选牌，确认出牌才提交。显示结算和战绩。
- [x] 更新协议、游戏索引和测试说明。跑后端单测、类型检查、lint，并在条件允许时用三浏览器会话验证房规、出牌、刷新、牌桌重排和结算。

## 验证重点

- 同一房内重复开局、重复动作、延迟提示和重连都以对局标识和版本校验。
- 叫分中底牌保持私有。结算和历史快照不泄露在局中未公开的手牌。
- 退出与离线超时只结算一次，叫分阶段退出会取消本局。回大厅再次修改规则不改写上一局战绩。
- 320 宽竖屏可操作 20 张手牌及跨行多选，旋转保留选中项。返回先关闭弹窗或请求离局确认。
